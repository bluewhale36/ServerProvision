## 대기 항목 확인

항목 파일은 `pending/<단계 코드>.md` 이다. 등록을 빠뜨린 항목은 아래 비교로 찾는다. 결과에 나온 파일이 `pending/` 의 어느 항목에도 없으면 그 단계에 항목 파일을 만든다.

```bash

```

## 항목 파일 쓰는 법

배포 때 사람이 해야 하는 일을 만든 슬라이스는 같은 PR 에 항목 파일을 커밋한다. 파일 이름은 단계 코드이고, 아래 절 가운데 해당하는 것만 쓴다.

| 절 | 적을 것 |
|---|---|
| DDL 과 DML | `ddl/` 경로, 적용 시점(jar 앞, jar 와 같은 순간, jar 뒤), 적용 계정 권한, 확인 SQL |
| 점검 SQL | 읽기 전용 SQL 원문, 기대 결과, 결과가 다르면 누가 무엇을 정하는지 |
| 환경 변수 | 키 이름, 값을 어디서 정하는지. 비밀값은 적지 않는다 |
| 서버 준비 | 패키지, 디렉터리, 소유자와 권한 |
| 자산 교체 | jar 와 함께 바꿔야 하는 시스템 자산(agent.sh 등)과 바꾸지 않으면 생기는 일 |
| 사용자 결정 | 배포 때 사용자가 정할 일 |

같은 캠페인의 하위 단계는 캠페인 코드 파일 하나에 하위 단계별로 절을 나눠 쓴다(예: `E4-1-b.md`).

## 배포 순서

1. 대기 항목의 점검 SQL 을 운영 DB 에서 읽기 전용으로 돌린다. 기대 결과와 다르면 사용자가 정한 뒤 진행한다.
2. 새 jar 를 반입하고 기존 jar 를 백업한다.
3. 서버 준비와 환경 변수를 반영한다.
4. DDL 을 적용 시점에 맞춰 적용하고 확인 SQL 로 검증한다.
5. 앱을 재기동하고 로그인과 오류 로그를 확인한다.
6. 자산 교체를 한다.
7. 적용한 항목 파일을 지우고 위 '환경별 마지막 배포' 를 갱신한다.

운영 DB 와 서버 작업은 사용자 지시가 있을 때만 한다.
