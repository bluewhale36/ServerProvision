# HF30-1 메타 자원 정체 UNIQUE

dev 병합 `c278131`. 로컬 개발 DB(3306)에는 적용했다.

## 점검 SQL

`ddl/HF30_meta_identity.sql` 머리의 사전 조회 1 과 2 를 운영 DB 와 스테이징 DB 에서 읽기 전용으로 먼저 돌린다.

- 사전 조회 1: 같은 (os_name, os_version) 인 OS 버전이 2 행 이상인지
- 사전 조회 2: 같은 (vendor, model_name) 인 RAID 카드가 2 행 이상인지, 행마다 정의서 RAID 단계의 참조 수

기대 결과는 둘 다 0 행이다. 행이 나오면 UNIQUE 를 만들 수 없고 DDL 이 그 자리에서 멈춘다. 어느 행을 남길지는 사용자가 정한다. RAID 카드는 정의서가 참조하는 수를 함께 보고 고른다. MA7 이 사용 중지 카드 옆에 같은 이름 카드를 허용해 왔으므로 다건이 있을 수 있다.

## DDL 과 DML

- 파일: `ddl/HF30_meta_identity.sql`
- 적용 시점: jar 와 같은 순간. 다시 적용해도 안전하다.
- 하는 일: `os_metadata` 에 (os_name, os_version) UNIQUE, `raid_card` 에 (vendor, model_name) UNIQUE 를 만들고, 성공한 뒤에만 옛 생성 컬럼과 인덱스를 지운다.
- 확인 SQL:

```sql
SHOW CREATE TABLE os_metadata;
SHOW CREATE TABLE raid_card;
```
