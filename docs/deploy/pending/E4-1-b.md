# E4-1-b RHEL 계열 자동 설치

b-1 과 b-2 는 dev 병합 `4a6ecd4`(PR #118). 배포는 b-4 실행기가 끝난 뒤에 한다(사용자 결정). 남은 하위 단계가 배포 작업을 더하면 이 파일에 절을 더한다.

## b-1 설치 트리

### 서버 준비

- 패키지: `bsdtar`(AppStream). spv-01 에는 7z 와 bsdtar 가 없고 libarchive 만 있다. 도구가 없으면 설치 트리를 풀지 못한다.

```bash
sudo dnf install bsdtar
```

- 디렉터리: `/var/lib/serverprovision/served/install-trees`, 소유자 `provisioning:provisioning`, 권한 0755.

### 환경 변수

| 키 | 값 | 비고 |
|---|---|---|
| `RHEL_INSTALL_TREE_ROOT` | `/var/lib/serverprovision/served/install-trees` | 빈 값이면 RHEL 설치 트리 기능이 꺼진다. 다른 루트와 같거나 겹치면 기동이 실패한다 |
| `RHEL_INSTALL_RELEASE_GRACE` | 넣지 않아도 된다 | 기본 10m. 그 ISO 로 설치 중인 서버가 0 대가 된 뒤 트리를 지우기까지 기다리는 시간 |

## b-2 정의서 RHEL 활성화

### DDL 과 DML

- 파일: `ddl/E4-1-b-2_iso_registration_failure.sql`
- 적용 시점: jar 와 같은 순간. ALTER 권한이 필요하다.
- 하는 일: `iso` 에 `registration_failure` 컬럼을 더한다. NULL 이 정상이라 기존 행은 채울 것이 없다.
- 확인 SQL: `SHOW CREATE TABLE iso;`

### 점검 SQL

읽기 전용.

```sql
-- 평문 비밀번호가 남은 RHEL 정의서
SELECT sd.id, sd.name
FROM setting_process sp JOIN setting_definition sd ON sd.id = sp.setting_definition_id
WHERE sp.process_type = 'OS_INSTALLATION'
  AND sp.payload_json LIKE '%"RHEL_BASED"%'
  AND sp.payload_json LIKE '%"isPasswordEncrypted":false%';

-- isKDumpEnabled 키가 없는 RHEL 정의서
SELECT sd.id, sd.name
FROM setting_process sp JOIN setting_definition sd ON sd.id = sp.setting_definition_id
WHERE sp.process_type = 'OS_INSTALLATION'
  AND sp.payload_json LIKE '%"RHEL_BASED"%'
  AND sp.payload_json NOT LIKE '%"isKDumpEnabled"%';

-- 지원 밖 Rocky 메타데이터(주 버전이 8, 9, 10 이 아닌 것을 사람이 확인)
SELECT id, os_version FROM os_metadata WHERE os_name = 'ROCKY_LINUX' AND is_deleted = false;

-- 기존 Rocky ISO 경로(아래 서버 확인용)
SELECT i.id, i.iso_path, m.os_version
FROM iso i JOIN os_metadata m ON m.id = i.os_metadata_id
WHERE m.os_name = 'ROCKY_LINUX' AND i.is_deleted = false;
```

| SQL | 기대 결과 | 행이 나오면 |
|---|---|---|
| 평문 비밀번호 | 0 행 | 실행은 막히지 않는다(실행 직전에 해시한다). 다음에 그 정의서를 고쳐 저장하면 해시로 바뀐다 |
| KDump 키 없음 | 0 행 | 저장 JSON 에는 키가 항상 있으므로 행이 나오면 직접 넣은 데이터다. 사용자가 확인한다 |
| 지원 밖 Rocky | 사람이 확인 | 지원 밖 주 버전 메타데이터 아래 ISO 는 정의서에서 고를 수 없다. 남길지 사용자가 정한다 |
| ISO 경로 | 사람이 확인 | 서버에서 ISO 마다 아래 명령으로 트리 설명서의 배포판과 버전을 보고 등록 OS 와 같은지 확인한다 |

```bash
bsdtar -xOf <iso_path> .treeinfo
```

기존 ISO 의 트리 설명서 불일치는 SQL 로 찾을 수 없다. 배포 뒤 그 ISO 의 [추출] 을 다시 실행해도 확인할 수 있다.

## b-4-1 OS 설치 계열 분기

### 환경 변수

| 키 | 값 | 비고 |
|---|---|---|
| `OS_INSTALL_SWEEP_INTERVAL` | 넣지 않아도 된다 | 기본 5m. OS 설치 시한 스위퍼 주기. 옛 키 `WINDOWS_INSTALL_SWEEP_INTERVAL` 이 있으면 그 값을 쓴다 |

옛 키를 그대로 둬도 동작이 같으므로 배포 때 할 일은 없다. 새 키로 바꾸려면 옛 키를 지우고 새 키에 같은 값을 넣는다.
