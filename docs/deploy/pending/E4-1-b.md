# E4-1-b RHEL 계열 자동 설치

b-1 과 b-2 는 dev 병합 `4a6ecd4`(PR #118). 배포는 b-4 실행기가 끝난 뒤에 한다(사용자 결정). 남은 하위 단계가 배포 작업을 더하면 이 파일에 절을 더한다.

## b-1 설치 트리

### 서버 준비

- 패키지: `bsdtar`(AppStream). spv-01 에는 7z 와 bsdtar 가 없고 libarchive 만 있다. 도구가 없으면 설치 트리를 풀지 못한다.

```bash
sudo dnf install bsdtar
```

- 디렉터리: `/var/lib/serverprovision/served/install-trees`, 소유자 `provisioning:provisioning`, 권한 0755.

### 환경 변수

| 키 | 값 | 비고 |
|---|---|---|
| `INSTALL_TREE_ROOT` | `/var/lib/serverprovision/served/install-trees` | 빈 값이면 설치 작업 트리 기능이 꺼진다(RHEL, Ubuntu 설치 모두 불가). 다른 루트와 같거나 겹치면 기동이 실패한다. E4-1-c-1 에서 이름을 바꿨다(옛 이름 `RHEL_INSTALL_TREE_ROOT` 는 읽지 않는다) |
| `INSTALL_TREE_RELEASE_GRACE` | 넣지 않아도 된다 | 기본 10m. 그 ISO 로 설치 중인 서버가 0 대가 된 뒤 트리를 지우기까지 기다리는 시간. 옛 이름 `RHEL_INSTALL_RELEASE_GRACE` |

## b-2 정의서 RHEL 활성화

### DDL 과 DML

- 파일: `ddl/E4-1-b-2_iso_registration_failure.sql`
- 적용 시점: jar 와 같은 순간. ALTER 권한이 필요하다.
- 하는 일: `iso` 에 `registration_failure` 컬럼을 더한다. NULL 이 정상이라 기존 행은 채울 것이 없다.
- 확인 SQL: `SHOW CREATE TABLE iso;`

### 점검 SQL

읽기 전용.

```sql
-- 평문 비밀번호가 남은 RHEL 정의서
SELECT sd.id, sd.name
FROM setting_process sp JOIN setting_definition sd ON sd.id = sp.setting_definition_id
WHERE sp.process_type = 'OS_INSTALLATION'
  AND sp.payload_json LIKE '%"RHEL_BASED"%'
  AND sp.payload_json LIKE '%"isPasswordEncrypted":false%';

-- isKDumpEnabled 키가 없는 RHEL 정의서
SELECT sd.id, sd.name
FROM setting_process sp JOIN setting_definition sd ON sd.id = sp.setting_definition_id
WHERE sp.process_type = 'OS_INSTALLATION'
  AND sp.payload_json LIKE '%"RHEL_BASED"%'
  AND sp.payload_json NOT LIKE '%"isKDumpEnabled"%';

-- 지원 밖 Rocky 메타데이터(주 버전이 8, 9, 10 이 아닌 것을 사람이 확인)
SELECT id, os_version FROM os_metadata WHERE os_name = 'ROCKY_LINUX' AND is_deleted = false;

-- 기존 Rocky ISO 경로(아래 서버 확인용)
SELECT i.id, i.iso_path, m.os_version
FROM iso i JOIN os_metadata m ON m.id = i.os_metadata_id
WHERE m.os_name = 'ROCKY_LINUX' AND i.is_deleted = false;
```

| SQL | 기대 결과 | 행이 나오면 |
|---|---|---|
| 평문 비밀번호 | 0 행 | 실행은 막히지 않는다(실행 직전에 해시한다). 다음에 그 정의서를 고쳐 저장하면 해시로 바뀐다 |
| KDump 키 없음 | 0 행 | 저장 JSON 에는 키가 항상 있으므로 행이 나오면 직접 넣은 데이터다. 사용자가 확인한다 |
| 지원 밖 Rocky | 사람이 확인 | 지원 밖 주 버전 메타데이터 아래 ISO 는 정의서에서 고를 수 없다. 남길지 사용자가 정한다 |
| ISO 경로 | 사람이 확인 | 서버에서 ISO 마다 아래 명령으로 트리 설명서의 배포판과 버전을 보고 등록 OS 와 같은지 확인한다 |

```bash
bsdtar -xOf <iso_path> .treeinfo
```

기존 ISO 의 트리 설명서 불일치는 SQL 로 찾을 수 없다. 배포 뒤 그 ISO 의 [추출] 을 다시 실행해도 확인할 수 있다.

## b-4-1 OS 설치 계열 분기

### 환경 변수

| 키 | 값 | 비고 |
|---|---|---|
| `OS_INSTALL_SWEEP_INTERVAL` | 넣지 않아도 된다 | 기본 5m. OS 설치 시한 스위퍼 주기. 옛 키 `WINDOWS_INSTALL_SWEEP_INTERVAL` 이 있으면 그 값을 쓴다 |

옛 키를 그대로 둬도 동작이 같으므로 배포 때 할 일은 없다. 새 키로 바꾸려면 옛 키를 지우고 새 키에 같은 값을 넣는다.

## b-4-2 RHEL 설치기 · 서빙 · 대상 디스크

DB 변경은 없다. 이 절이 배포되면 RHEL 정의서를 할당한 서버가 OS 설치 단계에서 실제로 kickstart 설치를 시작한다. b-1 절의 bsdtar 와 설치 트리 디렉터리가 먼저 준비돼 있어야 한다.

### 환경 변수

| 키 | 값 | 비고 |
|---|---|---|
| `RHEL_INSTALL_TIMEOUT` | 넣지 않아도 된다 | 기본 60m. kickstart 를 서빙한 시각부터의 설치 시한 |
| `RHEL_INSTALL_MAX_REENTRIES` | 넣지 않아도 된다 | 기본 5. 설치 중 재PXE 허용 횟수. 넘으면 REPXE_LOOP 실패 |
| `RHEL_INSTALL_SWEEP_GRACE` | 넣지 않아도 된다 | 기본 30m. 재PXE 없이 시한이 지난 서버를 스위퍼가 닫기까지 더 기다리는 시간 |

세 값은 실기 측정 전이라 Windows 와 같은 기본값이다. b-4-2 만 배포하면 설치가 성공해도 완료 보고가 없어 스위퍼가 INSTALL_TIMEOUT 으로 닫는다. 그래서 b-4-2 와 b-5 를 함께 배포한다.

## b-5 첫 부팅 완료 보고

DB 변경과 새 env 키는 없다. b-4-2 와 함께 배포한다.

- kickstart 끝에 첫 부팅 보고 유닛이 실린다. 설치된 OS 가 처음 부팅하면 `POST /api/pxe/v1/agent/rhel/complete` 로 완료를 보고하고, 보고가 끝나면 심은 파일을 스스로 지운다.
- 보고 주소는 기존 `PXE_SERVER_BASE_URL` 에서 만든다. 설치된 OS 가 이 주소에 닿아야 한다(설치 프로그램이 kickstart 를 받던 주소와 같다).
- Windows 완료 보고 응답 이름이 `OsInstallCompletionResponse` 로 바뀌었지만 JSON 은 그대로라 배포된 `spv-report.ps1` 은 바꾸지 않는다.

## b-7 OS 후처리 설정

DDL, env 키, 서버 준비는 없다. 정의서 payload, 할당 스냅숏, 원장 meta 가 모두 json 컬럼이라 스키마가 그대로다.

### 점검 SQL

읽기 전용. R11 이전에 만든 OS 후처리 단계가 남아 있으면 b-7 배포 뒤부터 실제로 적용된다. 배포 전에 행이 있는지 보고, 있으면 그 정의서를 열어 내용을 확인한다.

```sql
-- 정의서에 남은 OS 후처리 단계
SELECT sd.id, sd.name, sd.is_deleted
FROM setting_process sp JOIN setting_definition sd ON sd.id = sp.setting_definition_id
WHERE sp.process_type = 'OS_SETTING';

-- 할당 스냅숏에 남은 OS 후처리 단계(지난 할당 포함)
SELECT aps.id, aps.process_type
FROM assigned_process_snapshot aps
WHERE aps.process_type = 'OS_SETTING';
```
