# U7 개시 IP 대역 판정

PR #106. 시스템 설정 화면과 프로비저닝 허용 대역을 더하고, 개시 전에 BMC 와 LAN 주소가 그 대역 안인지 판정한다.

## DDL 과 DML

- DDL 파일: `ddl/U7_system_setting.sql`
- 적용 시점: jar 앞. CREATE 권한이 필요하다. MA8 DDL(SUPER_ADMIN 역할)이 먼저 적용돼 있어야 한다.
- 하는 일: `system_setting` 테이블을 만든다. 설정 키 하나가 행 하나다.
- 확인 SQL: `SHOW CREATE TABLE system_setting;`
- DML 파일: `sql/U7_system_setting_seed.sql`
- 적용 시점: DDL 바로 뒤, jar 기동 전.
- 하는 일: 프로비저닝 허용 대역 초기값(10.1.1.0/24, 접근 권한 최고 관리자)을 넣는다. 같은 키가 있으면 건너뛴다.
- 확인 SQL: `SELECT setting_key, value_json, min_role FROM system_setting;`

DML 을 빠뜨리면 허용 대역이 비어 모든 서버의 개시가 막힌다.

## 사용자 결정

운영 프로비저닝 LAN 대역이 10.1.1.0/24 가 아니면 DML 의 값을 배포 전에 정하거나, 배포 뒤 시스템 설정 화면에서 바꾼다.

## HF35 프로비저닝 대역 단일 정본(같은 배포)

HF35 는 U7 의 허용 대역을 dnsmasq 서브넷과 게스트 채널 출발지 제한의 정본으로 바꾼다. U7 과 같은 배포에 싣는다. DDL 은 없다.

- 배포 전 점검 SQL(읽기 전용): `SELECT subnet_cidr, dhcp_mode, applied_result FROM pxe_network_config;`
- 지금 서브넷이 위 DML 로 넣을 허용 대역과 다르면, 배포 뒤 저장 및 적용이 dnsmasq 서브넷을 허용 대역으로 바꾼다. 자체 DHCP 모드라면 리스 범위도 새 대역 안이어야 저장된다.
- 지금 서브넷이 사설 대역이 아니거나 prefix 가 26 보다 좁으면 허용 대역으로 그대로 쓸 수 없다. 허용 대역을 먼저 정한다.

순서:

1. U7 DDL 과 DML 을 적용한다(위 절).
2. jar 를 바꾼다.
3. PXE 네트워크 구성 화면에서 저장 및 적용을 한 번 한다. 서브넷이 허용 대역과 같으면 조각 내용은 바뀌지 않는다.
4. 환경 파일에서 `PXE_GUEST_ALLOWED_CIDRS` 줄을 지운다. 남아 있어도 읽지 않는다.

확인: 시스템 설정 화면의 허용 대역과 PXE 네트워크 구성 화면의 게스트 서브넷이 같고, 재적용 경고가 없다. 앱 로그에 `게스트 채널 출발지 제한 적재` 가 첫 게스트 요청 때 한 번 남는다.
