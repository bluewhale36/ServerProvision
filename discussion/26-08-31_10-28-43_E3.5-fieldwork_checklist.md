# E3.5 실측 체크리스트 — RAID 카드 인벤토리 원문 채집 (ssh 원격 실행판)

대상: 실서버 2대(① CRA3338 장착 = SAS3008 IR / ② 9361-8i 장착 = SAS3108 MegaRAID, 둘 다 Oracle Linux 9.7). 목적: E3.5-1 파서의 **픽스처 원문** 채집 + Redfish 경로 종결 판정. **전부 읽기 전용 명령이다 — create · delete · set 계열은 이 체크리스트에 없다. 있는 그대로만 실행한다.**

모든 명령은 **호스트(맥) 터미널에서** 실행한다 — `ssh` 가 원격 출력을 되돌려주므로 리다이렉트(`>`)가 맥 쪽 파일로 떨어진다. 서버에 파일이 남지 않고 옮길 것도 없다.

## 준비 — 접속 변수와 작업 폴더 (맥에서 1회)

```bash
mkdir -p ~/e35-fieldwork && cd ~/e35-fieldwork
CRA=user@<CRA3338 서버 IP>      # ① SAS3008 IR 서버
MR=user@<9361-8i 서버 IP>       # ② MegaRAID 서버
```

**sudo 주의** — 아래 `sudo` 가 붙은 명령은 원격에 tty 가 없어 비밀번호를 물으면 실패한다(`sudo: a terminal is required …`). 계정이 NOPASSWD sudo 이거나 root 접속이면 그대로 동작한다. 비밀번호가 필요한 환경이면 그 명령만 `ssh -t` 로 바꾸되(`ssh -t $MR 'sudo …' > 파일`), 프롬프트 문자열이 파일 머리에 섞일 수 있다 — 채집 후 첫 줄만 지우면 픽스처로 쓸 수 있다.

## 0. 도구 확인 (두 서버)

- [ ] `ssh $MR  'which storcli64 || ls /opt/MegaRAID/storcli/ 2>/dev/null' > mr-tool-check.txt`
- [ ] `ssh $CRA 'which sas3ircu' > cra-tool-check.txt`
- [ ] sudo 필요 여부 확인: `ssh $MR 'sudo -n true && echo NOPASSWD || echo NEED-PASSWORD'` · `ssh $CRA 'sudo -n true && echo NOPASSWD || echo NEED-PASSWORD'`

## 1. 두 서버 공통 — PCI 식별자 (숫자 ID)

- [x] `ssh $CRA 'lspci -nn -d 1000:' > cra-lspci-nn.txt`
- [x] `ssh $MR  'lspci -nn -d 1000:' > mr-lspci-nn.txt`
- 위 출력에 `Subsystem` 줄이 없으면(기본 `-nn` 은 한 줄만 낸다) 추가로:
- [x] `ssh $CRA 'lspci -nn -vv -d 1000:' > cra-lspci-nnvv.txt`
- [x] `ssh $MR  'lspci -nn -vv -d 1000:' > mr-lspci-nnvv.txt`
- 확인 포인트: CRA3338 의 `Subsystem: … [1458:????]` **숫자쌍**, 9361-8i 의 `[1000:9361]`

## 2. 두 서버 공통 — OS 쪽 디스크 식별자

- [x] `ssh $CRA 'lsblk -o NAME,WWN,SERIAL,SIZE,ROTA,TRAN,MODEL,TYPE' > cra-lsblk.txt`
- [x] `ssh $MR  'lsblk -o NAME,WWN,SERIAL,SIZE,ROTA,TRAN,MODEL,TYPE' > mr-lsblk.txt`
- [x] `ssh $CRA 'ls -l /dev/disk/by-id/' > cra-by-id.txt`
- [x] `ssh $MR  'ls -l /dev/disk/by-id/' > mr-by-id.txt`
- 목적: RAID 볼륨 · 단독 디스크가 리눅스에서 어떤 WWN/식별자로 보이는지(E4 인계 D-8 근거)

## 3. 9361-8i 서버 — StorCLI (JSON 5종)

- [x] `ssh $MR 'sudo storcli /c0 show all J' > mr-c0-show-all.json`
- [x] `ssh $MR 'sudo storcli /c0/eall/sall show all J' > mr-pd-all.json`
- [x] `ssh $MR 'sudo storcli /c0/vall show all J' > mr-vd-all.json`   ← 볼륨이 없어도 응답 원문 그대로 저장("없음" 의 모양도 파서에 필요)
- [x] `ssh $MR 'sudo storcli /c0 show personality' > mr-personality.txt`

## 4. CRA3338 서버 — sas3ircu (4종)

- [x] `ssh $CRA 'sudo sas3ircu list' > cra-list.txt`
- [x] `ssh $CRA 'sudo sas3ircu 0 display' > cra-display.txt`
  - 확인 포인트: `RAID Support : Yes`(IR 펌웨어 확정) · 볼륨 절 유무 · 디스크의 `Drive Type` · `Protocol` · `Size` · `Serial No`
- [x] `ssh $CRA 'sudo sas3ircu 0 status' > cra-status.txt`
- [x] `ssh $CRA 'sas3ircu help create 2>&1' > cra-help-create.txt`   ← 볼륨 이름 인자의 길이 한계(종결 문서 §2)

## 5. BMC Redfish — Storage 컬렉션 (경로 종결 판정)

BMC 는 맥에서 직접 닿으므로(E0-4 와 동일) ssh 없이 **맥에서 바로** curl 한다. 계정 · 암호는 명령 이력에 남지 않게 변수로:

```bash
read -s BMCPW   # 입력 후 엔터 (화면에 안 보임)
```

- [x] `curl -sk -u <계정>:$BMCPW https://<CRA서버 BMC IP>/redfish/v1/Systems/Self/Storage > cra-redfish-storage.json`
- [x] `curl -sk -u <계정>:$BMCPW https://<MR서버 BMC IP>/redfish/v1/Systems/Self/Storage > mr-redfish-storage.json`
- [ ] Members 가 비어 있지 않으면 그 멤버 URL · `/Drives` · `/Volumes` 도 같은 방식으로 저장
- [ ] BMC 웹 UI 좌측 메뉴에 RAID/Storage 항목이 있는지 눈으로 확인 — 있으면 스크린샷 1장
- 판정: **두 서버 모두 Members 가 비면 Redfish 경로 종결**(E3.5-0-2 §2-3 확정)

## 6. 부가 (선택)

- [ ] `ssh $MR 'sudo storcli /c0/e<EID>/s<slot> show all J' > mr-pd-one.json`   ← §3 결과에서 EID:Slt 하나 골라 상세
- [ ] `ssh $CRA 'modinfo mpt3sas | head -5' > cra-modinfo.txt` · `ssh $MR 'modinfo megaraid_sas | head -5' > mr-modinfo.txt`
- [ ] 두 서버의 디스크 구성 개요 한 줄 메모(예: "SSD SATA 480GB × 4 + HDD SAS 4TB × 2") — 매칭 알고리즘 예제를 실제 구성으로 만들기 위함

## 채집이 끝나면

`~/e35-fieldwork/` 경로를 세션에 알려 주면 된다 — 세션이 직접 읽어 E3.5-1 파서 픽스처로 저장소에 배치하고, Subsystem ID 를 MA7 카드 자원 · E3.5-0-1 에, Redfish 판정을 E3.5-0-2 에 반영한다. 주의: BMC 암호가 파일 · 셸 이력에 남지 않게 — `read -s` 변수만 쓰고, 응답 JSON 에는 자격증명이 들어가지 않는다.
