# HF24 부트 순서 용어와 실기 관측 지점

작성 2026-11-16 13:13 KST. HF24 문서들에 나오는 용어를 짧게 정의하고, 지금까지 실기에서 부트 순서 문제가 드러난 지점을 한 표로 모았다. 대상 BIOS 는 AMI(MS74-HB0, MS04-CE0)다.

## 1. 순서를 이루는 것

| 용어                     | 뜻                                                                                                                          |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 부팅 항목                  | `Boot0001` 같은 번호가 붙은 UEFI 항목 하나. NIC 마다 PXE 항목이 하나씩 있고, UEFI 셸은 `Boot0001`, Windows 를 설치하면 Windows Boot Manager 항목이 생긴다    |
| BootOrder              | 부팅 항목의 순서 목록. BIOS 는 이 순서대로 부팅을 시도한다                                                                                       |
| FBO (Fixed Boot Order) | AMI 가 항목을 묶는 그룹의 순서. 그룹은 HD, CD/DVD, USB, NET, AP(셸) 다섯이다. 공장 기본값은 `HD, CD, USB, NET, AP` 다. BIOS 셋업의 Boot 탭에 보이는 순서가 이것이다 |
| 표준 순서                  | 공장 기본값과 같은 순서. 디스크, CD/DVD, USB, 네트워크, 셸                                                                                   |

## 2. 순서를 바꾸는 수단

| 용어              | 뜻                                                                                                |
| --------------- | ------------------------------------------------------------------------------------------------ |
| 오버라이드           | Redfish 로 "다음 부팅은 이 장치로" 를 거는 설정. 순서 목록과는 별개의 층이다                                                |
| Once            | 오버라이드를 한 번의 POST 에만 적용한다. 엔진이 써 온 방식이다 (PXE_ONCE, HDD_ONCE)                                      |
| Continuous      | 오버라이드를 계속 적용한다. AMI 는 이것을 BIOS 안에 저장해 버려서, 풀어도 남는다. 폐기했다 (HF17)                                  |
| BootOrder PATCH | Redfish 로 BootOrder 목록 자체를 고쳐 쓰는 것. 엔진의 SHELL_LAST, DISK_FIRST 가 이것이다 (HF20)                     |
| 보류 PATCH        | BMC 는 PATCH 받은 값을 바로 BIOS 에 쓰지 않고 다음 POST 까지 들고 있다. 그동안 BMC 를 읽으면 PATCH 값이 보이지만 실제 BIOS 순서는 그대로다 |

## 3. POST 의 종류와 그때 일어나는 일

| 용어 | 언제 | 일어나는 일 |
|---|---|---|
| 오버라이드 POST (R1) | Once 가 걸린 상태의 POST | 오버라이드 대상 그룹이 FBO 1 번과 자리를 바꾸고(맞바꿈), BootOrder 가 그 순서로 다시 모인다. 그 POST 동안만이다 |
| 되돌림 POST | 오버라이드 POST 바로 다음 POST | 오버라이드 전의 순서로 통째로 돌아간다. 그 사이에 쓴 값(OS 의 쓰기, Windows Setup 의 쓰기, Redfish PATCH)은 버려진다 |
| 오버라이드 없는 POST (R2) | 오버라이드가 없고 직전도 오버라이드 POST 가 아닌 POST | 쓰인 BootOrder 가 유지된다. FBO 는 BootOrder 에 그룹이 처음 나오는 순서로 다시 세워진다 |
| BIOS 자체 POST | 엔진이 보내지 않은 POST | 펌웨어를 구운 뒤의 전원 사이클, BIOS 설정을 적용하며 하는 재시작 등. 엔진의 Once 가 여기에 닿지 않는 경우가 있었다 |

| 용어 | 뜻 |
|---|---|
| 맞바꿈 | R1 에서 대상 그룹과 FBO 1 번이 자리를 바꾸는 것 |
| 재생성 | BIOS 가 BootOrder 를 번호 순으로 다시 만들어 셸(`Boot0001`)이 맨 앞에 오는 현상. 09-17 MS04-CE0 과 10-23 MS74-HB0 에서 관측했고, 둘 다 오버라이드를 쓰던 실행이었다. 10-25 에 번호 순이 아니라 FBO 그룹 순서로 다시 모으는 것으로 재해석했다(그때 FBO 는 오버라이드로 흐트러져 있었다) |
| BIOS 밀어 넣기 | BIOS 는 매 POST 마다 실제 BootOrder 를 BMC 로 보낸다. 그래서 POST 뒤에 읽은 BMC 값은 실제와 같다. 오버라이드 POST 와 되돌림 POST 에서는 FBO 등 BIOS 속성도 함께 보낸다 |
| 셸 낙하 | 부팅할 것이 없어 순서상 셸까지 내려가 UEFI 셸 화면에 멈추는 것 |

## 4. 실기에서 드러난 지점

| 날짜 | 서버 | 일어난 일 | 관련 용어 |
|---|---|---|---|
| 09-04 | 실기 서버 | 오버라이드 없이 Windows 를 설치했고 문제가 없었다 | 오버라이드 없는 POST |
| 09-08 부터 | 실기 서버 | Once(E2.5)를 쓰기 시작한 뒤부터 셸 낙하가 나타났다 | Once |
| 09-16 | 실기 서버 | Continuous 를 쓴 서버에서 셋업으로도 Redfish 로도 순서가 안 바뀌었다. CMOS 클리어로만 복구했다 | Continuous |
| 09-17 | MS04-CE0 1호기 | WinPE 뒤 첫 재부팅에서 셸 낙하. FBO 가 `AP, CD, USB, HD, NET` 이었다 | 맞바꿈 |
| 09-17 | MS04-CE0 2호기 (계측) | 사이클마다 FBO 가 한 칸씩 밀렸다(NET 과 AP, 다음엔 HD 와 AP). Once 무장 뒤 첫 POST 가 PXE 를 안 타는 일이 사이클마다 2 번 있었다 | 맞바꿈, BIOS 자체 POST |
| 10-23 | MS74-HB0 (10.1.1.3) | Windows 항목이 생긴 뒤 POST 에서 셸이 맨 앞에 와 이후 계속 셸 낙하. SHELL_LAST 로 셸을 맨 뒤로 둔 순서가 Once Pxe POST 뒤 다시 셸 앞으로 바뀌었다 | 재생성, 오버라이드 POST |
| 10-26 | MS74-HB0 (10.1.1.3) | R1 4/4, 되돌림 4/4, R2 3/3 확인. 오버라이드 세션 안에서 보낸 Redfish PATCH 가 되돌림 POST 에서 BIOS 밀어 넣기에 덮였다(19:15:08) | 오버라이드 POST, 되돌림 POST, 보류 PATCH |
| 11 월 | 2 종 8~10 대 | 굽기, 설정, RAID 뒤 셸 낙하. 굽기, 설정 뒤 순서가 Disk, CD, USB, Shell, Network. Windows 설치 마지막 부팅에서 일부만 순서가 바뀜 | 맞바꿈(NET 과 AP), 되돌림 POST (해석) |

공통점은 순서 변화가 Once 나 Continuous 를 쓰는 동안에만 기록됐다는 것이다. 오버라이드가 없을 때는 순서가 유지됐다.
