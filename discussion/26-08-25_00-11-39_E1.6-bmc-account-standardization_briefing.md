# E1.6 BMC 계정 표준화 — 착수 브리핑

> **문서 종류**: 단계 착수 브리핑(ue 스트림 인수인계). 원장 = Notion `E1.6 : BMC 계정 표준화`(3차 개발, E 계열).
> **작성**: 2026-08-25 00:11 KST, 앵커 세션(R13 실기 캠페인).

## 1. 유래 — R13 실기에서 관측된 자격증명 폴백 노이즈

신품 BMC(MS74-HB0)는 공장 기본 자격(admin + 보드 시리얼)만 유효해, 앱의 모든 Redfish 호출이 표준 계정을 먼저 시도 → 401 → 공장 기본 폴백을 반복했다. 30초 폴링마다 로그 한 줄("표준 계정 자격증명 거부(401)")이 쌓이고 왕복도 두 배다. 사용자 결정(2026-08-25): **BMC IP 확인 후 자격증명을 변경할 것.**

## 2. 설계 방향 두 축

1. **계정 표준화(본 기능)**: 진단이 BMC IP 를 수집한 뒤 Redfish `AccountService` 로 계정을 사내 표준으로 변경(공장 기본으로 접속해 비밀번호 교체). 변경 시점(수집 직후 자동 vs 운영자 액션)과 실패 시 동작은 설계에서 확정.
2. **성공 자격 캐시(단기 처방 겸 보완)**: 성공한 자격증명을 게스트 단위로 기억해 다음 호출부터 그것을 먼저 시도 — 표준화 이전 장비와 혼재 환경에서도 노이즈가 사라진다.

## 3. 관련 코드 · 실측

- `global/redfish/BmcCredentialsFallback`(401 시 다음 후보 순회) · `BmcCredentialsResolver`(후보 = 표준 → 공장 기본(보드 시리얼) 순서) — E1.5 P1 의 공통화.
- 폴백 로그에는 R13 후속으로 request 컨텍스트("GET /redfish/…")가 이미 실린다.
- E0-4 잔여 실측 항목(Redfish 세션 발급 · ActionInfo 등)과 연계 — AccountService 계약(비밀번호 변경 PATCH 경로 · 제약)은 실측이 선행돼야 한다(T3 체크리스트 참조).

## 4. 주의

- 자격증명 값(사내 표준 비밀번호)은 코드 · 문서에 적지 않는다 — env(`provision.bmc.password`) 주입이 기존 계약.
- 계정 변경은 되돌리기 어려운 조작 — 신원 확인(보드 시리얼 대조, E2-2 D-11 선례) 후 실행할 것.
