# R21 앱 전체 휴대폰 폭 지원: 토론 아카이브

- 단계: R21 (Notion: https://app.notion.com/p/41cef0e868f9812cbb69c6fb3b838117)
- 토론 기간: 2026-11-18 (Notion 단계 페이지의 `## 토론` 절에서 진행, 같은 날 종결)
- 출발점: 디자인 원장 D-21(`docs/design-audit.md`, 390 폭에서 화면이 무너짐)
- 관련: 디자인 원장 D-16, D-17(Miller), D-22(폼 간격), `DESIGN.md` 1절 원칙 7, 4절 반응형, 5절 버튼, 7절 위계 표

## 1. 문제 제기

E4-1-b-2 검수에서 정의서 작성 화면을 390 폭으로 렌더하자 페이지 폭이 511px 로 넘쳤다. 화면 하나의 결함이 아니라 앱이 휴대폰 폭을 설계 대상으로 삼은 적이 없어서 생긴 상태였다. 그래서 원장 D-21 에 사용자 판단 몫으로 적었다.

앵커 세션이 사용자에게 세 안을 물었다.

| 안 | 내용 |
|---|---|
| A | 현 정책 유지(1024 이상만 지원) |
| B | 서버 상세 한 화면만 휴대폰 읽기 지원 |
| C | 앱 전체 휴대폰 지원(사이드바 서랍 전환, 표, Miller, BIOS 설정 편집기, 모달 등 모든 컴포넌트에 좁은 폭 규칙) |

사용자는 C 를 골랐다(원문: "C 로 해서 디자인 세션에 신규 캠페인 진행하도록 지시. 인벤토리 코드는 R 계열로 5차 개발 단계 하위."). `DESIGN.md` 원칙 7("지원 폭은 1024px 이상이다")과 4절을 뒤집는 방향 전환이고 여러 캠페인에 걸치므로 토론으로 쟁점을 먼저 정했다.

## 2. 현행 실태 (2026-11-18 코드 실측, origin/dev b7ab586)

| 대상 | 지금 방식 | 결과 |
|---|---|---|
| 지원 폭 원칙 | 원칙 7 은 1024 이상만 지원한다. 4절은 브레이크포인트를 1024 하나로 두고, 1024 이하에서도 사이드바 228px 를 유지한다 | 휴대폰 폭은 설계 대상이 아니었다 |
| viewport | `fragments/layout.html` 에 `width=device-width` 가 이미 있다 | 휴대폰이 화면을 축소하지 않고 실제 폭으로 그려 넘침이 그대로 드러난다 |
| 사이드바 | `style.css` 의 `flex: 0 0 228px`, sticky. 링크 18 개. 폭과 무관하게 펼쳐져 있다 | 390 폭이면 본문 칸이 약 130px 다 |
| 브레이크포인트 | CSS 16 개 중 9 개 파일에 max-width 규칙 15 개. 1024 가 4, 900 이 6, 640 이 2, 600 이 2, 480 이 1 | 경계가 다섯 가지로 흩어져 있고 휴대폰 기준 경계는 없다 |
| 표 | `n-table` 을 쓰는 템플릿 25 개, 표 47 개. 가로 스크롤 감싸기 `n-table-scroll` 은 4 곳이고 640 이하에서만 동작한다 | 대부분의 표가 페이지 전체를 넘친다 |
| Miller | 관리 화면 6 곳과 정의서 작성 ISO 고르기. 1024 이하에서 상세 열이 아래로 쌓인다 | 휴대폰 폭은 본 적이 없다. D-16, D-17 이 같은 자리다 |
| 비활성 사유 | `n-btn-tooltip-wrap` 29 곳. 마우스 올림(:hover)으로 띄운다 | 터치에는 마우스 올림이 없어 막힌 이유가 보이지 않는다. 'UX 모순은 UI 1차 차단' 원칙이 휴대폰에서 깨진다 |
| 버튼 크기 | 작은 버튼은 글자 13px, 위아래 여백 3px(높이 약 29px) | 손가락으로 누르기에 작다 |
| 점검 도구 | line-scan, overflow-scan 기본 1440, 1024. snippet-check 기본 1440, 1024, 390 | 휴대폰 폭은 조각 점검에서만 본다 |

## 3. 쟁점과 결정

| 질문 | 대안 | 결정 |
|---|---|---|
| Q1 지원 하한 | 360, 390, 768(태블릿까지) | 360. 가장 좁은 흔한 폭이라 여기서 검증하면 기기를 가리지 않는다 |
| Q2 경계 | 둘(1024, 640), 셋(1024, 768, 480) | 둘. 900, 600, 480 규칙은 가까운 쪽으로 흡수한다. 태블릿 사용 사례는 없을 것으로 본다(사용자) |
| Q3 사이드바 | 1024 이하 서랍, 1024 와 640 사이 아이콘 막대 + 640 이하 서랍, 640 이하만 서랍 | 미정. R21-1 plan 의 시안을 보고 정한다(사용자) |
| Q4 표 | 가로 스크롤 + 첫 열 고정, 카드 변환, 열 우선순위 숨김 | 가로 스크롤 + 첫 열 고정을 기본으로 한다. 휴대폰에서 자주 볼 표만 하위 단계에서 따로 판정한다 |
| Q5 Miller | 지금의 쌓기 유지, 한 열씩 넘기기 | 미정. R21-3 plan 의 시안을 보고 정한다(사용자) |
| Q6 터치 | 사유를 곁 글자로 늘 보이기, 막힌 버튼을 누르면 띄우기 | 640 이하에서 곁 글자로 늘 보인다. 누르는 높이는 최소 40px. 5절 버튼 문단("올렸을 때 보여 준다")을 7절 위계 표의 차단 사유 행("비활성 버튼 곁 글자, 같은 문장을 tooltip 에도")에 맞춘다 |
| Q7 우선순위 | 디자인 세션 추정(서버, 알림, 자원 목록, 폼 순) | 게스트 서버 목록과 상세 전체가 휴대폰에서 돼야 한다. 상세의 모든 탭과 딸린 기능(정의서 할당, 개시, 하드웨어 확인, 관리 탭 조작)을 휴대폰에서 쉽게 조작할 수 있게 설계한다(사용자) |
| Q8 분할 | 디자인 세션 제안 | 디자인 세션 판단에 맡김(아래 4절) |
| Q9 검증 폭 | 1440, 1024, 하한 | 1440, 1024, 360. 1024 는 사이드바가 바뀌는 경계라 남기고, 768 은 경계가 아니라 뺀다 |

## 4. 하위 단계 분할

나누는 기준은 CP5 가 한 이야기로 검증되는가이다. Q7 답에 따라 게스트 서버 화면이 공통 부품 정비보다 앞선다.

| 단계 | 범위 | CP5 가 확인하는 이야기 |
|---|---|---|
| R21-1 뼈대와 전역 부품 | 경계 체계와 기존 규칙 흡수, 사이드바 접기(Q3 시안), 본문 여백, 표 공통 가로 스크롤과 첫 열 고정, 비활성 사유 곁 글자와 누르는 높이, `DESIGN.md` 원칙 7과 4절과 5절 버튼 문단 개정, 앵커에 점검 폭 통보 | 어느 화면에서든 360 에서 메뉴로 이동할 수 있고, 표가 페이지를 밀지 않으며, 막힌 버튼의 이유가 보인다 |
| R21-2 게스트 서버 화면 | 서버 목록, 상세 4 탭(표 22 개와 단계 패널), 정의서 할당 고르기 창, 개시, 하드웨어 확인, 관리 탭. 같은 조각을 쓰는 서버 그룹 목록, 상세, 폼. 서버 목록 표의 형태는 시안으로 정한다 | 휴대폰 하나로 서버를 찾아 정의서를 할당하고 개시하고 진행을 끝까지 따라갈 수 있다 |
| R21-3 자원 관리와 선택 부품 | Miller(Q5 시안, D-16, D-17), 조회 띠, 필터 패널, 쪽 이동, 자원 등록 폼과 n-row(D-22 판정) | 자원 6 종을 휴대폰에서 찾고 고르고 등록할 수 있다 |
| R21-4 남은 화면 | 정의서 작성과 상세, BIOS 설정 편집기, 시스템 자산 대시보드, 운영 화면, 로그인 화면 확인, 4절 지원 상태 표 정리 | 남은 화면이 360 에서 넘침 없이 동작한다(캠페인 종료 기준) |

- R21-1 이 먼저다. 사이드바가 228px 를 차지하는 동안에는 다른 화면의 좁은 폭을 확인할 수 없다. 표 감싸기와 비활성 사유는 R21-2 의 서버 상세가 바로 쓰므로 R21-1 에 둔다.
- R21-3 과 R21-4 는 R21-2 뒤 순서를 바꿀 수 있다.

## 5. 탈락 대안

| 대안 | 탈락 사유 |
|---|---|
| 768 하한 | 사용자가 고른 휴대폰 지원과 맞지 않는다 |
| 390 하한 | 360 과 설계 차이가 작고, 360 에서 검증하면 기기를 가리지 않는다 |
| 경계 셋(1024, 768, 480) | 태블릿 사용 사례가 없고, 경계가 늘면 화면마다 확인할 폭이 는다 |
| 아이콘 막대 사이드바 | 링크 18 개를 글자 없는 아이콘으로 구별하기 어렵다. 7절 표기 4번은 아이콘을 방향 표시 같은 화면 장치에만 쓴다 |
| 표 전부 카드 변환 | 표 47 개의 마크업을 모두 바꿔야 하고, 여러 행을 견주는 표에서 비교가 어렵다 |
| 표 열 숨김 일괄 | 숨긴 정보가 휴대폰에서 사라진다 |
| 막힌 버튼을 눌러 사유 띄우기 | disabled 버튼은 누름을 받지 않아 감싸기에 따로 처리가 필요하고, 누르기 전에는 이유가 보이지 않는다 |
| 공통 부품을 모두 정비한 뒤 화면 순 | Q7 이 게스트 서버 화면을 먼저 요구한다 |

## 6. 넘기는 것

- Q3(사이드바)는 R21-1 plan, Q5(Miller)와 서버 목록 표의 형태는 R21-3 과 R21-2 plan 의 시안에서 정한다. 디자인 plan 은 실화면 스냅숏 위의 전후 체험이 몸통이다.
- 지원 폭이 360 으로 정해졌으므로 R21-1 에서 앵커에 cp5-verifier 와 `scripts/design-audit` 스캐너 기본 폭(1440, 1024, 360) 변경을 통보한다.
