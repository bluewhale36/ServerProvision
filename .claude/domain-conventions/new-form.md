# 폼을 추가한다

## 결론부터 — 대개 아무것도 안 해도 된다

상태를 바꾸는 폼은 **가로채기가 기본**이다. `static/global/form-submit.js` 가 레이아웃에서 전역 적재되어 제출을 `fetch` 로 보내고, 거절은 안내 모달로 수렴한다. 마커를 붙이지 않는다.

예외는 하나뿐이다 — **실패 시 뷰를 다시 렌더하는 폼**.

## 판정 — 핸들러가 `BindingResult` 를 받는가

| 핸들러 | 폼 표기 | 이유 |
|---|---|---|
| `BindingResult` 를 받지 않는다 (성공 시 redirect, 실패 시 예외) | **아무것도 안 붙인다** | 그릴 화면이 없다. 모달이 맞다 |
| `BindingResult` 를 받는다 (실패 시 같은 뷰 재렌더) | `data-native-submit="사유"` | 그릴 화면(오류 붙은 폼)이 있다 |
| `@ResponseBody` 로 JSON 을 돌려주고 페이지 전용 JS 가 처리한다 | **아무것도 안 붙인다** | 그 스크립트가 이미 기본 동작을 취소하므로 전역 인터셉터가 비켜간다 |

`BindingResult` 가 정확한 신호인 이유는 **재렌더가 그 파라미터의 유일한 목적**이기 때문이다. "문자열 뷰를 반환하는가" 로 판정하면 헬퍼 메서드로 재렌더하는 핸들러를 놓친다 — 실제로 `IsoUploadController#addIso` 를 그렇게 놓쳤다.

## 빠뜨리면 어떻게 되는가

| 빠뜨린 것 | 결과 |
|---|---|
| 입력 폼에 `data-native-submit` 미부착 | `fetch` 로 나가 서버가 돌려준 재렌더 HTML 을 버린다 → **필드별 오류 표시가 사라진다.** `FormSubmissionConventionTest` 가 CP4 에서 실패시킨다 |
| 사유 없이 `data-native-submit=""` 만 부착 | 같은 테스트가 실패한다. 다음 사람이 의도인지 실수인지 구분할 수 없기 때문 |
| 폐기된 `data-async-submit` 부활 | 같은 테스트가 실패한다. opt-in 구조로 되돌아간 것 |

**테스트가 세는 것은 개수다** — 비 XHR POST 핸들러 중 `BindingResult` 를 받는 것의 수와, `data-native-submit` 이 붙은 폼의 수가 같아야 한다. 한 핸들러에 폼이 둘 붙는 등 정당하게 이 관계가 깨지는 변경이라면 **사유와 함께 기대값을 고친다.** 숫자만 올리지 않는다.

## 테스트가 못 잡는 것

**성공 후 어디로 갈 것인가.** 전역 기본 동작은 현재 페이지 재적재다. 그런데 영구 삭제처럼 보고 있던 자원이 사라지는 액션은 재적재하면 없어진 자원을 다시 요청해 404 가 뜬다.

그런 화면은 페이지 로컬에서 `window.AsyncSubmitResult` 를 덮어써 `resp.url`(서버가 redirect 로 지정한 최종 도착지)로 이동시킨다. 선례는 `static/provisioning/setting-lifecycle.js` 와 `static/maintenance/trash/trash-action.js` 다.

**확인 절차가 필요한가.** 되돌릴 수 없는 액션(영구 삭제)이나 파급이 큰 액션(하위 자원 동반 삭제)은 확인 모달을 거친다. `ConfirmModal.bindFormSubmit` 으로 붙이며, 사용자 승인 후 `approveAndSubmit` 이 전역과 **같은 전송 구현**으로 넘긴다. 두 진입점이 한 구현을 공유하므로 따로 배선하지 않는다.

**애초에 막아야 할 조작인가.** 정상 흐름에서 실패가 예상되는 액션은 버튼을 `disabled` 로 두고 tooltip 으로 사유를 알린다. 서버 가드는 안전망으로 유지하되, UI 차단 조건과 서버 가드 조건은 도메인 메서드 하나를 함께 호출한다.

## 새 화면을 만든다면

레이아웃 fragment 를 쓰는지 확인한다. 전역 인터셉터는 `fragments/layout.html` 에서 적재되므로, 레이아웃을 거치지 않는 화면을 만들면 그 화면의 폼만 조용히 네이티브 제출로 돌아간다. `FormSubmissionConventionTest` 가 레이아웃의 적재 자체는 지키지만 **새 레이아웃을 만드는 경우까지는 못 잡는다.**
