# 작업 전 체크리스트

**이 디렉토리는 설명이 아니라 목록이다.** "이 도메인이 어떻게 동작하는가" 는 `docs/dev/` 가 담당하고, 여기는 **"이것을 건드릴 때 무엇을 함께 건드려야 하는가"** 만 담는다.

## 왜 있는가

S10 의 계기가 된 사고는 이해 부족이 아니라 **빠뜨림**이었다. 규약은 이미 CLAUDE.md 에 있었고 지켜지지 않았다. 설명을 한 겹 더 얹으면 같은 실패가 반복되므로, 항목을 **작업 직전에 펴 보는 짧은 목록**으로 분리했다.

목록은 두 종류로 나뉜다.

- **테스트가 잡는 항목** — 빠뜨리면 CP4 에서 빨간불이 뜬다. 그 테스트 이름을 함께 적는다.
- **테스트가 못 잡는 항목** — 사람이 확인해야 한다. 그래서 여기 적혀 있는 것이다.

두 번째 부류가 이 문서의 존재 이유다. 첫 번째 부류만 있다면 테스트만으로 충분했을 것이다.

## 언제 여는가

| 트리거 | 문서 |
|---|---|
| 새 예외 클래스를 만든다 | [new-exception.md](new-exception.md) |
| 상태를 바꾸는 폼이나 입력 폼을 추가한다 | [new-form.md](new-form.md) |

## 아직 없는 것

아래는 결합 지점이 있다고 알고 있으나 **실측으로 확정하지 않아 작성하지 않았다.** 추측으로 채우면 틀린 목록이 되어 없느니만 못하다.

- 새 자원 도메인 (`Markable` · `MarkableScanner` · `LifecycleService` 5분할 · `*MarkerWriter` · typed-name 가드)
- 새 드리프트 종류 (`DriftKind` 문구 3종 · `DriftResolutionMode` · 해결 전략 · 재확인 지원 여부)
- 새 특권 명령 (`AllowedCommand` · `sudoersLine()` · `ArgShape` · 타임아웃 근거)
- 새 phase · step (`ProvisioningPhase(Step)` · 전진 규칙 · `OwnedPhasesProvider`)

각 항목은 해당 영역을 실제로 건드리는 슬라이스에서 실측해 추가한다.

## 쓰는 법

- 항목을 늘릴 때는 **그 항목을 빠뜨렸을 때 무슨 일이 일어나는지**를 함께 적는다. 결과를 모르면 우선순위를 못 정한다.
- 테스트가 잡아 주게 만들 수 있는 항목은 목록에 적기보다 **테스트로 옮긴다.** 목록은 그렇게 할 수 없는 것들의 자리다.
