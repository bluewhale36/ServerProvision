# 새 예외 클래스를 만든다

## 1. 계층을 고른다 — 대개 advice 수정이 필요 없다

**커스텀 도메인 예외 121 개 중 advice 에 명시 등록된 것은 17 개다.** 나머지는 상위 타입 핸들러가 `@ResponseStatus` 를 계층 탐색으로 읽어 흡수한다. 새 예외도 그래야 한다 — 핸들러를 추가하면 분기가 도메인 수만큼 자란다.

| 상황 | 상속할 것 | 결과 |
|---|---|---|
| 자원을 못 찾음 | `NotFoundException` | 404 |
| 현재 상태와 요청이 충돌 | `ConflictException` | 409 |
| 위 충돌이 **특정 입력 필드와 1:1** | `FieldBoundConflictException` | 409 + `fieldErrors[]` |
| 잘못된 입력이 **특정 입력 필드와 1:1** | `FieldBoundBadRequestException` | 400 + `fieldErrors[]` |
| 그 외 4xx | `DomainException` + `@ResponseStatus` 직접 부착 | 그 상태코드 |
| 저장소 · IO 실패 | `DomainException` (어노테이션 없음) | 500 + ERROR 로그와 스택 |

`FieldBound*` 를 고르면 `fieldName()` 을 구현해야 하고, 그 값이 폼의 오류 표시 위치로 자동 매핑된다. **필드가 특정되지 않는데 `FieldBound*` 를 고르지 않는다** — 표시할 자리가 없다.

**보안 예외는 이 계층 밖이다.** `SecurityException` 을 상속하고 `httpStatus()` 를 구현한다. 두 계층을 섞으면 과거 사고(도메인 예외를 잡는 코드가 보안 예외까지 흡수)가 재발한다.

## 2. advice 에 명시 등록이 필요한지 판단한다

**아래 중 하나라도 해당할 때만** 등록한다. 아니면 등록하지 않는다.

- 고유한 상태코드가 필요하다 (예: 410 Gone)
- 응답 몸체가 `ApiErrorResponse` 가 아니다 (예: 재확인 세션, 삭제 의도 토큰)
- 프런트가 메시지 문자열이 아니라 **안정된 코드**로 분기해야 한다 → `ApiErrorResponse.ofCode(...)`

등록한다면 **JSON 쪽만** 넣는지 확인한다. HTML 변형을 함께 넣으면 모호한 `Accept` 에서 XHR 이 HTML 을 받아 파싱이 깨진다.

## 3. 로그 정책을 확인한다

`ExceptionLogPolicy.record(eventCode, ex, status, variant)` 가 레벨을 결정한다. 5xx 는 스택을 동반한 ERROR, 4xx 는 스택 없는 WARN 이다.

**예외 하나당 스택 한 번**이 원칙이다. 가드나 서비스가 이미 스택을 남겼다면 advice 는 DEBUG 로 경계만 찍는다. 두 곳에서 남기면 같은 스택이 중복 방출된다.

**메시지 본문을 로그에 싣지 않는다.** 자원명 같은 사용자 입력이 메시지에 섞인다.

## 4. 테스트를 함께 만든다 — 이것이 빠지면 CP4 승인 대상이 아니다

새 예외를 추가하면 **그 예외를 실제로 발생시키는 시나리오 테스트**를 함께 추가한다. 단위 테스트만 있고 통합 시나리오가 빠진 묶음은 승인되지 않는다.

- **단위** — Service 분기별 happy 1 + 실패 1
- **통합** — `@WebMvcTest` + `MockMvc` 로 HTTP 계층에서 실제 상태코드와 바디 검증. Mocking 은 Service 단까지만 두어 advice 매핑이 실제로 실행되게 한다

과거 `MissingFilenameException` 이 500 으로 새던 사고가 이 규율의 출처다.

## 5. 사용자가 그 예외를 보게 되는 경로를 확인한다

**여기가 테스트로 다 잡히지 않는 자리다.**

예외가 뜨는 상황이 정상 UX 흐름에서 도달 가능하다면, 그건 예외로 막을 일이 아니라 **UI 가 먼저 차단할 일**이다. 예외는 direct POST · 동시성 · stale · 외부 변조 같은 진짜 비정상에서만 발동해야 한다.

- UI 차단 조건과 서버 가드 조건은 **도메인 메서드 하나를 함께 호출**한다. 두 곳에 복붙하면 드리프트가 생긴다
- 버튼을 `disabled` 로 막았다면 **왜 막혔는지** tooltip 으로 알린다

응답 형식은 신경 쓰지 않아도 된다. 액션 폼은 전역 인터셉터가 `fetch` 로 보내 안내 모달로 수렴하고, 문서 이동은 필터가 오류 페이지로 보낸다. 다만 **새 폼을 함께 추가한다면** [new-form.md](new-form.md) 를 본다.
