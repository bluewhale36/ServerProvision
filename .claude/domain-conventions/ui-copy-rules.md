# 화면 문구를 쓰거나 고치기 전에

화면에 보이는 문구(안내, 오류, 배지, 라벨, 확인 창, 원장 사유처럼 화면에 그려지는 모든 글자)를 새로 쓰거나 고칠 때 이 문서를 연다. 어휘의 정본과 문체 기본은 `new-user-copy.md` 를 따르고, 이 문서는 S22(화면 정보 위계 재편, 2026-11)에서 사용자가 확정한 기준을 더한다. 판정의 근거 자료는 `docs/ui-copy/`(서버 상세 문구 판정표와 화면 자리 범례), 반영 기록은 S22-3 커밋이다.

## 1. 화면에 남길 정보

1. 화면에는 PXE 서버를 운영하면서 그 자리에서 알아야 하는 정보와 중요한 안내만 남긴다. 사용법, 동작 원리, 엔진 설명처럼 문서와 겹치는 문구는 화면에서 뺀다. 문서화는 별도 세션(ServerProvision-docs)이 맡는다.
2. 남기는 문구는 운영자가 지금 할 일을 정하는 것이다: 긴급 실패, 주의, 상태와 진행, 결과와 기록, 다음 행동, 차단 사유, 조작 결과 알림, 확인 문구, 빈 값 안내, 라벨.
3. 같은 사실은 한 자리에서 한 번만 말한다. 배지가 이미 말하는 것을 문장으로 다시 쓰지 않는다.
4. 다음은 화면에 보이지 않는다.
   - 내부 식별자(`id=`, `guestId=`, `definitionId=`)
   - 코드 상수와 enum 이름(예: `RAID_APPLYING`, `CARD_MISMATCH`, `MPT_IR`)
   - 프로토콜 원문(요청 경로, HTTP 상태 줄, ETag 같은 헤더 이름)
   - 에이전트나 외부 도구의 영어 원문
   - 설정 키 이름(예: `provision.bmc.password`)
   - 기술 표준 약어(PXE, BMC, BIOS, RAID, ISO, NIC, IP, MAC, UUID)와 장비가 쓰는 고유 이름(예: CSRFToken, Subsystem)은 허용한다.

## 2. 위계와 자리

쓰임새와 심각도에 따라 자리와 모양을 정한다. 무거운 사실이 흐린 글자에 묻히지 않게 하고, 가벼운 사실이 경보 모양을 쓰지 않게 한다.

| 쓰임새 | 모양 | 자리 |
|---|---|---|
| 긴급 실패(진행이 멈추고 사람이 조치해야 다시 움직인다) | 빨간 경보 판(`n-alert-danger`) | 화면 전체에 걸리면 맨 위 띠, 한 구획의 일이면 그 구획 맨 위 |
| 주의(진행을 막지 않는 예고, 자원 대기, 되돌릴 수 없는 결과의 예고) | 노란 판(`n-alert-warning`) 또는 노란 글자(`n-hint-warn`) | 관련 항목 곁 |
| 조작 결과 알림 | 결과에 맞는 색: 성공 초록, 부분 성공이나 미확인 노랑, 실패 빨강 | 페이지 맨 위 알림 |
| 차단 사유 | 비활성 버튼 곁에 보이는 글자, 같은 문장을 tooltip 에도 | 버튼 곁 |
| 결과와 기록 | 보통 글자 | 값 곁 |
| 빈 값 | '-' 또는 짧은 한자어 명사형(미검출, 미소속, 미지정, 미입력) | 그 칸 |

진행을 막지 않는 사실은 빨강을 쓰지 않는다. 실패 사유처럼 화면에서 가장 크게 보이는 자리에 오르는 값은, 그 값이 정확한지 다시 확인한다.

## 3. 표기

1. 대시(—)는 쓰지 않는다. 문장은 콜론, 마침표, 접속사로 잇는다.
   - 예: "미검출 — 전원 제어를 쓸 수 없습니다" 대신 "미검출: 전원 제어를 쓸 수 없습니다"
2. 가운뎃점(·)은 쓰지 않는다. 나열은 쉼표나 접속사로 한다.
   - 예: "주소 · 네트워크 · BMC 상태" 대신 "주소, 네트워크, BMC 상태"
   - 상태와 값을 붙여 쓸 때는 괄호를 쓴다. 예: "끊어짐(3분 전)", "RAID 구성 실패"
3. 문장은 '~합니다.'로 끝내고, 요청은 '~하십시오.'로 끝낸다. 짧은 표지와 배지는 한자어 명사형으로 끝낸다.
4. '~음', '~함', '~됨', '~ㅁ' 꼴로 끝내지 않는다. 해요체('~해요', '~하세요', '~해주세요')도 쓰지 않는다.
   - 예: 없음 → 미지정, 미검출, 미배치, 0개 / 등록됨 → 등록 / 회수됨 → 회수 / 건너뜀 → 생략 / 설정됨 → 설정 완료 / 안 함 → 생략, 미설정 / 문제 없음 → 정상
   - 진행 중인 상태는 '~ 중'을 쓴다. 예: 굽는 중, 프로비저닝 중
   - '다음', '처음'처럼 낱말 자체가 '음'으로 끝나는 것은 해당하지 않는다.
5. '축'처럼 내부 설계에서만 쓰는 표현을 쓰지 않는다. 과하게 서술하지 않고, 정보 전달에 필요한 만큼 간결하게 쓴다.
6. 빈 값 표시는 '-'를 쓴다.

## 4. 고치는 방법

1. 화면이 그릴 때마다 만드는 문장(템플릿, 메시지 키, 화면용 Java 문장, JS)은 출처에서 고친다.
2. DB(원장 등)나 로그에 저장되면서 화면에도 나가는 문장은 원문을 두고 화면으로 나가는 경계에서 바꾼다. 원문은 원인 추적에 쓰이기 때문이다.
   - 오류 응답: `UserFacingMessage`(내부 식별자 제거, 대시와 가운뎃점 변환). `ApiErrorResponse` 가 만들어질 때 적용된다.
   - 원장 사유: `ScreenNote`(요청 경로 제거, 항목 상수를 화면 이름으로, 옛 문장 대응표, 대시와 가운뎃점 변환)
   - 저장되는 문장의 출처를 고치더라도 과거 행에 옛 문장이 남으므로 대응표에 옛 문장을 함께 둔다.
3. enum 의 화면 이름은 `description`(또는 기존 표시 이름 필드)으로 두고, 화면은 상수 원문 대신 그 이름을 쓴다.
4. 여러 화면이 함께 쓰는 정의(enum 이름, 공용 조각, 공용 JS)를 고치면 다른 화면도 함께 바뀐다. 무엇이 함께 바뀌는지 기록한다.
5. 테스트는 새 문장으로 단언을 바꾼다. 다만 저장된 옛 문장을 입력으로 쓰는 테스트(경계 변환을 검사하는 것)의 입력값은 바꾸지 않는다. 입력과 기대값을 같은 규칙으로 함께 바꾸면 그 테스트는 아무것도 검사하지 않는다.
6. 사용자가 입력한 데이터(정의서 이름, 메모 등)는 고치지 않는다.

## 5. 검증

소스 검색만으로 끝내지 않는다. 저장된 문장, enum 이름, 버튼을 눌러야 열리는 창이 소스 검색에서 빠지기 때문이다. 샌드박스 화면을 실제로 열어, 렌더된 글자와 tooltip 에서 대시, 가운뎃점, '~음' 꼴, '축'을 센다. 서버 상세의 선례 도구는 `sbx-design/S22-2-hierarchy/legend/text-scan.mjs`(상세 네 탭)와 `picker-scan.mjs`(정의서 선택 창)다.
