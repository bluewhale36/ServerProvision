# 점검 대상별로 여는 절

규칙 문장은 `DESIGN.md` 에만 있다. 이 표는 어디를 열지와 무엇을 볼지만 가리킨다. 절 제목이 바뀌면 이 표를 같이 고친다.

| 점검 대상 | 여는 곳(DESIGN.md) | 볼 것 |
|---|---|---|
| 어떤 부품을 쓸지 | 5절 고르기 | 표에 행이 있는가, '쓰지 않는 것' 칸에 걸리지 않는가 |
| 선, 테두리 | 5절 구분선 | 경계 하나에 선 하나인가, 판 테두리 옆에 선을 더 긋지 않는가 |
| 표 | 5절 표, 9절 표 타입 선택 | 목록은 `n-table` + `thead`, 라벨과 값은 `n-detail-table` |
| 식별자 값(경로, IP, 해시) | 5절 인라인 코드와 mono, 고르기 표의 식별자 행 | 표 칸이면 `n-table-mono` 인가, 긴 값이 옆 열을 누르지 않는가 |
| 폼 항목, 힌트 | 5절 폼, 고르기 표의 주석 행 | 라벨 `n-label strong`, 힌트 `n-hint`, 힌트를 다른 자리(표 칸 안)에 빌려 쓰지 않는가 |
| 배지, 상태 표지 | 5절 배지, 6절 | 색이 상태를 뜻하는가, 같은 상태가 화면마다 같은 색인가 |
| 버튼, 비활성 사유 | 5절 버튼 | 비활성 사유를 감싸는 방식, 주 동작 하나 |
| 다단 선택 | 5절 Miller, 9절 페이지 스코프 컴포넌트 | 컴포넌트 통째 재사용, 화면 CSS 는 치수만 |
| 조회 띠, 검색 선택기 | 5절 조회 띠와 쪽 이동, 9절 화면 조각 | 조각을 쓰는가, 동작 스크립트가 정해져 있는가 |
| 좁은 폭 | 4절 반응형, 해당 컴포넌트 절 | 1024 이하 배치(쌓임)에서 선, 폭, 넘침 |
| 글자 크기, 굵기 | 3절 타이포그래피 | 층에 있는 크기인가 |
| 색 | 2절 토큰, 8절 | 토큰만 쓰는가 |
| 클래스 이름 | 8절 | 정의 있는 `n-` 인가, 두 번째 이름이 아닌가, 표지는 `data-*` 인가, 인라인 스타일이 없는가 |
| 컴포넌트 덮어쓰기 | 9절 문맥 스타일 오버라이드, 페이지 스코프 컴포넌트 | 치수만 덮는가, 동작을 바꾸려면 컴포넌트 변형인가 |
| 화면 조각 | 9절 화면 조각 | 조각 표에 행이 있는가, 쓰는 화면 칸이 맞는가 |

## 문구 점검 순서(7절)

1. 남길 정보: 운영 중 그 자리에서 알아야 하는 것인가. 사용법과 기술 설명이 아닌가. 같은 사실을 배지와 문장이 되풀이하지 않는가.
2. 위계와 자리: 막는 실패와 막지 않는 주의를 구분했는가. 막는 사유가 보이는 글자로 막힌 조작 곁에 있는가.
3. 문체: 합니다체 평서형인가. 금지된 문체와 종결 꼴이 없는가.
4. 단어: 설계 어휘, 내부 식별자, enum 원문, 프로토콜 원문이 없는가.
5. 표기: 금지된 기호가 없는가. 빈 값 표기가 맞는가. 영문 뒤 조사 띄어쓰기.

`scripts/design-audit/lib.mjs` 의 `BAD` 정규식이 3과 5의 일부를 기계로 잡는다. 나머지는 사람이 본다.
