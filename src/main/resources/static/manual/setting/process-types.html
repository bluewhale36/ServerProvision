단계 종류별 설정

세팅 정의서에 넣을 수 있는 단계는 펌웨어 업데이트, BIOS 설정, RAID 구성, OS 설치 네 가지입니다. 단계는 이 순서로 실행되며, 단계마다 입력 칸과 실행 방식이 다릅니다.

펌웨어 업데이트

서버의 BIOS 펌웨어와 BMC 펌웨어를 업데이트합니다. 진행 화면에는 펌웨어 업데이트 단계로 표시됩니다.

입력 칸선택지설명
메인보드 모델자동 감지(기본), 활성 메인보드 모델자동 감지는 실행할 때 서버의 보드 모델을 감지
업데이트할 BIOS 버전최신 버전(기본), 고른 보드의 활성 BIOS 펌웨어최신 버전은 실행할 때 그 보드의 순위 1위 활성 펌웨어
업데이트할 BMC 버전최신 버전(기본), 고른 보드의 활성 BMC 펌웨어BIOS 버전과 같은 방식
  • 메인보드를 자동 감지로 두면 두 버전 칸이 최신 버전으로 고정되어 바꿀 수 없습니다.
  • 메인보드를 직접 지정하면 그 보드의 펌웨어만 고를 수 있습니다. 보드를 바꾸면 다른 보드의 버전을 골라 둔 칸은 최신 버전으로 돌아갑니다.
  • 직접 지정한 보드에 활성 펌웨어가 하나도 없으면 "이 보드에 등록된 BIOS 펌웨어가 없습니다" 안내가 표시됩니다. 저장은 되며, 실행할 때까지 펌웨어를 등록하지 않으면 그 업데이트를 건너뜁니다.
  • 메인보드를 직접 지정했는데 서버의 보드가 다르면 실행할 때 BIOS 와 BMC 업데이트가 모두 차단됩니다.

최신 버전이 고르는 펌웨어와 반영 확인 방식은 BIOS 펌웨어에서 설명합니다.

BIOS 설정

BIOS 세팅 템플릿의 값을 서버의 BIOS 에 적용합니다. 진행 화면에는 펌웨어 설정 단계로 표시됩니다.

참고

이 단계를 넣으면 BIOS 설정에 이어 BMC 표준 설정(시간대, NTP, 전원 이중화, 네트워크 Bond 등)도 함께 적용됩니다. 작성 화면에는 이 안내가 없습니다. 이 단계를 넣지 않으면 BMC 표준 설정도 적용되지 않습니다.

입력 칸선택지설명
메인보드 모델자동 감지(기본), 활성 메인보드 모델펌웨어 업데이트 단계가 함께 있으면 그 단계의 선택으로 고정
적용할 BIOS 세팅 템플릿등록된 템플릿 전체. 템플릿마다 보드 이름 표시하나 이상 필수
  • 메인보드를 직접 지정하면 그 보드의 템플릿 1개만 고를 수 있습니다. 다른 템플릿을 고르면 앞의 선택이 바뀝니다.
  • 자동 감지로 두면 보드마다 템플릿을 1개씩 고를 수 있습니다. 실행할 때 서버에서 감지된 보드의 템플릿 1개만 적용되고, 맞는 템플릿이 없으면 BIOS 설정을 건너뛴 뒤 BMC 표준 설정을 진행합니다.
  • 템플릿이 하나도 없으면 "등록된 BIOS 세팅 템플릿이 없습니다" 안내가 표시됩니다. 먼저 BIOS 세팅 템플릿을 작성합니다.

RAID 구성

RAID 카드로 디스크를 묶어 볼륨을 만들고, 어느 볼륨을 OS 영역과 Data 영역으로 쓸지 정합니다. RAID 카드를 이용한 구성만 지원하며 메인보드 내장 RAID 는 지원하지 않습니다. OS 설치 단계를 넣는다면 이 단계가 반드시 필요합니다.

RAID 카드와 기존 구성 처리

입력 칸선택지설명
RAID 카드선택 안 함(기본), 활성 RAID 카드RAID 로 묶는 디스크 묶음이 있으면 필수. 카드의 지원 레벨과 디스크 수 규칙이 묶음 표의 선택지를 결정
기존 구성 처리기존 구성 보존, 기존 구성 파괴. 기본값 없음RAID 로 묶는 묶음이 있으면 필수
  • 기존 구성 보존을 고르면, 카드에 PXE 서버가 만들지 않은 RAID 볼륨이 남아 있는 서버에서는 RAID 구성 단계가 실패로 기록됩니다. 이전 프로비저닝이 만든 볼륨은 지우고 다시 구성합니다.
  • 기존 구성 파괴를 고르면 카드의 기존 볼륨을 모두 지운 뒤 정의서대로 다시 구성합니다. 디스크에 저장된 데이터는 삭제되며 복구할 수 없습니다.

디스크 묶음 규칙

묶음 하나는 RAID 레벨, 디스크 종류, 전송 방식, 용량, 개수로 정합니다. 위의 묶음부터 차례로 조건에 맞는 디스크를 가져가고, 남은 디스크는 아래 묶음으로 넘어갑니다. 어느 묶음에도 맞지 않는 디스크는 사용하지 않습니다. + 묶음 추가 로 행을 더하고, 행 왼쪽의 ☰ 아이콘을 끌어 순서를 바꿉니다.

열선택지설명
RAID 레벨RAID 없음(기본), RAID0, RAID1, RAID5, RAID6, RAID10RAID 카드를 고른 뒤 선택 가능. 카드가 지원하지 않는 레벨은 선택 불가
종류SSD, HDD, 자동 탐지자동 탐지는 같은 사양의 디스크끼리 묶음
전송SATA, SAS, NVMe, 자동 탐지HDD 에는 NVMe 선택 불가
용량자동 탐지(기본), 직접 지정(GB, TB)직접 지정은 1 이상의 크기 필요
개수숫자와 방식(개, 개씩, 개 이상)아래 표 참고. 카드와 레벨을 고르면 허용 대수가 칸에 표시
역할우선순위에 따름(기본), OS 영역, Data 영역, 영역 할당 없음OS 영역은 한 묶음만 지정 가능
개수 방식동작
개조건에 맞는 첫 디스크 그룹에서 슬롯 순서로 n 개를 가져가 볼륨 하나 구성. 남은 디스크는 아래 묶음으로
개씩조건에 맞는 그룹마다, 그룹의 디스크 수가 n 의 배수일 때 n 개씩 나눠 전부 구성(같은 사양 4개를 RAID1 2개씩이면 볼륨 2개)
개 이상조건에 맞는 그룹마다, n 개 이상이면 그룹 전체로 볼륨 하나 구성
  • RAID 레벨을 RAID 없음으로 두면 그 묶음의 디스크를 RAID 로 묶지 않고 그대로 씁니다. 단, OS 설치 단계가 있는 정의서에서 RAID 없음 묶음이 디스크를 하나라도 가져가면 실행할 때 OS 설치 단계에서 막히므로, OS 를 설치하는 정의서에는 RAID 없음 묶음을 두지 않습니다.
  • 그룹은 종류, 전송, 용량이 같은 디스크의 모음입니다. 종류나 전송을 자동 탐지로 두면 사양이 다른 그룹마다 볼륨이 따로 생깁니다.
  • 묶음 하나의 디스크 수 허용 범위는 카드의 칩 계열이 정합니다. 예를 들어 MPT IR 카드는 RAID1 을 정확히 2대로만 만들 수 있습니다. 허용 범위를 벗어나면 개수 칸이 빨갛게 표시되고 아래에 허용 대수가 나옵니다.
  • 칩 계열이 만들 수 있는 볼륨 수(MPT IR 은 2개)는 작성 화면이 검사하지 않습니다. 넘으면 실행할 때 RAID 구성이 보류됩니다.
  • MegaRAID 카드의 RAID10 묶음에서는 개수 칸 아래에서 스팬당 디스크 수를 정합니다.
  • 같은 조건의 묶음을 두 번 넣거나, 앞 묶음이 뒤 묶음의 디스크를 모두 가져가 뒤 묶음이 쓰일 수 없으면 저장되지 않고 안내가 표시됩니다.

볼륨 우선순위

역할이 우선순위에 따름인 묶음들의 볼륨 가운데 어느 것을 OS 영역으로 쓸지 정하는 순서입니다. 볼륨은 종류와 전송 방식이 같은 첫 행의 순위를 받고, 같은 행 안에서는 그 행의 용량 순서(작은 용량부터, 큰 용량부터)를 따르며, 가장 앞선 볼륨이 OS 영역이 됩니다. 어느 행에도 맞지 않는 볼륨은 맨 뒤에 놓입니다. 묶음 하나를 OS 영역으로 고정했다면 우선순위는 쓰이지 않습니다. OS 가 아닌 볼륨은 역할이 영역 할당 없음이면 어디에도 쓰이지 않고, 그 밖에는 Data 영역이 됩니다.

처음 열면 기본 5행(SSD NVMe, SSD SAS, SSD SATA, HDD SAS, HDD SATA 순, 모두 작은 용량부터)이 들어 있습니다. 기본 행으로 되돌리기 는 확인 창 없이 기본 5행으로 바꿉니다.

주의

OS 설치 단계가 있는 정의서는 OS 영역이 정해질 수 있어야 저장됩니다. 묶음 하나의 역할을 OS 영역으로 정하거나, 역할을 우선순위에 따름으로 두고 볼륨 우선순위 행을 둡니다. 묶음을 하나도 두지 않아도 저장은 되지만, OS 설치 단계가 실행할 때 막히므로 OS 를 설치할 묶음을 반드시 둡니다.

OS 설치

RAID 구성 단계가 만든 OS 영역 볼륨에 Windows Server 를 설치합니다. 현재 설치할 수 있는 OS 는 Windows Server 뿐입니다.

입력 칸설명
설치할 OS사용할 수 있는 ISO 가 있는 활성 OS 버전. 리눅스 계열은 선택 불가로 표시. Windows 설치 소스가 준비되지 않았으면 Windows Server 도 선택 불가
설치 ISO고른 OS 버전의 활성 ISO. 하나뿐이면 자동 선택
설치 이미지 (에디션)시스템 자산 화면의 Windows 설치 소스에 있는 install.wim 의 이미지 목록. 어느 OS 버전을 골라도 같은 목록
Administrator 비밀번호127자 이하, 영문, 숫자, 기호만 사용(공백과 한글 불가). Windows 비밀번호 정책(길이, 복잡도)은 설치할 때 Windows 가 판정하므로 맞지 않으면 설치가 끝나지 않는다
  • 설치할 디스크를 고르는 칸은 없습니다. RAID 구성 단계의 OS 영역 볼륨에 설치됩니다.
  • 시간대, 제품 키, 설치 소스 접속 정보는 정의서가 아니라 PXE 서버의 운영 설정에서 옵니다.
  • 드라이버는 정의서에서 고르지 않고, 실행할 때 서버의 보드와 대상 OS 에 맞는 드라이버가 자동으로 설치됩니다(드라이버와 유틸리티).

OS 후처리 설정

예전 정의서에는 OS 후처리 설정 단계가 남아 있을 수 있습니다. 이 단계는 지금 새로 넣을 수 없고, 수정 화면에도 카드가 나오지 않습니다. 그런 정의서를 수정해 저장하면 이 단계는 빠집니다.
