§0. 도메인 흐름 — 설치 트리가 왜 필요한가
v1 → v2 : 2026-11-17 사용자 결정 B: 미리 풀어 두면 디스크를 두 배로 쓰므로, 설치를 시도할 때 임시 작업 디렉터리에 풀고 그 ISO 로 설치 중인 서버가 없어지면 지운다.
개정 1 (2026-11-17, 세션 검수 판정 · CP1 승인 전) :
  • 신규 예외 클래스 없음 확정 (§4)
  • 확보 실패 = 대기 대신 OS 설치 단계 실패, 다시 시도는 운영자 [재시도] 의 새 acquire (§3 · D-10)
  • EXTRACTION_FAILED 문구 확정 · 즉시 실패와 추출 단계 실패 구분 · 추출 중 보유자 0 처리 확정
  • 패키지 세분 execution/installtree/{config, service, vo, enums} (§4 · §10)
  • AsyncConfig = 고쳐서 · HF6 선례 실명

네트워크 설치에서 설치기(anaconda)는 설치 원본을 HTTP 로 파일 단위로 읽는다. ISO 는 10 GB 파일 하나라 그 안의 파일을 경로로 내줄 수 없다 → ISO 를 폴더로 펼친 "설치 트리" 가 필요하다.

§1. 진단 (실측)

ISO 를 풀어 둘 자리도, 버전별 설치 원본도 지금은 없다.

ISO 를 풀 영속 · 공유 장치 없음. IsoPreparationService.prepare() 는 임시 폴더 · close 때 삭제 · mount 는 root 필요 · 7z → bsdtar · 도구 출력을 읽지 않아 출력이 많으면 멈출 위험IsoPreparationService

설치기는 커널을 받은 뒤에도 설치 내내 패키지를 받음 → 삭제 기준은 설치 종료 (완료 · 실패 · 시한)anaconda 동작

§5-b. 운영 배치 (앵커 자문 11-17)

항목내용
자리/var/lib/serverprovision/served/install-trees — 자원 볼륨 (590 G 중 574 G 남음, VG 여유 198 G). / (71 G) · /var (112 G, DB · 로그) · /var/tmp (PrivateTmp, 재기동 때 지워짐) 는 피함
served 인 이유OPS-2 D2 "서빙되는 것과 아닌 것을 부모 디렉터리로 가른다". 트리는 Anaconda 가 HTTP 로 받아 가는 서빙 대상. 실제 서빙은 nginx → 앱 컨트롤러 (등록 ISO 기준 완성 트리만). 원시 경로를 여는 정적 매핑은 두지 않음
쓰지 않는 곳internal/work (OPS-2 D4, IsoPreparationService 열람용 임시 공간 · 서빙 대상 아님)
형제 관계allowed-roots (served/resources) · PXE 자산 (served/pxe) 의 형제 → 무결성 스캐너가 훑지 않고 자산 이력과 섞이지 않음
권한provisioning:provisioning · 0755 (운영자가 손으로 쓰는 자리 아님 — spvadmin · setgid 안 줌). 유닛 ProtectSystem=strict · ReadWritePaths=/var/lib/serverprovision 아래라 drop-in 불필요. 자원 볼륨 noexec 는 서빙 전용이라 무관
도구spv-01 에 7z · 7za · bsdtar 없음. EL9 AppStream 의 bsdtar 패키지 설치 필요 (EPEL 불필요, 이름 · 저장소는 dnf info 로 확정). 앱은 비특권이라 mount 불가 → 7z · bsdtar 설계가 맞음
관찰 (범위 밖)같은 이유로 지금 운영의 IsoPreparationService 압축 해제 대체 경로도 동작하지 않을 것
런북 반영 (이번 슬라이스 문서 변경)docs/staging-vm-bootstrap.md: 디렉터리 생성 블록에 served/install-trees · env 블록에 RHEL_INSTALL_TREE_ROOT=/var/lib/serverprovision/served/install-trees · 패키지 설치 절에 bsdtar. docs/pxe-server-install.md: 파티션 표 자원 볼륨 비고에 "RHEL 설치 트리 (ISO 당 약 10 GB, 동시 2~3 개)"
운영 반영배포 때 앵커가 사용자 지시로 (폴더 생성 · 패키지 설치 · env 추가)

§7. 접근 통제 — b-4 가 구현할 계약

사용자 질문 (11-17) 반영. b-1 은 InstallTree.resolve 만 만들고, 나머지 겹은 b-4 가 구현한다.

겹장치
① 경로에 추측 가능한 값 없음URL /api/pxe/v1/rhel/{토큰}/…, 토큰 = 서버마다 무작위 UUID. ISO id · 서버 id 는 경로에 없고 서버 안에서 토큰 → 게스트 → 활성 정의서 → isoId
② 모르는 토큰 거절게스트 인증 필터 (GuestCredentialConverter 에 rhel 종류 추가)
③ 토큰은 PXE 부팅으로만/boot (LAN ∧ PXE 부팅 계정) 를 통과해 OS 설치 단계에 도달한 RHEL 서버에만 발급
④ 짧은 수명완료 · 실패 · 시한 때 회수 · 메모리
⑤ LAN 제한게스트 채널 전체 LAN ∧ 게스트 인증. 운영 서버에 PXE_GUEST_ALLOWED_CIDRS 설정 필요 (비면 제한 없음 · WARN)
⑥ 파일 범위요청 경로를 그 ISO 작업 트리 안으로만 해석 (InstallTree.resolve) · .. · 트리 밖 · 숨김 파일 (.treeinfo 제외) 거절
⑦ kickstart비밀번호 해시가 들어가므로 그 서버 설치가 진행 중 (원장 RUNNING) 일 때만 서빙
관리 요청과 게스트 서빙의 구분 : v2 에는 관리 요청 (POST /management/…/install-tree) 이 없다 (v1 폐기). 작업 트리는 설치 내부에서만 다룬다.
