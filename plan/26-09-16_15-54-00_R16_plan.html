§1. 현재 상태 (진단)

1-1. 배경 — 왜 지금인가

2026-09-15 사용자 확인으로 두 가지가 동시에 닫혔다. 사내망 배포에서는 우리 DHCP 를 띄울 수 없고, 사내 DHCP 도 우리가 수정할 수 없다. 이어 2026-09-16 네트워크 관리사 회신은 정확한 확인은 불가하나 정황상 별도 제약 (DHCP snooping 차단 등)은 걸려 있지 않을 것이라는 내용이었다. 즉 우리가 IP 를 배정하는 길은 막혀 있지만, 부팅 옵션만 얹는 응답까지 차단돼 있다고 볼 근거는 없다. 그래서 PXE 규격이 이 상황을 위해 두고 있는 proxyDHCP — IP 는 사내 DHCP 가 주고 부팅 옵션만 우리가 준다 — 로 첫 접촉을 바꾸는 시험에 들어간다. 설명 자료는 discussion/26-09-15_16-29-30_proxydhcp-first-contact_brief.html(앵커 미커밋)이다.

한 데몬 · 두 모드 — 그러나 실습 LAN(192.168.1.0/24 · 실기 1~4호)은 우리 DHCP 가 IP 까지 준다. 그 경로를 잃으면 실기 회귀 수단이 없어진다. 따라서 이 슬라이스는 "proxy 전용" 이 아니라, 한 데몬이 두 모드를 내는 구조다.

이 표에서 갈라 봐야 할 것은 "데몬에 묶인 것" 과 "데몬과 무관한 것" 이다. 적용 파이프라인(스왑 · 게이트 · 재기동 · 검증 · 롤백 · 이력 · 락)은 데몬과 무관한 자산이고 그대로 남는다. 바뀌는 것은 무엇을 렌더하고, 어떤 명령으로 검사 · 재기동하며, 무엇을 관측하는가 다. 그래서 이 슬라이스의 부피는 커 보여도 위험이 몰려 있는 지점은 렌더러 · 명령 셋 · 임대 파서 셋으로 좁다.

1-3. 게스트 첫 접촉의 두 단 (현행 · dhcpd)

  1. PXE ROM 이 DHCPDISCOVER(option 60 = PXEClient)를 보내면 dhcpd 가 IP 와 next-server · filename ipxe.efi 를 함께 준다.
  2. ROM 이 tftp 로 ipxe.efi 를 받아 올린다.
  3. iPXE 가 다시 DHCP 를 돌린다(user-class iPXE). 이때 dhcpd 는 filename 으로 boot.ipxe 를 준다 — 같은 파일을 주면 무한 체인이 된다(2026-08-24 실기 보정).
  4. tftp 로 boot.ipxe 를 받아 chain http://pxe:<secret>@<서버>/api/pxe/v1/boot?… 로 넘어간다(S19-2 가 정한 PXE 부팅 계정 credential 이 여기 실린다).
  5. 이후 등록 · 진단 · RAID · 펌웨어 · 설정 · Windows 설치는 이 전환과 무관하다.

바꾸는 것은 ①과 ③ 뿐이다. ②와 ④ 는 tftp 전송이고, ⑤ 는 HTTP 로 넘어간 뒤라 데몬 교체의 영향권 밖이다.

§2. 요구사항 (확정) + 비목표
ID요구
R-1데몬을 dnsmasq 로 교체한다. 한 데몬이 두 모드를 낸다
R-2모드 PROXY — 사내 DHCP 가 IP · 우리는 부팅 옵션만. 입력 = 게스트 서브넷 · 부트 서버 IP
R-3모드 AUTHORITATIVE — 종전 입력(서브넷 · 범위 · 라우터 · DNS · 임대 · 도메인 · 부트 서버) 유지. max-lease 는 dnsmasq 에 없어 제거
R-4iPXE 2단 분기(ROM → ipxe.efi · iPXE → boot.ipxe)를 두 모드 모두 유지
R-5적용 파이프라인(스왑 · 게이트 · 재기동 · 검증 · 롤백 · 이력 · 락)은 유지 · 명령 셋만 교체
R-6임대 목록은 AUTHORITATIVE 에서만 의미 — dnsmasq 임대 파일 형식으로 파서 교체 · PROXY 는 안내
R-7대시보드 영역 표시 · chip 을 dnsmasq · 모드에 맞춘다
R-8런북 · 설정 키 · DDL · T3 를 함께 옮긴다
비 목표 (어디로 가는지 함께) :
  • TFTP 를 dnsmasq 내장 tftp 로 합치기 — 별도 슬라이스. 지금은 tftp-server 를 유지하고 자산 계약 TftpAsset 은 손대지 않는다.
  • PXE_GUEST_ALLOWED_CIDRS 를 화면 서브넷에서 자동 파생 — S19-2 가 이 값을 env 로 정했고, 보안 설정과 화면 값을 묶지 않는다. 런북에 사내 대역을 적는 것으로 갈음한다.
  • ipxe.efi 커스텀 빌드(임베디드 스크립트) — D-4 의 예비안이다. proxy 2단이 실기에서 안 되면 그때 꺼낸다.
  • legacy BIOS(x86PC) PXE · IPv6 · 다중 서브넷 · UEFI HTTP boot · BMC 가상 미디어 — 범위 밖. 지금 자산이 UEFI ipxe.efi 하나다.
  • HF17(PXE 보장 Once 회귀)과의 병행 — 패키지가 겹치지 않는다(pxeinfra 대 execution.engine · global.redfish). 충돌 파일 없음.

      §4. 도메인 모델 (SSOT)
      

        
4-1. DhcpMode 신규 enum — pxeinfra.enums

        

          
상수뜻requiresAddressing() · label()renderRange(config)

          
            
AUTHORITATIVE우리가 IP 까지 배정true · "자체 DHCP"dhcp-range=<start>,<end>,<netmask>,<lease>s + dhcp-authoritative + option 줄들

            
PROXY사내 DHCP 가 IP · 우리는 부팅 옵션만false · "proxyDHCP"dhcp-range=<network>,proxy,<netmask> + pxe-prompt · pxe-service

          
        

        
requiresAddressing() 이 이 슬라이스의 단일 SSOT 다. 화면의 필드 그룹 disabled 판정,
          PxeNetworkConfigValidator 의 모드별 필수 집합, 엔티티 invariant 셋이 모두 이 메서드 하나를 부른다.
          세 곳에 같은 조건을 복붙하면 그 순간부터 셋이 갈라지고, 화면은 막지 않는데 서버는 거절하거나 그 반대가 된다.


        
4-2. PxeNetworkConfig 변경

        

          
필드분류변경

          
            
dhcpMode신규@Enumerated(STRING) · NOT NULL

            
rangeStart · rangeEnd · routers · primaryDns수정nullable 로 — PROXY 에서 null

            
defaultLeaseSeconds · maxLeaseSeconds수정leaseSeconds 하나로(dnsmasq 는 한 값) · nullable

            
secondaryDns · domainName유지그대로(nullable)

            
subnetCidr · bootServerIp유지그대로 — 두 모드 공통 NOT NULL

            
appliedResult · appliedVersionId · appliedAt유지그대로

          
        

        
invariant(정적 팩토리 · updateDesired)는 셋으로 갈린다. 두 모드 공통 — 서브넷 · 부트 서버 필수.
          AUTHORITATIVE — 범위 · 라우터 · 주 DNS · 임대 필수, 범위가 서브넷 안, 시작 ≤ 끝.
          PROXY — 주소 배정 필드는 null 로 정규화한다(값이 와도 버린다). 마지막 항이 중요한 이유는 direct POST 다.
          화면은 필드를 잠가 두지만 잠긴 필드를 우회해 값을 실어 보낼 수는 있고, 그때 값이 남아 있으면 모드를 되돌렸을 때
          아무도 입력한 적 없는 범위가 되살아난다.


        
4-3. DDL — ddl/R16_pxe_network_config_dnsmasq.sql

        
ALTER TABLE pxe_network_config
  ADD COLUMN dhcp_mode VARCHAR(20) NOT NULL DEFAULT 'AUTHORITATIVE' AFTER id,
  MODIFY range_start VARCHAR(45) NULL,
  MODIFY range_end VARCHAR(45) NULL,
  MODIFY routers VARCHAR(45) NULL,
  MODIFY primary_dns VARCHAR(45) NULL,
  CHANGE default_lease_seconds lease_seconds BIGINT(20) NULL,
  DROP COLUMN max_lease_seconds;

        
기본값을 AUTHORITATIVE 로 둔 것은 기존 1행의 의미를 보존하기 위해서다 — 지금 들어 있는 값은 우리가 IP 까지 주던
          설정이므로 그대로 그 모드가 맞다. ddl/schema.sql 도 같이 동기한다.

실기 정정(2026-09-17): 실 UEFI ROM 은 client-arch 7 을 보내는데 dnsmasq 의 CSA 이름표는 RFC 4578 과 반대(x86-64_EFI=7 · BC_EFI=9)라 두 이름을 다 선언한다. proxy 모드에서 dnsmasq 는 dhcp-boot 를 쓰지 않으므로 iPXE 둘째 단도 pxe-service 다. 부팅 파일 교환은 UDP 4011 이라 방화벽에 4011/udp 를 연다(런북 §3-1).

결정성 규율은 종전 렌더러와 같다 — 머리말은 정적, 줄 순서는 리터럴로 고정, 마지막에 trailing newline,
          선택 줄(보조 DNS · 도메인)의 유무 조합은 분기로 명시한다. 같은 입력이 같은 바이트를 내야 드리프트 비교와 골든 테스트가 성립한다.
          빈 조각(renderEmpty)은 머리말 + # (구성 없음 — 유효한 빈 조각) 을 유지한다(복원 경로 D-8).
