§1. 현재 상태 (진단)

S8-4 가 남긴 것 — 게스트 서버 목록만 기간 줄을 가졌다

S8-4 CP6 수정으로 게스트 서버 목록에 '등록 시각' 기간 줄과 기본 범위(1 년 전 ~ 오늘)가 생겼다.

자리구현

둘 다 BaseTimeEntity.createdAt 을 가진다. 자원 관리 6 화면은 S8-3 결정(Q2)으로 기간 조건 예외다.

발견한 결함 (S8-4 에서 생김) : 게스트 서버 목록에서 다른 조건 없이 기본 범위 때문에 결과가 0 이면, 1 년보다 오래된 서버가 있어도 "등록된 게스트 서버가 없습니다" 라고 안내한다. server-list.html 빈 상태 갈래가 filtered 만 보고, 기본 범위는 조건이 아니므로 filtered = false 이기 때문이다. 세팅 정의서 · 서버 그룹에 기본 범위를 넣으면 같은 문제가 그대로 생긴다.

흐름

GET /provisioning/{setting|server-group|server}?…
  → 컨트롤러: ListDateRangeDefaults.today()            (Clock)
  → 조건 record.range()  → DateRange
  → DateRange.withDefault(today)                         (비운 끝 = 기본값)
  → 조회: Specification
        createdAt ≥ from 0시   (startInclusive)
        createdAt <  to+1일 0시 (endExclusive)
  → 결과 0 이고 조건 없음(isFiltered(today) = false)?
        예 → 기간만 뺀 조회 (빈 상태 ② 판정)

빈 상태 판정

서비스가 기간 밖에서 가장 오래된 생성 날짜를 돌려주는 메서드 하나를 둔다(예: findOldestCreatedDate() → Optional<LocalDate> · 기간 외 다른 조건은 없음 상태에서만 부름). 값이 있으면 빈 상태 ②(기본 범위 때문에 0 건)이고 그 날짜가 [기간 넓히기] 링크의 시작일이 된다(D6). 값이 없으면 ③(아예 없음). 별도의 건수 · 존재 확인 메서드는 두지 않는다 — 한 번의 조회로 판정과 링크 값이 함께 나온다.

세션 판정(CP1 검수) — 전사 단계에서 D6 와 판정 메서드의 반환형이 어긋난 것을 이렇게 맞췄다. 빈 상태 ① 의 설명 문구 "초기화하면 전체 목록이 보입니다" 는 S8-5 뒤 사실과 달라지므로(초기화 = 기본 범위) "초기화하면 기본 범위의 목록이 보입니다" 로 messages 에서 바꾼다. 서버 그룹의 ③ 문구는 기존 "만들어진 그룹이 없습니다." 를 유지한다. 빠른 칩의 날짜 계산은 최근 N일 = 오늘 − N일 ~ 오늘, 올해 = 1월 1일 ~ 오늘로 확정한다(Q3 채택 시).

§8. 예상 부산물 / 주의 / 결정 사항

주의

  1. S8-4 의 게스트 서버 빈 상태 결함을 여기서 함께 고친다 (D5).
  2. 기본값은 URL 에 안 실리므로 날짜가 바뀌면 같은 주소가 새 범위다 — 실시간 갱신(게스트 서버)도 같은 규칙.
  3. 서버 그룹 목록은 정렬 기본이 생성 최신순이라 기본 범위와 잘 맞는다.
  4. 세팅 정의서는 정렬 기본이 번호 순 — 오래된 정의서가 기본으로 숨는 것이 운영상 괜찮은지 (Q1).
