§0. 한눈에 · 재설계 동기
OS 를 배포판과 메이저 단위로 고정한다. 등록 화면에는 지원하는 상수만 보이고, 메이저 능력은 RhelRelease(R8 · R9 · R10)와 WindowsServerRelease(W2025) 한 곳에 모인다. 지원 밖 기존 행은 옛 이름 그대로 '미지원' 상수로 읽히며, 배포 직후 정리하고 S23-1-a 로 미지원 상수를 지운다.

지금

OSName  = UBUNTU, CENTOS, ROCKY_LINUX,
          WINDOWS, WINDOWS_SERVER   (배포판만)
RhelRelease = ROCKY_8 · 9 · 10
          (OSName.ROCKY_LINUX, major)
등록 POST osName=ROCKY_LINUX
          &rhelRelease=ROCKY_9&osVersion=9.6
지원 목록 = MVP_OS_NAMES · SUPPORTED ·
          verifyRelease 의 ROCKY_LINUX 조건

바뀐 뒤

OSName  = 배포판 + 메이저
          (지원 8 + 미지원 4, status)
RhelRelease = R8 · R9 · R10 + Set<OSName>
WindowsServerRelease = W2025 (build 26100)
등록 POST osName=ROCKY_LINUX_9&osVersion=9.6
지원 판정 = registrable() · extractable()
          (세 목록은 능력 메서드로 흡수)

근거: 토론 아카이브 discussion/26-11-17_20-39-03_S23-support-catalog_discussion.md, 패치 항목 "OSFamily 에 따른 OSName 의 메이저버전 상세화".

§4. 도메인 모델 (SSOT) · DB 변화

OSName (D-1) : 선언 순서 = 목록 정렬 순서 = DB ENUM 순서

상수displayNamemajorfamilystatuslabel()registrableextractable
 
registrable()       = status == SUPPORTED
label()             = displayName + (major != null ? " " + major : "")   // "Rocky Linux 9", "Windows Server 2025"
extractable()       = family == RHEL_BASED && registrable()
registrableValues() = 선언 순서의 지원 상수
OSCatalogStatus     = SUPPORTED, LEGACY        // 새 enum, management/os/enums
displayName 의 뜻(배포판 이름)은 그대로라 22 곳 사용처가 바뀌지 않는다. OSMetadata.displayName() = displayName + " " + osVersion → "Rocky Linux 9.6" 유지(휴지통 이름 직접 입력 확인, UE b-4-2 실패 문구가 이 형식에 기댄다).

RhelRelease (D-2) : 메이저 단위 + Set<OSName>

구분내용
상수R8(8, {ROCKY_LINUX_8, RHEL_8}), R9(9, {ROCKY_LINUX_9, RHEL_9}), R10(10, {ROCKY_LINUX_10, RHEL_10})
유지 (UE 계약)major(), supportsRootSshFlag()(major >= 10), covers(version), of(OSName, String version), majorOf(version)(정적)
추가of(OSName) = 속한 release, osNames()
제거osName()(→ osNames), displayName()(→ OSName.label), supportedMajors(OSName)(호출처 둘을 OSName 기준으로)
불변식 테스트RHEL_BASED 이고 registrable 한 OSName 은 정확히 한 release 에 속하고 OSName.major == release.major

of(OSName, version) = "그 OSName 의 메이저에 version 이 속하면 그 release, 아니면 empty".

WindowsServerRelease (D-3) : 새 enum, management/os/enums

W2025(major 2025, build 26100, {WINDOWS_SERVER_2025})
of(OSName)
matchesBuild(String build)   // "10.0.26100.1742" 의 세 번째 마디가 26100 인가

  'WINDOWS_SERVER_2025','UBUNTU','ROCKY_LINUX','CENTOS','WINDOWS','WINDOWS_SERVER') NOT NULL;
ALTER TABLE subprogram MODIFY COLUMN os_name ENUM(
  'ROCKY_LINUX_8','ROCKY_LINUX_9','ROCKY_LINUX_10','RHEL_8','RHEL_9','RHEL_10',
  'WINDOWS_SERVER_2025','UBUNTU','ROCKY_LINUX','CENTOS','WINDOWS','WINDOWS_SERVER') DEFAULT NULL;

-- 2. 행 이전 (os_metadata). 다시 적용해도 조건에 맞는 행이 없어 안전하다.
UPDATE os_metadata
   SET os_name = CONCAT('ROCKY_LINUX_', SUBSTRING_INDEX(os_version, '.', 1))
 WHERE os_name = 'ROCKY_LINUX'
   AND SUBSTRING_INDEX(os_version, '.', 1) IN ('8', '9', '10');
UPDATE os_metadata
   SET os_name = 'WINDOWS_SERVER_2025'
 WHERE os_name = 'WINDOWS_SERVER' AND os_version = '2025';

-- 3. 행 이전 (subprogram). 드라이버는 버전이 없고 지금 지원은 2025 하나라 전부.
UPDATE subprogram
   SET os_name = 'WINDOWS_SERVER_2025'
 WHERE os_name = 'WINDOWS_SERVER';

잔존 책임 : 배포 직후 해소 (D-8, 사용자 지시)

배포 전 점검 SQL ① + ② (os_metadata 와 subprogram 의 미지원 유지 합계) ├─ 합계 = 0 (모든 환경) ──▶ S23-1 + S23-1-a 같은 배포 (잔존 0) └─ 합계 > 0 ──▶ S23-1 배포 ──▶ 운영자가 화면에서 그 OS · ISO · 드라이버를 휴지통 → 영구 삭제 (참조 정의서는 사용자 판단) ──▶ 점검 SQL ① + ② 합계 0 확인 ──▶ 미리 만들어 둔 S23-1-a 바로 병합 · 배포

판정 기준에 subprogram 을 넣는 이유: S23-1-a 의 가드 DDL 이 두 테이블을 모두 검사하므로, 판정 기준이 os_metadata 만 세면 '같은 배포' 로 판정하고도 가드에서 멈출 수 있다. 미지원 상수를 S23-1 에 두는 이유: 이 정리를 앱 화면(파일 · 마커 처리 포함)으로 하기 위해서다. 둘 다 docs/deploy/pending/S23-1.md 에 등록(점검 SQL 원문, DDL 두 파일, 판단 흐름).

-- ① os_metadata 를 (os_name, 메이저, is_deleted)별로 세고 분류
SELECT os_name,
       SUBSTRING_INDEX(os_version, '.', 1) AS major,
       is_deleted,
       CASE
         WHEN os_name = 'ROCKY_LINUX' AND SUBSTRING_INDEX(os_version, '.', 1) IN ('8', '9', '10') THEN '이전'
         WHEN os_name = 'WINDOWS_SERVER' AND os_version = '2025' THEN '이전'
         WHEN os_name IN ('ROCKY_LINUX', 'CENTOS', 'WINDOWS', 'WINDOWS_SERVER') THEN '미지원 유지'
         ELSE '그대로'
       END AS bucket,
       COUNT(*) AS cnt
  FROM os_metadata
 GROUP BY os_name, major, is_deleted, bucket
 ORDER BY os_name, major, is_deleted;

-- ② subprogram.os_name 별 수
SELECT os_name, COUNT(*) AS cnt FROM subprogram GROUP BY os_name ORDER BY os_name;

-- ③ 미지원으로 남을 OS 를 참조하는 ISO 와 정의서 단계 수
WITH legacy_os AS (
  SELECT id FROM os_metadata
   WHERE (os_name = 'ROCKY_LINUX' AND SUBSTRING_INDEX(os_version, '.', 1) NOT IN ('8', '9', '10'))
      OR (os_name = 'WINDOWS_SERVER' AND os_version <> '2025')
      OR os_name IN ('CENTOS', 'WINDOWS')
)
SELECT 'iso' AS ref, COUNT(*) AS cnt FROM iso WHERE os_metadata_id IN (SELECT id FROM legacy_os)
UNION ALL
SELECT 'setting_process', COUNT(*) FROM setting_process
 WHERE process_type = 'OS_INSTALLATION'
   AND JSON_VALUE(payload_json, '$.osMetadataId') IN (SELECT id FROM legacy_os);
-- ddl/S23-1-a_os_catalog_legacy_drop.sql
-- ENUM 에서 값을 지우면 그 값의 행이 오류 없이 빈 문자열이 되므로 가드가 먼저다.
DELIMITER //
BEGIN NOT ATOMIC
  IF EXISTS (SELECT 1 FROM os_metadata WHERE os_name IN ('ROCKY_LINUX', 'CENTOS', 'WINDOWS', 'WINDOWS_SERVER'))
     OR EXISTS (SELECT 1 FROM subprogram WHERE os_name IN ('ROCKY_LINUX', 'CENTOS', 'WINDOWS', 'WINDOWS_SERVER')) THEN
    SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'S23-1-a guard: legacy os_name rows remain';
  END IF;
END //
DELIMITER ;
ALTER TABLE os_metadata MODIFY COLUMN os_name ENUM(
  'ROCKY_LINUX_8','ROCKY_LINUX_9','ROCKY_LINUX_10','RHEL_8','RHEL_9','RHEL_10',
  'WINDOWS_SERVER_2025','UBUNTU') NOT NULL;
ALTER TABLE subprogram MODIFY COLUMN os_name ENUM(
  'ROCKY_LINUX_8','ROCKY_LINUX_9','ROCKY_LINUX_10','RHEL_8','RHEL_9','RHEL_10',
  'WINDOWS_SERVER_2025','UBUNTU') DEFAULT NULL;
