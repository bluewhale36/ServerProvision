§1. 배경
한 줄 요약 : Ubuntu 정의서 하나가 정의서 고르기 창 전체를 500 으로 막고(O-2), 폼에 필수 호스트명 칸이 없어 Ubuntu 정의서를 화면으로 저장할 수 없다(O-1). 카드의 리눅스 공통 갈래에서 RHEL 전용 행을 RHEL 조각으로 옮기고, 남아 있던 Debian 계열 폼 조각을 폼에 다시 붙인다.

출처: E4-1-b-4-2 CP5 에서 UE 세션이 범위 밖 결함으로 발견해 앵커로 이관했다(O-1 · O-2). 사용자 지시(2026-11-19)로 HF 로 묶어 앵커가 긴급 진행한다.

식별자심각도증상영향
O-2높음활성 Ubuntu 정의서가 있으면 정의서 고르기 창 500그 창을 쓰는 모든 서버 할당 · 그룹 일괄 할당 막힘
O-1중간정의서 폼에 호스트명 칸 없음지금은 드러나지 않음: Ubuntu 는 설치 대상 정책(E4-1-b-2 비목표)으로 잠겨 폼에서 고를 수 없다. 차단을 푸는 순간 호스트명 필수 거절로 저장 불가(CP5 F-1 로 정정)
§2. 실측 (원인)

2-1. O-2 정의서 고르기 창 500

OS 설치 카드 조각 fragments/provisioning/setting-process-cards.html 을 세 화면이 함께 쓴다.

화면템플릿
정의서 상세provisioning/setting-detail.html
정의서 고르기 창fragments/provisioning/definition-picker.html
그룹 정의서 고르기 창fragments/provisioning/group-definition-picker.html

카드의 계열 분기 th:switch="${process.osFamily().name()}" 는 'WINDOWS' 와 *(그 밖) 두 갈래뿐이다.

setting-process-cards.html :: processCards (OS_INSTALLATION) └── th:switch osFamily().name() ├── 'WINDOWS' → detail-windows :: body └── * (리눅스 공통) ├── 공통 표 : 대상 OS · 설치 ISO · 타임존 · root 비밀번호 ← process.rootPassword ├── 파티션 표 · 사용자 표 └── th:switch osFamily().name() ├── 'RHEL_BASED' → detail-rhel :: body └── 'DEBIAN_BASED' → detail-debian :: body
  • 공통 표의 root 비밀번호 행이 process.rootPassword 를 읽는다. 이 값은 RHELInstallationRequest 에만 있고 UbuntuInstallationRequest 에는 없다.
  • 없는 이유: 사용자 확정(2026-07-05). Ubuntu autoinstall 은 root 잠금이 기본이라 설치 계약에 root 비밀번호 개념이 없다. LinuxInstallationRequest Javadoc 에 기록돼 있다.
  • Thymeleaf 식(SpEL)은 없는 프로퍼티를 만나면 예외를 던지고 렌더 전체가 끝난다. 고르기 창은 정의서 여러 개를 한 화면에 그리므로 Ubuntu 정의서 하나가 창 전체를 500 으로 만든다.
  • Java 컴파일러는 템플릿 속 프로퍼티 이름을 검사하지 않는다. 테스트가 Ubuntu 정의서로 화면을 그리지 않는 한 드러나지 않았다.

2-2. O-1 폼에 호스트명 칸 없음

  • UbuntuInstallationRequest.hostname 은 @NotBlank + RFC 1123 형식 검증이 붙은 필수 값이다.
  • Debian 계열 폼 조각 fragments/provisioning/setting/os-installation/debian-based.html :: form(호스트명 · 추가 패키지 칸)은 저장소에 남아 있으나 정의서 폼 provisioning/setting-new.html 어디에서도 쓰지 않는다.
  • 경위: R11(커밋 056c861, OS 섹션 식별 전용 축소)에서 폼이 빠졌고, E4-1-b-2 복원 때 rhel-based 조각만 다시 붙였다.
  • 폼 스크립트 static/provisioning/setting-form.js 도 OS 설치 요청을 만들 때(OS_INSTALLATION 조립) 리눅스 공통(시간대 · 파티션 · 사용자)과 RHEL 고유값만 싣는다. Ubuntu 의 hostname · packages 는 싣지 않는다. 수정 폼 다시 채우기(prefill)도 같다.
  • 계열 패널 표시 전환(osFamilyPanes(), data-os-family 로 토글)은 이미 Debian 패널을 다룰 수 있게 되어 있다.
  • 단, Ubuntu 는 설치 대상 정책(E4-1-b-2 비목표, DebianInstallationFamilyInspector.installBlockReason)으로 폼 선택지와 저장 경로가 모두 잠겨 있어 지금은 이 결함이 드러나지 않는다(CP5 F-1 로 정정).
§3. 결론 (고칠 것)

3-1. 결정 (채택 + 비채택 + 사유)

결정채택비채택 대안과 탈락 사유

D2 공통 갈래 이름 * 를 리눅스 공통으로 유지(계열 전용 값이 하나도 없게 됨) 'RHEL_BASED' · 'DEBIAN_BASED' 를 바깥 분기에 나열: 공통 표 복제가 필요해 D1 ① 과 같은 문제

D4 스크립트 OS_INSTALLATION 조립에 family === 'DEBIAN_BASED' 일 때 hostname(trim) · packages(콤마 분리, 기존 splitCsv 재사용) 추가. 수정 폼 다시 채우기에도 같은 두 값 별도 Ubuntu 전용 조립 함수: RHEL 분기와 같은 자리에 두는 편이 읽기 쉽고 줄 수가 적음
D5 조각 문구 정비 화면 문구 규약(DESIGN.md 7절)에 맞춤
  • "autoinstall identity.hostname 필드로 매핑됩니다" 같은 기술 설명 제거
  • 추가 패키지 안내: "콤마로 구분해 입력합니다. 비워 두면 기본 패키지만 설치합니다." 수준
  • data-error-field 는 다른 칸처럼 n-form-group 에 단다(지금도 메시지는 칸 옆에 뜬다. 다른 칸과 맞추는 정렬)
  • 상세 조각 detail-debian.html: 호스트명이 빈 옛 저장본은 "미설정 (기본값: ubuntu-server)" 대신 '-'(호스트명은 이제 필수), 패키지 빈 값은 "미지정" 으로 폼 안내와 말을 맞춤, 라벨 "추가 설치 패키지"
  • 일반 사용자 칸 안내(setting-new.html): "root 비밀번호가 없으면 한 명 이상" 은 RHEL 기준. Ubuntu 는 사용자 1명 이상이 늘 필수라 두 계열 모두 맞는 문장으로 고침
  • 카드 조각 머리 주석의 사용 화면 목록에 그룹 정의서 고르기 창 추가(코드 주석)

D6 호스트명 비움 · 형식 오류 서버 @Valid 400 이 칸 옆 메시지로 뜨는 기존 경로 클라이언트 사전 검사 추가: 서버 검증 메시지와 이중 SSOT(Single Source of Truth) 가 됨

§4. 범위 밖 · 남는 일
범위 밖 :
  • Ubuntu 설치 실행기(autoinstall 생성 · 서빙)는 이 HF 범위가 아니다. 리눅스 설치는 E4-1-b(RHEL 계열)가 먼저이고 Ubuntu 는 그다음 슬라이스.
  • Ubuntu 정의서는 저장 · 표시가 되지만 실제 설치는 아직 안 된다. 실행 준비도에서 어떻게 막을지는 Ubuntu 실행 슬라이스에서 정한다.
  • OS 후처리 단계의 Ubuntu 계약은 E4-1-b-7 CP1.
