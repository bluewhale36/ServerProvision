§1. 범위와 진단

S22 우산 plan 이 정한 첫 슬라이스다. 흑연 팔레트, 한글과 라틴을 한 벌로 그리는 글꼴, 아이콘 한 세트, 문장형 라벨, 상자 없는 식별자로 전 화면의 시각 어휘를 바꾼다. 아래 수치는 refine 브랜치에서 실제로 바꾸고 샌드박스(포트 7797, 11-08 r17 덤프를 복제한 DB 3360)에서 확인한 결과다.

표식현행 실측실험 결과
D2 기본값 팔레트 · 글꼴Tailwind slate 값, Inter(라틴) + 시스템 글꼴(한글) 섞임흑연 토큰, IBM Plex Sans KR + IBM Plex Mono
토큰 규약 위반:root 밖 색 리터럴 117 곳(hex 64 + rgba 53, 주석 · reset.css 제외), 정의 안 된 토큰 fallback 4 종0 곳, fallback 은 정의된 토큰으로
D5 대문자 소형 라벨text-transform: uppercase 9 곳0 곳(문장형, 자간 제거)
D6 화살표 글리프119 회 = 주석 69 · 링크와 버튼 안 36 · 그 밖 본문 14실험은 대표 3 곳, CP2 에서 링크와 버튼 36 을 아이콘으로
D7 식별자 상자전역 code 회색 상자, SMBIOS UUID 칩상자 0, 고정폭 글자만
SB 짙은 사이드바slate 남색 #16202e, slate 글자 3 색 리터럴유지(우산 K6), 흑연 짙은 면 #1f1f1e + 글자 토큰 3

우산 plan 의 'hex 78 곳' 은 주석 속 예시 값까지 센 수였다. 주석을 빼고 rgba 를 함께 세면 117 곳이고, 이번 실험은 117 곳을 모두 정리했다. 무대 판정 패널의 현행 값은 109 다. 무대 5 화면이 싣는 CSS 10 파일만 세기 때문이다(나머지 8 곳은 bios-setting.css · os-page.css · trash-list.css 에 있다).

D1 판 구조 · D3 · D4 · D8 은 S22-2, 로딩은 S22-3 소관이라 이 슬라이스의 판정 패널에 넣지 않는다.

요구

  • R1 색: 흑연 한 계열 + 강조 하나 + 상태색 5(green · teal · orange · yellow · red, 독립 유지). 규칙 본문은 토큰 또는 color-mix(토큰) 만 쓴다.
  • R2 글꼴: IBM Plex Sans KR(400 · 500 · 600) + IBM Plex Mono(400 · 500). 700 요청은 600 이 그린다.
  • R3 라벨: 대문자 변환과 자간을 쓰지 않는다.
  • R4 식별자: UUID · IP · 경로 · 시리얼은 상자 없이 고정폭 글자.
  • R5 아이콘: Phosphor regular 한 세트, 조각 fragments/icon :: icon(name) 하나로. 링크와 버튼의 화살표 글리프를 대신한다.
  • R6 기능 무변경. 단 정적 자산 경로 /icons/** 를 기존 /fonts/** 와 같은 허용 목록에 더한다(아래 K7).
비목표: 판 정돈 · 정보 절제는 S22-2, 로딩 뼈대는 S22-3, 문구 표현은 S16-2. 로그인 · 가입 화면은 토큰과 글꼴만 받는다.
🎬 무대 · 현행과 제안
화면
보기 폭 글꼴 요소 검사
시나리오
시나리오를 누르거나 위 단추로 화면 · 보기 · 폭 · 글꼴을 바꿔 본다. 와이프에서는 손잡이로 경계를 옮긴다.

판정은 무대에 그려진 화면과 무대 CSS 텍스트를 그 자리에서 잰 값이다. D6 은 무대 5 화면에 있는 링크 화살표 3 곳을 실험에서 바꿔 모두 0 이다. 나머지 33 곳은 다른 화면에 있으며 CP2 에서 바꾼다.

요소 검사

제품 CSS 의 media query 는 무대 폭이 아니라 문서 창 폭을 본다. 그래서 무대 안 화면은 넓은 창에서 1440 기준의 규칙으로 그려지고, 1024 를 골라도 max-width: 1024px 규칙은 켜지지 않는다.
