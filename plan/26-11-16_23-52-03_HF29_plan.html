§1. 배경
  • docs 세션이 DOC-7 사용자 매뉴얼을 쓰며 코드와 대조해 MA8(사용자 관리, PR #102 · dev 997ce9b)에서 결함 후보 다섯을 찾았다(C-26). 원자료: ServerProvision-docs sbx-docs/facts/ma8-r172-facts.md '코드 결함 후보' 3~6 · verify-account-raid.md A2.
  • 그중 둘은 MA8 CP5 에서 '관찰'로만 기록하고 넘긴 것(O-3 403 사유 없음 · O-5 404 id 노출)이다. 매뉴얼에 현재 동작이 경고로 들어가 있어, 고치면 커밋을 docs 세션에 알린다.
§2. 실측 (2026-11-16, 샌드박스 sbx-ma8 · MA8 jar · Playwright)
ID지적조작관측판정
M1 마지막 최고 관리자 보호 문구가 나타날 수 없음 코드 경로 대조(UserManagementService.run · ensureSuperAdminRemains · UserAction) 행위자는 잠근 활성 최고 관리자 목록 안에 있어야 진행되고, 권한 변경 · 비활성화 · 비밀번호 지정은 자기 자신을 대상으로 못 한다 → '대상을 뺀 활성 최고 관리자 수' 에 행위자가 늘 들어가 1 이상. 동시 상호 강등도 뒤 요청은 행위자 재확인에서 먼저 거절. 문구 "최고 관리자가 한 명도 남지 않게 되어 처리하지 않았습니다." 는 도달 불가 사실(설계 D-9 대로) · 매뉴얼 서술이 틀림
M2 초기 비밀번호 폼 409 가 공통 오류 화면으로 두 브라우저: 최고 관리자 A 가 user.park 상세를 연 채, B 가 user.park 비활성화 → A 가 초기 비밀번호 제출 /users/3/password 에서 공통 오류 화면 "요청을 처리할 수 없습니다 / 다른 작업과 충돌했습니다 (409) / 비활성화된 계정입니다. 먼저 활성화하십시오." — 상세 화면을 잃고 이전 페이지로 돌아가야 함 결함 확정
M3 같은 개념의 빈칸 문구 두 벌 사용자 추가에서 비밀번호 칸을 비워 제출 "비밀번호를 입력하십시오." · "비밀번호를 한 번 더 입력하십시오." — 상세의 초기 비밀번호 폼은 "초기 비밀번호를 입력하십시오." · "초기 비밀번호를 한 번 더 입력하십시오." (SignUpRequest vs InitialPasswordRequest) 결함 확정
M4 404 문구 id 노출 /users/9999 "페이지를 찾을 수 없습니다 (404) / 사용자를 찾을 수 없습니다. id=9999" 결함 확정
M5 403 화면 사유 없음 관리자 admin.lee 가 /users "접근 권한이 없습니다 (403)" 만 · 사이드바 활성 표시 'OS 버전'(error.html 이 navbar('os-metadata')) 결함 확정
§3. 결론 (원인)
ID원인
M1결함이 아니라 설계상 도달 불가인 마지막 확인. 문제는 매뉴얼이 그것을 사용자가 볼 수 있는 문구로 적은 것.
M2UserManagementController.assignPassword 는 네이티브 제출(재렌더) 폼인데 FieldBoundBadRequestException 만 잡고 UserManagementBlockedException(409)은 advice 로 흘려보낸다 → HTML 경로의 공통 오류 화면.
M3빈칸 · 불일치 문구가 두 DTO 에 따로 리터럴로 있다(SSOT 없음).
M4UserNotFoundException 메시지가 사용자 문구와 진단 정보(id)를 겸한다.
M5웹 체인 403 은 Spring Security 기본 거절 → /error → error.html 로 가는데, 거절 결정에 사유가 실리지 않고 ProvisionErrorAttributes 도 메시지를 채우지 않는다. error.html 의 navbar 인자가 'os-metadata' 고정.
§4. 수정 방향 (결정과 탈락 대안)
#채택비채택사유
F1(M1) 코드 동작 유지 + 주석으로 "구조상 도달하지 않는 마지막 확인" 명시 · docs 에 올바른 매뉴얼 서술 전달("본인 계정은 강등 · 비활성화할 수 없어 최고 관리자는 항상 한 명 이상 남습니다", 동시 처리 문구 = "권한이 바뀌어 이 작업을 할 수 없습니다. 사용자 관리는 최고 관리자만 할 수 있습니다.") (b) 확인 삭제 · (c) IllegalStateException(500)으로 격하 (b) 앞으로 자기 대상 금지가 풀리는 동작이 생기면 마지막 방어선이 사라진다 (c) 도달한다면 사용자에게 500 보다 이유 있는 409 가 낫다
F2(M2) 컨트롤러가 UserManagementBlockedException 도 받아 409 + 상세 재렌더: 최신 상태로 다시 그리고(예: 비활성이 되었으면 지정 버튼 disabled), 초기 비밀번호 카드 머리의 실패 안내에 그 사유를 싣는다(기존 passwordFailed 안내 자리 재사용, 사유 문장 표시) (b) PRG — 상세로 redirect + flash 오류 · (c) 그대로 두고 매뉴얼에 적기 (b) 이 폼만 실패를 flash 로 돌리면 같은 폼의 400 재렌더와 경로가 둘이 된다 (c) 상세 화면을 잃는 UX 결함을 남긴다. 선례: SignupSubmission 이 FieldBound* 를 받아 재렌더
F3(M3) 빈칸 · 재입력 빈칸 · 불일치 문구를 PasswordRule 상수로 올려 SignUpRequest · InitialPasswordRequest · PasswordMismatchException(서비스 안전망의 불일치 문구) · 제출 전 확인(data 속성)이 같은 문장을 쓴다. PasswordChangeRequest('새 비밀번호' 라벨의 본인 변경 화면)는 다른 개념이라 범위 밖. 문장은 라벨과 무관한 공통형 "비밀번호를 입력하십시오." · "비밀번호를 한 번 더 입력하십시오." · "비밀번호가 일치하지 않습니다." (b) '초기 비밀번호…' 로 통일 · (c) 경로별 문구 (b) 최초 관리자 등록 폼의 라벨은 '비밀번호' 라 맞지 않는다 (c) 두 벌이 다시 생긴다
F4(M4) UserNotFoundException 메시지를 사용자 문구 "사용자를 찾을 수 없습니다. 목록에서 다시 고르십시오." 로. id 는 메시지에 넣지 않는다 404 공통 화면에서 id 를 가리는 전역 처리 다른 자원의 NotFound 관례까지 바꾸는 일이라 범위 밖(이 슬라이스는 사용자 관리만)
F5(M5) 거절 결정에 사유를 싣는다 — ReasonedDenial(AuthorizationDecision 하위, 사유 문장 보유). /users/** 는 SuperAdminOnlyPolicy(사유 "사용자 관리는 최고 관리자만 할 수 있습니다."), SignupAccessPolicy 는 닫혔을 때 사유 "최초 관리자 등록은 관리자 계정이 하나도 없을 때만 열립니다. 계정이 필요하면 최고 관리자에게 요청하십시오." 웹 체인에 ReasonedAccessDeniedHandler(AuthorizationDeniedException 의 결과가 ReasonedDenial 이면 요청 속성에 사유를 싣고 기본 403 처리에 위임) · ProvisionErrorAttributes 가 그 속성을 message 로 채움 → error.html 이 이미 그리는 자리에 사유가 나온다. error.html 의 navbar 인자를 빈 값으로(활성 메뉴 없음) (b) 경로 → 사유 표를 핸들러에 둠 · (c) /users 전용 403 화면 (b) 경로가 늘 때마다 표가 자란다(분기 증식 금지) — 사유는 그 거절을 내린 정책이 소유한다 (c) 화면이 하나 더 생긴다. 선례: 게스트 체인 ProvisioningLanPolicy.Denied + GuestAccessDeniedHandler
범위 밖 :
  • 409 안내를 닫은 뒤 화면 자동 갱신(MA8 O-4, 전역 form-submit 동작)
  • 다른 자원의 404 id 노출 관례
  • 비활성 계정 재로그인 문구(계정 열거 방지 방침)
조율 : error.html · ProvisionErrorAttributes · SecurityConfig 는 앵커 HF28(layout.html · CurrentUserModelAdvice · MustChangePasswordWebConfig)과 파일이 겹치지 않는다. SecurityConfig 는 HF28 이 건드리는지 병합 전에 앵커와 확인한다.
