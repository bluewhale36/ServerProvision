§1. 현재 상태 (실측)

세팅 정의서를 비슷한 내용으로 하나 더 만들려면 지금은 작성 화면에서 처음부터 다시 입력해야 합니다. 이 슬라이스는 정의서 상세 화면에 [복제] 버튼을 두어, 정의서와 모든 단계를 그대로 복사한 새 정의서를 만들고 곧바로 그 수정 화면으로 보내 줍니다. 비밀번호는 저장 때 해시로만 남아 있으므로 복사본에도 해시를 그대로 옮기고, 사용자는 비밀번호를 다시 넣지 않습니다. DB 구조는 바뀌지 않습니다.

자리지금
정의서 엔티티 SettingDefinition이름(128 자) · 삭제 · 활성 · 사용 중단 플래그 + 단계 SettingProcess 목록(cascade ALL · orphanRemoval)
단계 SettingProcess다형 payload(JSON 컬럼, 계약 원문) + 파생 판별자 · BIOS 템플릿 참조 파생 행. 생성자 new SettingProcess(payload) 가 파생값을 만듦
비밀번호저장 때 해시, payload 안 passwordHash 로만 남음(E4-1-b-2 D-18). 평문 저장 없음
이름 유일성활성 정의서끼리만(existsByNameAndIsDeletedFalse, U3-2-b DEC-B). 삭제된 정의서 이름은 재사용 가능
생성 경로 JpaSettingCommandService.create이름 중복 → 저장된 비밀값 거부 → 참조 자원 검증 → 해시 → 저장
상세 화면 동작 줄삭제 안 됨: [수정] · [삭제] / 삭제됨: [복구] · [영구 삭제] (setting-detail.html n-form-actions)
생명주기 컨트롤러 SettingLifecycleControllerSSR form-POST /{id}/delete · restore · purge · toggle · deprecate · undeprecate → 상세로 redirect(PRG)
복제없음. 패치 내역 '세팅 정의서 복제 기능'(낮음, 본문 없음)
flash 알림redirectAttributes.addFlashAttribute("flashMessage", …) 선례(GuestServerController · GuestServerGroupController)
§2. 요구사항 (확정) + 비목표
ID요구
R1정의서 상세(삭제 안 된 정의서) 동작 줄에 [복제] 버튼. [수정] 다음 자리
R2[복제] → 서버가 정의서와 모든 단계를 그대로 복사해 새 정의서 저장 → 새 정의서 수정 화면으로 이동 + flash "정의서를 복제했습니다."
R3새 이름 = <원본 이름> 복사본. 활성 정의서에 같은 이름이 있으면 <원본 이름> 복사본 2, … 3 처럼 빈 번호. 128 자를 넘으면 원본 이름 쪽을 잘라 맞춤
R4비밀번호는 해시 그대로 복사(다시 입력하지 않음)
R5새 정의서는 활성 · 사용 중단 아님 · 삭제 안 됨으로 시작(원본 상태를 물려받지 않음)
R6삭제된 정의서는 복제하지 않음. 화면에 버튼 없음, direct POST 는 404(findByIdAndIsDeletedFalse 가 없음 → SettingNotFoundException)
R7원본은 바뀌지 않음. 할당 스냅숏(U3)은 정의서와 별개라 영향 없음
비 목표 : 여러 정의서 한꺼번에 복제 · 내보내기 · 가져오기 · 복제 전 이름 입력 창(이름은 수정 화면에서 바꿉니다).
🎬 미리보기 : 라이브 데모

정의서 상세 화면 모형입니다. [복제] 를 누르면 서버와 같은 이름 규칙(§4 SettingCopyName)으로 새 이름이 정해지고, 수정 화면 모형으로 넘어가며 flash 안내가 보입니다. 맨 아래 "활성 정의서 이름 목록" 에 이름을 더하거나 지우면 다음 복제 이름이 바로 달라집니다. 예를 들어 프리셋 3 에서 '복사본 2' 를 지우면 빈 번호 2 가 다시 쓰입니다.

(c) 시각 꼬리		(b) 작은 기능에 창 하나가 더 생김. 수정 화면에서 바로 바꿀 수 있음
(c) 길고 읽기 어려움
