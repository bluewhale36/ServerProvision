§1. 현재 상태(진단)
v2 는 11-08 판정을 반영했다. 팔레트는 흑연, 판 구조와 짙은 사이드바는 유지, 로딩은 측정 뼈대, 상태색 5 는 독립, 슬라이스 plan 은 데모 중심 형식이다. 진단표(표 1)는 그대로 둔다. 진단은 사실이고, 그중 일부를 남기기로 한 것은 결정(§8 표 5)이다.

사용자 지시는 "AI 가 만든 티가 나지 않게 디자인을 바꾼다" 이다. 판단 도구는 둘이다. stageshow 스킬(v1.1.1)은 가짜 제품 화면을 만드는 스킬이지만 그 정지 화면 규칙(references/craft.md)과 화면 검사 스크립트가 실화면 진단에 쓰인다. skullet(0.0.3)은 실제 내용의 형태를 재어 그리는 로딩 뼈대(skeleton) 라이브러리다.

S17(방향안 C 승격)과 S21-1(서버 상세 탭 4 개)을 거쳐 노골적인 생성형 표식(그라디언트, 반짝이 아이콘, 보라색)은 이미 없다. 남은 표식은 구조와 기본값이다.

§2. 요구사항 + 비목표
  • R1 생성형 기본값 제거: 흑연 팔레트(색조 없는 중립 한 계열 + 강조 하나 + 상태색 5 독립), 한글과 라틴을 한 벌로 그리는 글꼴, 아이콘 한 세트. 짙은 사이드바는 slate 남색 대신 흑연 계열 짙은 면.
  • R2 구조: 판 구조는 유지한다(11-08 판정). 판 안을 정돈한다: 식별자는 상자 없이 고정폭 글자로 쓰고, 두 판 높이 맞춤으로 생기는 빈 띠와 소제목 막대 3 곳을 걷는다(OQ4 판정).
  • R3 절제: 같은 신호는 한 곳에서 한 번. 빈 값은 — 하나, 해설은 구획당 한 줄.
  • R4 비동기 상태: 피커 3 곳과 경로 탐색기 3 곳의 로딩을 실제 내용 형태의 뼈대로 바꾼다. 목표는 도착 시 레이아웃 출렁임 0. 방식은 측정 뼈대로 정했다(K5).
  • R5 기능 무변경: URL, 폼, 컨트롤러, 도메인 변화 없음. 탭, 모달, SSE(Server-Sent Events) 갱신 동작 보존.
  • R6 DESIGN.md 를 슬라이스마다 함께 개정해 코드와 문서를 일치시킨다.
비목표
  • 문구 표현의 재작성은 S16-2(문구 정비, 시작 전) 소관이다. S22-2 는 문장의 존재와 자리만 정하고(삭제와 이동), S16-2 가 그 위에서 표현을 다듬는다.
  • 1024px 미만 반응형 확장 없음(DESIGN 원칙 7 유지). 다크 모드 없음.
  • 로그인과 가입 화면(auth.css)은 S18 이 진행 중이라 S22-1 토큰 교체만 받고 구조 변경은 하지 않는다.
  • SSE 실시간 영역에는 뼈대를 쓰지 않는다. 갱신마다 뼈대가 비치면 데이터가 사라진 것으로 읽힌다.
  • stageshow 로 마케팅 · 문서용 제품 일러스트를 만드는 일은 범위 밖이다(§11 후속 후보).

3-3 skullet 사용 계획

  • 하는 일: 실제 내용을 보이지 않게 배치해 상자를 재고 그 자리에 뼈대를 그리므로 도착해도 레이아웃이 밀리지 않는다. 150ms 안의 응답이면 뼈대를 생략하고 그 밖은 위에서 아래로 차례로 드러내며, prefers-reduced-motion · aria-busy 를 스스로 처리한다.
  • 적용 지점 6: 정의서 선택 피커(provisioning/server-detail.html 의 definitionPickerBody), 그룹 정의서 피커와 서버 넣기 피커(provisioning/server-group-detail.html), 경로 탐색기 3(management/common/path-browser.js · management/common/bundle-upload-bootstrap.js · management/subprogram/subprogram-edit.js). 제외: SSE 실시간 영역(provisioning/server-stream.js).
  • 들이는 방법: npm 매니페스트 없이(Gradle 단일 빌드) 보존본 sbx-design/vendor/skullet-0.0.3/(sha512 기록)의 dist/index.mjs · styles.css · LICENSE 를 static/vendor/skullet/ 로 복사하고(S17-5 방식), 일반 스크립트에서 import() 로 바닐라 Reveal 을 쓴다. 웹 컴포넌트 진입점은 import map 이 필요해 쓰지 않는다.
  • 공유 헬퍼: static/global/skeleton.js 하나가 6 지점을 맡는다. 각 지점의 행 렌더 함수를 견본 데이터로 불러 뼈대를 만들므로 뼈대와 실제 화면이 어긋나지 않는다. 경로 탐색기는 id 로 직전 모양을 기억한다.
  • 테마: --skullet-base 는 중립 선 토큰, --skullet-radius 는 --n-radius 에 잇는다. 애니메이션은 pulse 또는 none(화면을 쓸고 가는 shimmer 는 업무 화면에서 소음이다).
  • 위험 관리: 0.0.3 · 작성자 한 명이라 vendor 로 버전을 고정하고, 적재가 실패하면 지금의 "불러오는 중…" 문구가 남는다. CSP(Content Security Policy) 헤더가 없어 인라인 style 주입은 막히지 않는다(뒤에 CSP 를 들이면 nonce 필요).
  • 판정: 11-08 에 측정 뼈대로 정했다(K5). S22-3 CP1 실험에서 2 지점(정의서 선택 피커, 경로 탐색기 1)에 붙여 출렁임 0 을 확인하고, 뼈대 출처와 이동을 표시하는 ?skullet-debug 오버레이를 CP5 증거로 쓴다. 막히면 같은 원리를 skeleton.js 에 직접 구현한다. 라이브러리는 수단이고 결정은 측정 방식이다.

3-4 슬라이스 디자인 plan 형식 (K10)

화면 변경은 글로 판정할 수 없다. 그래서 슬라이스 plan 은 데모를 문서의 몸통으로 삼고, 데모가 실제로 쓰는 CSS · JS 를 같은 파일 안의 설계 절로 보인다. 이 우산 plan 의 데모는 축소 모형이지만 슬라이스 plan 의 데모는 실화면 스냅숏이다.

  1. 무대: 샌드박스에서 해당 화면을 렌더한 DOM(스크립트 제거)과 현행 CSS, 제안 CSS 를 파일에 넣는다. 조작은 전후 전환(버튼과 좌우 와이프 비교), 화면 탭(그 슬라이스 CP5 이야기의 목록 · 상세 · 폼 · 모달), 폭 1440 · 1024, 요소를 누르면 적용된 토큰과 규칙 표시, 원클릭 시나리오 4~6.
  2. 판정 패널: 그 슬라이스가 다루는 D 표식의 남음 · 해소 · 결정으로 유지.
  3. CSS 설계: 토큰 표(전 → 후)와 규칙 diff. 코드 블록은 데모가 실제로 적용하는 <style> 의 텍스트를 그대로 보인다. 화면과 설계 절이 같은 텍스트를 쓰므로 둘이 어긋날 수 없다.
  4. JS 설계(해당 시): 모듈 구성, 호출 순서, 실패 경로.
  5. 적용 범위와 CP5 항목: 파일과 건수, DESIGN.md 개정 문장, A · B · C 검증 항목, 결정 · OQ, Critical Files.

글꼴은 스냅숏에 쓰인 글자만 남긴 부분 글꼴을 base64 로 넣어 실제 모양을 보인다. 파일은 정본 하나이고 수 MB 까지 허용한다(Notion 임베드 1.8 MB 실증).

와이프 비교 · 요소 검사 · 스냅숏 무대는 명세 카탈로그에 없으므로 S22-1 CP1 착수 때 .claude/plan-report-html-spec.md 에 '디자인 plan' 변형 절을 먼저 추가한다. 밀도 상한(본문 13,000 자 · 표 7 개)은 설계 절에 적용하고 데모 코드와 스냅숏은 세지 않는다.

§4. 도메인 모델(SSOT: Single Source of Truth, 단일 진실 출처)

엔티티, VO, Enum, DB 변화가 없다(12 단계 중 6 · 7 · 9 단계 해당 없음). 이 캠페인의 SSOT 는 시각 규칙 세 곳이다.

  • static/global/style.css 의 :root 토큰(색 · 글꼴 · 반지름). 다른 CSS 는 토큰만 참조한다.
  • 아이콘 조각 templates/fragments/icon.html 의 icon(name). sprite 참조를 이 한 곳에 둔다.
  • 로딩 헬퍼 static/global/skeleton.js(S22-3). 로딩 지점 6 이 공유한다.

  • 새 예외와 새 엔드포인트가 없어 4 범주(2xx · 400 · 409 · 404)의 신규 시나리오는 없다.

  • S22-2 에서 상대 시각 표현을 만들면 단위 테스트를 쓴다. 경계: 59 초, 59 분, 23 시간, 6 일, 미래 시각. Clock 을 주입해 시각 의존 테스트를 막는다.
  • 아이콘 조각은 없는 이름이 들어오면 빈 출력이 아니라 렌더 실패가 나게 하고, 그 경우를 Thymeleaf 렌더 테스트 1 건으로 고정한다(조용한 누락 방지).
  • skullet 헬퍼는 JS 테스트 체계가 없어 CP5 브라우저 검증이 대신한다. 모듈 적재 실패 시 기존 문구 유지 경로는 CP5 의 B 항목으로 둔다.
