§1. 현재 상태 (진단)

실기 3호(2026-09-08)에서 일산 상1 이 등록 때와 다른 포트로 부팅했다 — 보고된 MAC 은 …c4:cc · IP 는 .170 이었는데, 서버 상세 화면의 호스트 NIC 섹션에는 등록 때 NIC(…c4:cd · .184) 한 행만 있었다. systemUUID 매칭이 서버 정체성을 잡아 주어 프로비저닝 흐름 자체는 끊기지 않았지만, 화면이 보여 주는 MAC · IP 가 실물과 어긋난 채로 남았다.

결손의 성격 — 값이 틀린 것이 아니라 낡았다. 바인딩은 최초 등록 순간의 스냅샷이고, 그 뒤의 포트 교체 · DHCP 재임대를 반영할 경로가 없었다. 운영자는 이 화면의 IP 로 접속을 시도하므로 낡은 표시는 곧 잘못된 안내가 된다.
§2. 요구사항 (확정) + 비목표
  1. 재부팅이 보고한 MAC 이 그 서버의 바인딩에 없으면 행을 추가한다(isPrimary=false).
  2. 같은 MAC 이 다른 IP 를 받았으면 그 행의 IP 를 갱신하고 ipSource 를 DHCP 로 둔다.
  3. 값이 그대로면 아무 것도 쓰지 않는다 — updatedAt 이 부팅마다 헛돌지 않게.
  4. MAC · IP 형식이 어긋나면 경고 로그만 남기고 부팅 응답은 정상 진행한다. 신원은 systemUUID 로 이미 확정됐으므로 표시 갱신 실패가 부팅을 막을 이유가 없다.
  5. DDL 변경 0 · 화면 변경 0 — 상세의 NIC 섹션은 이미 그 서버의 모든 바인딩을 primary 우선으로 렌더한다.
비 목표 :
  • primary 재지정 — 목록의 대표 IP 가 부팅 포트마다 흔들리지 않게 최초 등록 NIC 에 고정(§4 대안 A 탈락 사유).
  • 예약 · 고정 IP 관리(IpSource.STATIC) — 별도 자산 관리 주제.
  • 사라진 NIC 의 회수 · 이력 원장 — 더는 안 보이는 MAC 도 행으로 남는다(§8 Q1).
  • hostname · bondGroup 채우기 — iPXE 보고 페이로드에 그 값이 없다.

// HostNicBinding — 같은 값이면 손대지 않는다(updatedAt 헛돌기 방지)
public boolean refreshIp(IpAddressVO observed) {
    if (observed == null || observed.equals(this.ipAddress)) return false;
    this.ipAddress = observed;
    this.ipSource  = IpSource.DHCP;
    return true;
}
