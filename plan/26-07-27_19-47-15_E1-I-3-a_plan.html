§1. 현재 상태 — 쉬운 말 요약

지금 시스템 자산 화면은 진단 리눅스를 띄우는 데 쓰는 파일 여섯 개만 본다. 그런데 물리 서버를 실제로 부팅시키려면 그 여섯 개 말고도 관리해야 할 파일이 더 있다. 게스트 서버가 맨 처음 내려받는 부팅 프로그램 ipxe.efi 가 그렇고, 나중에는 주소를 나눠 주는 DHCP 서버의 설정 파일도 그렇다. 문제는 화면도 그 뒤의 코드도 "관리 대상은 진단 리눅스 한 종류" 를 전제로 짜여 있다는 점이다 — 종류가 하나 늘 때마다 화면의 조건과 서비스의 분기가 같이 늘어난다. 이번 작업은 화면과 코드를 자원 영역을 하나씩 꽂아 넣는 판으로 바꾼다. 판이 하는 일은 등록된 영역들에게 "너는 무엇을 갖고 있고 지금 상태가 어떠냐" 고 묻고 그 답을 모아 보여 주는 것뿐이며, 무엇을 어떻게 검사할지는 각 영역이 스스로 정한다. 그래서 화면에서는 주소가 /system/asset 으로 바뀌고, 한 화면 안에 영역이 두 덩어리로 나뉘어 보이며, 맨 위에 "정상 n / 전체 m" 집계가 붙는다. 진단 자산의 상세·교체·롤백 화면은 지금 있는 그대로 남는다.

진입 전제 (모두 충족) — E1-I-1 이 진단 자산의 봉인·무결성 판정과 대시보드를, E1-I-2-a 가 업로드 교체를, E1-I-2-b 가 버전 이력과 롤백을 완료했다. 도메인 무관 저장소 global/history 는 이미 AssetVersionKey(category, name) 로 어떤 자산이든 받아들이므로 이번 슬라이스에서 손대지 않는다.

지금 구조에서 종류를 늘릴 때 생기는 일

  • DiagnosticAssetIntegrityService 가 DiagnosticAsset.values() 를 직접 순회하고, 자산 루트도 PxeAssetsProperties 한 개를 직접 안다. 다른 루트를 쓰는 자원이 들어올 자리가 없다.
  • DiagnosticAssetController.parseSlot() 은 DiagnosticAsset.valueOf 1단 해석이다. 영역이 둘이 되면 여기에 "어느 영역이냐" 분기가 생긴다 — CLAUDE.md 가 금지하는 조건분기 확장.
  • 봉인 여부·상태 문구·배지 색을 문자열로 조립하는 코드(toResponse / offSlot)가 자원 종류만큼 복제된다.
§2. 요구사항 (확정) + 비목표
  1. /system/asset 통합 대시보드를 신설한다. 영역별로 구분된 표 + 영역 헤더 배지 + 전체 집계(정상 n / 전체 m)를 한 화면에 담는다.
  2. 구 대시보드 GET /system/diagnostic-asset 은 302 로 새 주소로 보낸다(북마크 보호). 진단 자산의 상세·교체·롤백 주소는 그대로 둔다.
  3. 보존 설정·봉인·재검사 엔드포인트는 새 주소로 이전하되 동작은 동일하다. 봉인만 /{area}/seal 로 영역 인자를 받는다.
  4. 영역은 Spring 빈 등록만으로 대시보드에 합류한다. 공용 층에 영역별 조건문을 두지 않는다.
  5. TFTP 영역을 두 번째 영역으로 신설한다. 슬롯은 ipxe.efi 하나이며 조회와 봉인만 한다.
  6. 영역 루트가 구성되지 않았으면 화면에서 사라지지 않고 "미구성" 상태로 보인다. 그 상태에서 봉인 버튼은 disabled + 사유 tooltip 이고, 서버 가드가 같은 판정으로 409 를 낸다.
  7. 엔티티·DDL 변경 0, 트랜잭션 경계 추가 0. 실 서버 없이 샌드박스에서 CP5 까지 끝난다.

설계 ⓐ — SystemAssetArea : 영역이 자기 자산과 판정을 제공한다

공용 층(대시보드·봉인)은 자원 종류를 모른다. 영역에게 묻고 답을 모으기만 한다. 라우팅은 저장소에 여덟 번 반복된 사내 표준(OrphanRecoverySpi 선례)을 그대로 쓴다 — 생성자에서 List<SystemAssetArea> 를 받아 키로 Map 을 만들고, 없는 키는 즉시 실패시킨다. 

public interface SystemAssetArea {
    SystemAssetAreaKey areaKey();          // 라우팅 키 (DIAGNOSTIC / TFTP)
    String displayName();                  // 화면 표시명
    AreaAvailability availability();       // CONFIGURED / NOT_CONFIGURED — 루트 구성 여부
    List<SystemAssetSlot> slots();         // 이 영역이 관리하는 자산 목록
    Optional<SystemAssetSlot> findSlot(String slotKey);
    AssetCondition inspect(SystemAssetSlot slot);   // 현재 상태 판정
    String markerResourceType();           // 마커 resourceType 문자열
    String historyCategory();              // 버전 이력 category 문자열

    default boolean supportsSeal() { return true; }
    default SealResult seal() {            // 미지원 영역은 이 default 가 안전망
        throw SystemAssetSealNotSupportedException.of(areaKey());
    }
}

채택 — 영역 확장점 + List 주입 라우팅영역 추가가 빈 등록 1건. 공용 층 분기 0. 사내 표준과 동형
공용 서비스에 영역별 switch탈락 — 종류가 늘 때마다 분기가 자라는 구조(CLAUDE.md 불가침 위반)

설계 ⓑ — AssetCondition : 판정 방식이 달라도 분기가 자라지 않는다

지금은 무결성 결과를 IntegrityStatus enum 으로 받아 화면 문자열과 배지 색을 if 로 조립한다. b 단계의 dhcpd 영역은 "파일 해시" 가 아니라 "문법 검사 종료코드" 와 "서비스 활성 여부" 로 상태를 판정한다 — 판정 결과의 모양만 공통이고 판정 방법은 영역마다 다르다. 그래서 결과 쪽을 인터페이스로 세우고, 영역별 판정은 그 인터페이스를 구현한 enum 이 담는다. 

public interface AssetCondition {
    String label();        // "원본 유지" / "마커 파일 없음" …
    String badgeClass();   // 배지 CSS 클래스
    boolean healthy();     // 집계(정상 n/전체 m)와 대시보드 배지의 단일 근거
}

// a 의 유일한 구현 — 봉인된 파일 자산의 판정 사다리(순서가 규약)
public enum SealedFileCondition implements AssetCondition {
    NOT_CONFIGURED, MISSING, MARKER_MISSING, SIGNATURE_INVALID, TAMPERED, ORIGINAL;
    // 사다리: 루트 미구성 → 파일 부재 → 마커 부재/손상 → 서명 무효 → 해시 불일치 → 원본
}

비채택 대안은 두 가지였다. ① IntegrityStatus enum 에 상수를 계속 더하기 — 파일 무결성과 무관한 값(서비스 비활성 등)이 섞여 enum 의 의미가 무너진다. ② 응답 DTO 에 문자열만 담고 판정 타입을 두지 않기 — 지금 코드가 그렇고, 집계 기준(healthy)이 화면 문자열 비교로 새어 나간다.

부품 추출 — SealedFileInspector

진단 자산의 probe(존재·크기·수정시각·해시)와 verify(판정 사다리)는 이미 도메인과 무관하다. 이 둘을 무상태 부품으로 뽑아 두 영역이 함께 쓴다. 확장점 추출이 아니라 부품 추출이므로 후속 R* 의 범위를 선점하지 않고, 오히려 그 재료가 된다. DiagnosticAssetIntegrityService 의 공개 시그니처와 판정 순서는 바뀌지 않는다 — 생성자 조립 한 줄만 바뀐다.

  • SealedFileInspector 6건 — 루트 미구성 / 파일 부재 / 마커 부재 / 마커 손상 / 해시 불일치 / 원본. 임시 디렉토리에 실제 ProvisionMarkerService 를 대고 실행해 판정 사다리 순서를 고정한다.
  • TftpAssetArea 5건 — 경로 미구성 / 파일 부재 / 봉인 전 / 봉인 후 원본 / 봉인 후 변조.
  • SystemAssetDashboardService 3건 — 영역 2개 집계 합산 / 미등록 영역 키 조회 시 404 예외 / 영역 표시 순서 고정.
회귀 안전망 — 기존 진단 자산 테스트 8파일 999행 중 791행이 단언 무변경으로 green 이어야 한다(상세·교체·활성화·판정표·버전). 대시보드 65행과 설정 106행만 새 URL 로 옮겨 같은 단언을 유지한다. 단언을 고쳐야 green 이 된다면 그것은 회귀 신호다.

잔존 책임과 해소 시점

  • 이중 구조 — DiagnosticAssetIntegrityService 가 남고 그 위에 DiagnosticSystemAssetArea 어댑터가 얹힌다. 층이 하나 늘지만 진짜 로직(탐지·판정)은 SealedFileInspector 부품으로 내려가 TFTP 와 공유되므로 중복은 회수되고 층만 남는다. 그 대가가 안전망 791행 보존이다. 해소 시점 = 활성화 코어 추출 R* 에서 어댑터와 기존 서비스 병합.
  • 이력 보존 개수는 전역 단일 값 그대로 둔다. 카테고리별 분리는 c 에서 실제로 필요해질 때.
  • 조작 감사 이력은 만들지 않는다 — 인증 주체가 없어 "누가" 를 채울 수 없다. 대신 봉인·재검사를 고정 접두 [system-asset] 구조화 로그로 남긴다. 도입 시점 = 인증 도입 + 활성화 확장점 R* 와 동시.
  • TFTP 사이드카 마커(ipxe.efi.provision.json)가 tftpd 를 통해 익명 조회될 수 있다. 격리망 전용이고 마커에는 서명·해시·파일명만 들어가 비밀값이 없으므로 수용하고 잔존 위험으로 기재한다.

§11. 다음 마일스톤

E1-I-3-b — PXE 인프라 관측(읽기 전용). 특권 명령을 화이트리스트로 감싼 실행 포트를 두고, dhcpd 를 세 번째 영역으로 붙여 구성 파일 문법·서비스 상태·주소 임대 현황을 조회 화면에 보여 준다. 관측 실패는 예외가 아니라 상태로 흡수하므로 신규 예외가 없다. 착수 전 Rocky 9 컨테이너로 실제 출력 형식을 실측한다.

E1-I-3-c — dhcpd 조각 반영(쓰기). 주소 대역과 임대 시간을 폼으로 입력받아 앱이 소유하는 설정 조각을 렌더하고, 문법 검사를 통과할 때만 원자 교체 후 재기동하며 실패하면 자동 복원한다. 싱글턴 설정 엔티티와 DDL 1건이 생기고, 실 Rocky 서버 검증이 필요하다.
