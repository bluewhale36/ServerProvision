§1. 현재 상태 (진단)

지금은 등록된 게스트 서버의 전원을 시스템에서 켜거나 끌 방법이 없다. 서버에는 본체 전원과 별개로 살아 있는 관리 칩이 있고, 그 칩에 표준 규격으로 명령을 보내는 방식이 Redfish 다. 그런데 앱 안에는 Redfish 로 실제 요청을 보내는 코드가 아직 하나도 없다. 이번 슬라이스는 그 통로를 만들고, 첫 용도로 전원 제어를 붙인다. 화면에서는 게스트 서버 상세에 '전원 제어' 카드가 생겨 지금 전원이 켜져 있는지 확인하고 켜기 · 강제 끄기 · 재시작을 누를 수 있다. 관리 칩을 찾지 못한 게스트는 버튼 대신 이유 문구만 보여 준다. 실제 장비 실측에서 명령은 성공했다고 답하는데 전원은 켜지지 않는 경우가 확인됐기 때문에, 켤 때만은 실제로 켜졌는지 확인하고 안 켜졌으면 한 번 더 다른 방식으로 시도한다.

현재 코드 · 데이터

  • 앱에 실 Redfish HTTP 호출이 0 이다 — BmcPasswordService 는 적용 계획을 산출해 로그와 화면에 표기할 뿐 장비를 부르지 않는다. 전역 RestClient 빈은 comps.xml 추출용 기본 설정이라 자가서명 TLS 를 다루지 못한다.
  • GuestServerDetail 에 bmcIp · bmcMac · boardSerial 이 이미 있다. bmcIp · bmcMac 은 E1-2 의 in-band 수집 결과이며, QEMU 처럼 관리 칩이 없는 환경은 null 로 남는 것이 정상 동작(정상 degrade)이다. 자격증명 저장소는 없다.
구현 계약 = E0-4 실측 1~4 호 (문서 조사값이 아니라 실장비 측정값) :
  • 인증은 Basic 우선. 세션은 유효 30 초 · 동시 상한 10 이라 Task 추적 같은 단기 용도로만 병용한다.
  • Reset 허용값은 5 종 — ForceOff · ForceRestart · GracefulShutdown · On · PowerCycle. GracefulRestart 는 없다.
  • On 실패 모드 실측 — "명령 성공 · 전원 불변" 이 재현됐다. 그래서 PowerState 폴링 + PowerCycle 폴백이 필요하다.
  • Reset 응답이 Task 경로를 반환한다(전달 성공과 실행 성공 · 실패를 나눠 판독).
  • 412 응답 시 fresh ETag 로 1 회 재시도. 전송 구간은 자가서명 TLS.

토론 종결 (P1~P6) · 소비처

  • 자격증명은 전역 표준 계정을 쓴다(username 은 무조건 admin) + 공장 기본 폴백(비밀번호 = 메인보드 시리얼 11 자 — 실측 · 예외 없음). 위치는 global/redfish. BootSourceOverride 는 후속(E1.5-2, K1 실측 게이트). 제어 불가는 예외가 아니라 결과 타입. 알림은 추후 별도 기능이며(BackgroundJob 은 용도가 아니다) 이번에는 로그 + 결과 반환까지. UC-2 수동 제어 화면은 이번에 포함한다.
  • 소비처 — E2-3(펌웨어 flash 전 ForceOff · 후 On — 이 슬라이스가 착수 게이트) · E3(설정 적용 후 ForceRestart) · MA6(같은 클라이언트 기반 재사용) · UC-2(수동 제어 화면).
§2. 요구사항 (확정) + 비목표
  1. Redfish 클라이언트 기반 — global/redfish 에 Basic 인증 · 자가서명 TLS · 타임아웃 · 오류 분류 · Task 판독을 담당하는 저수준 클라이언트를 둔다.
  2. 전원 제어 서비스 — Reset 5 종 발행 · PowerState 조회 · 켜짐 검증 폴링 + PowerCycle 폴백(집행 소비처가 부르는 동기 메서드).
  3. 자격증명 resolve — 표준 계정 우선 → 401 이면 공장 기본(메인보드 시리얼 11 자)으로 폴백.
  4. 결과 타입 — 제어 불가 · 발행됨 · 검증됨 · 실패 네 가지를 값으로 돌려준다.
  5. 게스트 상세 '전원 제어' 카드 — 상태 조회 · 버튼 · bmcIp 가 null 이면 버튼 없이 사유 문구로 UI 1 차 차단.
비 목표 :
  • BMC · BIOS 펌웨어 flash 집행 — E2-2 · E2-3
  • BIOS 설정 PATCH — E3 / Attribute Registry 화면 — MA6

  • 엔진(phase) 배선 — 소비처 슬라이스의 몫
🎬 미리보기 — 게스트 상세 '전원 제어' 카드

위 세그먼트로 게스트 상태(관리 칩 검출 여부 · 현재 전원)와 BMC 응답 모드를 바꾼 뒤 카드의 버튼을 눌러 보면, 그때 오간 Redfish 요청이 타임라인으로 찍히고 서버가 내리는 판정(PowerControlResult.kind)이 배지로 뜬다. 판정 스크립트는 RedfishPowerService 의 판정 순서를 그대로 재현한다 — 실 HTTP 왕복과 폴링 간격(5 초 × 12 회 = 60 초)은 데모에서 압축했다. 화면의 실제 [켜기] 는 단발 발행(SENT) + [상태 조회] 다(§3 — 60 초 폴링을 화면에 얹지 않는다). 이 데모의 [켜기] 는 집행 소비처가 쓰는 검증 경로(powerOnAndVerify)의 판정을, [강제 끄기] · [재시작] · [정상 종료] 는 파괴적 액션의 confirm 확인을 보여 준다.

§4. 도메인 모델 (SSOT)
타입내용
RedfishResetType 신규실측 5 종 enum — ON("On") · FORCE_OFF("ForceOff") · FORCE_RESTART("ForceRestart") · GRACEFUL_SHUTDOWN("GracefulShutdown") · POWER_CYCLE("PowerCycle"). wire 값을 보유하고 destructive() 로 ON 외 전부(ForceOff · ForceRestart · GracefulShutdown · PowerCycle)를 true 로 돌려준다(화면 confirm 의 재료).
RedfishEndpoint 신규record — ip · username · password. 클라이언트 호출 단위이며 basicAuthHeader() 를 제공한다.
BmcCredentialsResolver 신규표준 계정(설정 provision.bmc.username 기본 admin · provision.bmc.password)을 먼저 쓰고 401 이면 공장 기본으로 폴백(비밀번호 = boardSerial 11 자). 표준 비밀번호가 없으면 폴백만 시도하고, 시리얼도 없으면 제어 불가 판정의 재료가 된다.
RedfishClient 신규저수준 — JSON GET · POST · Basic 인증 · 전용 RestClient(자가서명 신뢰 + connect 3 초 / read 10 초, comps 용 전역 빈과 분리) · 오류 분류(RedfishError : CONNECT_FAILED · AUTH_FAILED · PRECONDITION_FAILED · PROTOCOL) · Task 경로 GET 판독.
RedfishPowerService 신규powerState(guest) 조회 / reset(guest, type) 발행 + Task 판독 + 직후 상태 1 회 / powerOnAndVerify(guest) On 발행 → PowerState 폴링(5 초 간격 · 총 60 초) → 불변이면 PowerCycle 1 회 폴백 → 재폴링 → 검증됨 또는 실패. 실패는 서버 로그(WARN)로 남긴다.
PowerControlResult 신규record — kind{UNSUPPORTED, SENT, VERIFIED, FAILED} · powerState(nullable — RedfishPowerState enum ON · OFF · POWERING_ON · POWERING_OFF · UNKNOWN, wire 값 보유. 원시 String 금지) · message(사용자 문구. 문구의 SSOT 는 서버 — U4-1-3 관례). 예외가 아니라 값이며 컨트롤러가 그대로 JSON 으로 직렬화한다.
화면 수정server-detail.html 에 '전원 제어' 카드 — bmcIp 가 null 이면 문구만, 있으면 상태 배지(lazy)와 버튼 [상태 조회] [켜기] [강제 끄기(confirm)] [재시작(confirm)] [정상 종료(confirm)] — PowerCycle 은 화면 미노출(API 전용 폴백, OQ1). 페이지 스크립트 server-power.js 를 새로 둔다.

UI 진리표 —
  • bmcIp null → 버튼 없음 + 사유 문구 (UI 1 차 차단)
  • bmcIp 있음 → 버튼 활성, PowerState 미조회 상태의 배지는 "미조회"
  • ForceOff · ForceRestart → confirm 모달을 거쳐야 발행
  • XHR 결과 kind 별 배지 색 — VERIFIED 초록 · SENT 회색 · FAILED 붉음 (+ message 표기)

엔티티 · Repository · DDL 변경이 없다(Step 6 · 7 · 9 는 N/A). 저수준 예외는 클라이언트 안에서 분류돼 결과 타입으로 흡수되므로 컨트롤러에 try/catch 를 두지 않는다(§7).

§7. 예외 계층
신규 공개 예외 0. 저수준 RedfishError 분류(CONNECT_FAILED · AUTH_FAILED · PRECONDITION_FAILED · PROTOCOL)는 RedfishClient 내부에 머물고, 밖으로는 PowerControlResult 값이 나간다. 전원 제어 실패는 일상적으로 일어나는 사건이므로 예외 계층을 늘리지 않는다.

재사용하는 것은 둘이다 — 게스트를 못 찾은 경우의 기존 404 경로, 그리고 잘못된 resetType 을 400 으로 만드는 요청 바인딩 · 검증 경로다. 둘 다 이미 있는 advice 매핑을 그대로 탄다.

D1위치 · 클라이언트global/redfish + 전용 RestClient 빌더execution 내부 · 전역 빈 재사용
D2자격증명설정 표준 계정(admin 고정) + 401 시 시리얼 폴백게스트별 엔티티(E3-0) · fail-fast
D3실패 표현결과 타입 PowerControlResult예외 계층
D4검증 폴링집행용 동기 powerOnAndVerify(5 초 × 60 초 · PowerCycle 1 회). 화면은 단발화면도 폴링(60 초 블로킹) · 비동기 Job
D5Reset 허용값실측 5 종 enum 고정ActionInfo 런타임 조회
D6알림로그 + 결과 반환까지BackgroundJob · 신규 알림 채널
D7BootSourceOverrideE1.5-2 후속 (K1 게이트)이번 합류
  • D1 — MA6(management)도 소비처이므로 execution 안에 두면 의존 방향이 어긋난다. 또한 자가서명을 신뢰하는 TLS 설정을 comps 추출용 클라이언트에 섞지 않는다.
  • D2 — 사용자 확정 P1 : username 은 무조건 admin 이고 신품 비밀번호는 시리얼 11 자다(예외 없음 · 수집 정보에 포함). 미설정 fail-fast 는 부적절하다 — BMC 기능은 부가 기능이라 앱 부팅을 막을 이유가 없다.
  • D3 — 전원 제어 실패는 일상 사건이고(P4), 소비처(엔진 · 화면)가 결과를 각자 다형으로 받는다.
  • D4 — 실측 실패 모드("명령 성공 · 전원 불변")의 유일한 대응이 폴링 + 폴백인데, 그 60 초를 화면 XHR 에 얹으면 UX 가 죽는다. 화면은 단발 발행 + [상태 조회] 로 나눈다.
  • D5 — 계약은 실측이다(4 호까지 5 종이 일관). ActionInfo 런타임 조회는 장비가 다변화되는 시점의 일이다. POWER_CYCLE 은 화면에 노출하지 않는 API 전용 폴백이지만 실측 허용값이므로 상수는 보존한다(OQ1 확정 — GracefulShutdown 은 화면 4 종에 포함).
  • D6 — 사용자 확정 P5 : BackgroundJob 은 이 용도가 아니고, 프로비저닝 알림은 별도 기능으로 예정돼 있다.
  • D7 — Once / Continuous 구분과 Systems/Self/SD 경유가 아직 미실측(K1)이다. 실물 없이 계약을 짜지 않는다.

열린 질문 (CP1 결정 — 권장안 굵게)

  • OQ1 확정 2026-08-20 화면 버튼 = On · ForceOff · ForceRestart · GracefulShutdown 4 종. PowerCycle 만 Java API 전용(폴백용 — 화면 미노출).
  • OQ2 확정 2026-08-20 provision.bmc.username(기본 admin) · provision.bmc.password = 사내 공장 표준 세팅 비밀번호를 넣어 둔다(환경변수 BMC_PASSWORD). 401 실패 시 M/B 시리얼 11자로 폴백 — 사용자 확인과 설계 동일.

부산물 · 주의

  • server-detail.html 은 U4-1 브랜치(PR #40)에서도 수정한다. 병합 시 카드 추가 위치에서 사소한 충돌이 날 수 있다.
  • BmcPasswordService(현재 계획 산출 전용)를 실제 호출로 전환하는 일은 이 슬라이스 밖이다 — E3-0 계열로 넘긴다.
