§1. 배경

Windows Server 2025 무인 설치(서버 260915009 · 260914017, 보드 MS04-CE0) 중 "이 드라이버 소프트웨어의 게시자를 확인할 수 없습니다" 창이 2~3 회 떴습니다. 사람이 "설치하지 않음" 을 눌러야 설치가 이어졌습니다. 화면 앞에 사람이 없으면 SetupComplete(Windows 설치 직후 SYSTEM 으로 한 번 도는 스크립트)가 끝나지 않고, 첫 로그온 완료 보고까지 막힙니다.

무인 설치에서 대화 상자 대기는 실패보다 나쁩니다.

드라이버는 SetupComplete 가 pnputil /add-driver … /install 로 설치합니다. 드라이버 자원마다 설치 방식이 있습니다.

조건설치 방식설치 대상
변형 없음TREE폴더 안 INF 전부 (/subdirs)
변형 있음진입점 확장자로 INF · MSI · EXE파일 하나

INF 는 드라이버 설치 정보 파일, CAT 은 그 INF 패키지의 파일 해시를 담은 서명 카탈로그입니다. 변형은 OS 버전당 한 행만 허용합니다(SubprogramVariantRules.VERSION_DUPLICATE).

사용자 지시 (2026-10-02)

  • A 안 : 서명 검증 실패 시 묻지 않고 거절합니다.
  • B 안 : 진입점에 폴더를 지정하는 방식을 현행 방식과 융합해 "파일 또는 폴더" 를 지정할 수 있게 기능을 수정합니다.
  • 둘 다 이 HF 에서 처리합니다.

세 건 모두 오류 0xE000024B("변조된 것으로 보임")였고, 세 건이 곧 창 세 번입니다.

실측에서 확정한 사실

  • 우리 사본 손상이 아닙니다. 같은 폴더(PROXGB/NDIS65)의 같은 nicco5.dll 로 ixn · sxa 등 다른 카탈로그는 통과했습니다. 따라서 Intel 원본 패키지 안의 일부 옛 INF 카탈로그가 다른 버전의 nicco5.dll 로 만들어졌다고 봅니다.
  • 서명자로 거를 수 없습니다. 카탈로그 서명자는 LAN 77 · Chipset 92 · ASPEED · QAT 전부 Microsoft Windows Hardware Compatibility Publisher 입니다. 즉 모두 WHQL(Windows Hardware Quality Labs) 서명입니다. "서명 카탈로그 없는 INF 건너뛰기" 는 1 차의 QAT 예제만 잡고 2 차는 잡지 못합니다.
  • INF 선언으로도 거를 수 없습니다. NDIS65 INF 는 [Manufacturer] 에 NTamd64.10.0(상한 없음)으로 선언돼 있어, INF 선언 기준의 "대상 OS 아님" 판정으로는 걸러지지 않습니다. Intel 은 OS 구분을 폴더 이름(NDIS65 · NDIS68 · WS2022 · WS2025)으로 합니다.
  • LAN 패키지의 Server 2025 폴더는 7 개입니다: PRO1000 · PRO2500 · PRO40GB · PROAVF · PROCGB · PROXGB 의 Winx64/WS2025, 그리고 RDMA/Windows/ws2025.
  • Windows 에는 "묻지 않고 거절" 갈래가 있습니다. 같은 setupapi 로그에서 Windows 기본 프린터 드라이버(prnms009.inf)는 같은 해시 오류를 Code Integrity is enforced 경로로 묻지 않고 실패했습니다.
  • 서버가 받는 로그는 꼬리 60 줄(최대 4,000 자)뿐입니다. 그래서 1 차에는 실패 INF 이름이 잘렸습니다. pnputil 출력은 로캘에 따라 바뀌는 문장이므로 파싱하지 않습니다(HF11-1 원칙).
§3. 결론

원인은 두 겹입니다.

(1) 서명 실패 시 사람에게 묻는다

  • 서명 검증에 실패한 패키지에 대해 Windows 가 사람에게 묻습니다.
  • 무인 설치가 정지합니다.
  • 대응 : 원인이 무엇이든 막습니다 (A).

(2) TREE 가 옛 OS · 예제 INF 까지 설치한다

  • TREE 방식이 패키지 안의 옛 OS · 예제 INF 까지 설치 대상으로 삼습니다.
  • 대응 : 설치 범위를 OS 폴더로 좁힐 수 있게 합니다 (B).

여기에 더해, 실패를 화면에서 볼 수 있어야 합니다. 그래서 실패 INF 를 잘리지 않게 전부 보고합니다(§4-2).

§4. 수정 방향

§4-1 A — 서명 검증 실패 시 묻지 않고 거절

SetupComplete 가 드라이버 설치 전에 드라이버 서명 정책 HKLM\SOFTWARE\Policies\Microsoft\Windows NT\Driver Signing 의 BehaviorOnFailedVerify 를 2(차단)로 두고, 설치가 끝나면 원래 값으로 되돌립니다. 원래 값이 없었으면 지웁니다.

Server 2025 가 이 정책을 따르는지는 미확인입니다. 실기 검증 항목입니다(§6). 따르지 않으면 §5 의 A2(시간 제한 감시)로 넘어갑니다.

§4-2 INF 단위 설치 · 실패 INF 전체 보고

TREE · FOLDER 방식은 pnputil … /subdirs 한 번 대신 for /r 로 INF 하나씩 pnputil /add-driver "<INF>" /install 을 돌리고, INF 마다 한 줄을 남깁니다. 종료 코드는 로캘과 무관합니다.

[SPV-INF] <folder>|<상대경로>|exit=N
[SPV-INSTALL] <folder>|<mode>|<entry>|exit=N

§4-3 B — 진입점에 파일 또는 폴더

변형 진입점에 폴더를 지정할 수 있게 합니다. 저장 시 트리 안 실제 경로를 보고 판정합니다.

실제 경로판정저장값
디렉토리FOLDER끝에 / 를 붙여 정규화
파일확장자로 INF · MSI · EXE (종전대로)그대로

InstallEntrypointKind 에 FOLDER 를 더하고, fromPath 는 끝의 / 로 FOLDER 를 압니다. 그래서 종류를 저장할 컬럼은 필요 없습니다. 다만 "한 OS 버전에 여러 행" 은 기존 고유 제약 (subprogram_id, os_version) 과 충돌하므로 제약 교체 DDL 1 건이 따릅니다(CP2 에서 발견 · 정정).

한 OS 버전에 여러 행을 허용합니다. VERSION_DUPLICATE · WILDCARD_DUPLICATE 를 "같은 OS 버전 + 같은 진입점" 중복 하나로 바꿉니다. 선택(WindowsDriverSelection.pick)은 버전이 정확히 일치하는 행 전부(정렬 순)를 고르고, 없으면 전 버전 행 전부를 고릅니다.

게스트 목록 한 줄은 행 하나에 대응합니다. SetupComplete 는 FOLDER 줄을 받으면 그 하위 폴더에서 §4-2 의 INF 단위 루프를 돕니다.

탈락 사유

  • A2 : 대화 상자를 띄운 쪽이 pnputil 이 아니라 설치 하위 프로세스일 수 있어, pnputil 을 종료해도 창이 남을 수 있습니다. 또 정상적으로 오래 걸리는 설치를 잘못 끊습니다. A1 이 실기에서 무시될 때의 차선으로 남겨 둡니다.
  • A3 : 카탈로그 파싱 · Authenticode 해시 계산의 구현 비용이 크고, Windows 가 이미 하는 검증을 다시 만드는 일입니다.
  • 출력 파싱 : 로캘에 의존합니다(HF11-1).
  • 로그 꼬리 확대 : 길이 상한이 남아 같은 잘림이 재발합니다.
  • 종류 컬럼 : 경로에서 유도되는 정보를 두 곳에 저장하면 어긋날 수 있습니다. R15-1 의 "확장자가 방식을 정한다" 와 같은 원칙입니다.
  • 서빙 시점 확인 : 선택 로직은 의존 0 의 정적 진리표(R15-2)이므로 파일 시스템 의존을 넣지 않습니다.
  • ; 구분 : 경로마다 검증하고 오류 위치를 표시하기 어렵습니다.
  • 포함 폴더 목록 : OS 버전별로 폴더가 달라(WS2022 · WS2025) 버전 연결을 다시 만들어야 합니다. 변형 행이 이미 그 연결을 갖고 있습니다.
