§2. 요구사항 + 비목표
  1. 정의서 스냅숏(RHEL) → kickstart 텍스트. 같은 입력이면 같은 출력(결정적).
  2. Rocky 8 · 9 · 10 차이는 RhelRelease 능력 메서드로만 가른다.
  3. 비밀번호는 kickstart 에 해시로만 싣는다(--iscrypted). root 없으면 rootpw --lock.
  4. 정의서에서 오는 값과 실행 때만 아는 값(설치 원본 URL · 대상 디스크)을 입력 둘로 나눈다.
  5. 대상 디스크 없이는 렌더하지 않는다(모든 디스크를 지우는 kickstart 를 만들 수 없게).
  6. 렌더본은 메모리에만 두고 toString 을 가린다.
비 목표(어디로) :
  • kickstart 서빙 · iPXE 체인 · 트리 주 버전 대조 · 실행 준비도 → b-4
  • 대상 디스크 by-id 결정 → b-6(b-3 은 값을 받기만)
  • %post 첫 부팅 완료 보고 유닛 · 보고 엔드포인트 → b-5(Q3)
  • 화면 변경 없음 · DB 변경 없음 · DDL 없음
🎬 kickstart 미리보기 (라이브 데모)

왼쪽 입력판을 바꾸면 오른쪽 kickstart 가 다시 렌더됩니다. 판정은 §4 렌더 규칙 표를 그대로 옮긴 JS 입니다(드리프트 0). 버전에 따라 달라지는 줄(#version · --allow-ssh)은 주황으로 강조합니다.

D-4 비밀번호provider 가 toCrypt(hasher) 로 해시만 넘긴다. 렌더러는 평문을 모른다--plaintext 경로 없음

D-6 grow 크기--size=1 --grow--size 생략(레거시) : 유효하지만 명시가 흔한 형태라 읽기 쉽다

D-8 패키지 누락 처리--ignoremissing 을 쓰지 않는다(Q4 권고)사유 : 정의한 것보다 적게 설치하고 조용히 끝나는 것보다 멈추는 편이 낫다. 저장 때 ISO 제공 목록으로 이미 검증

            
D-9 b-2 D-19 의 "b-3 에서 확인" 항목기본 환경 · 기본 그룹 · root 기본은 정의서 화면(b-2)이 정하고 kickstart 는 저장값을 그대로 싣는다(기본값을 kickstart 에서 다시 넣지 않는다)--allow-ssh 의 9 지원은 V-6 으로 확인
