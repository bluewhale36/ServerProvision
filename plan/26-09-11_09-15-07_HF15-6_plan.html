§1. 현재 상태 (진단)

진단 리눅스 에이전트는 lspci 원문을 서버로 보내고, 서버 파서 DiagnosticReportParser.classifyPcie 가 장치 클래스로 걸러 HardwareSpec.PcieDevice(slot, kind, vendor, model) 로 적재한다. 온보드 NIC(Intel I210 두 개)도 Ethernet 클래스라 같은 목록에 담기고, 그 결과 "PCIe 슬롯 장착물" 표에서 운영자가 추가로 꽂은 카드와 보드에 붙박인 칩을 구분하지 못한다 — 실기 4호에서 사용자가 지적한 지점이다.

BMC 웹 API 실측 (AMI · E0-3 계열 · 2026-09-10 HAR)

GET /api/system_inventory_gbt/pci_info 가 장치마다 다음을 준다. 헤더는 X-CSRFTOKEN + 세션 쿠키이며, 로그인 POST /api/session 과 함께 기존 global.bmcweb.AmiWebClient 가 이미 구현해 두었다.

필드예시쓰임
hexBusNumber"0x00AE"lspci 슬롯의 버스
hexDeviceNum"0x0000"lspci 슬롯의 장치 번호
iOnBoard0 / 1온보드 여부 판정 축
strSlotDesignation"PCIE_1" / "Onboard"추가 장착일 때 보드 표기
hexVendorID · hexDeviceID · strClass · strProductName—대조 참고(판정 축 아님)

lspci 의 슬롯 표기 ae:00.0 은 버스 0xAE · 장치 0 · 기능 0 이므로, 버스와 장치 번호로 BMC 응답과 1:1 로 이어진다.

제약(사용자 실측) — 이 조회는 BMC 최초 접속 뒤 일정 시간이 지나거나 cold boot 등 조건이 맞아야 정상 응답하고, 그 전에는 오류를 낸다. 즉시 실패로 다루면 정상 장비가 실패로 기록된다.
사용자 결정(2026-09-11) — 온보드 NIC 는 보드마다 항상 같으므로 스펙 그룹 키에서 제외해도 무방하다.
§2. 요구사항 (확정) + 비목표
  1. 진단이 적재한 PCIe 장착물 각 항목에 온보드 · 추가 장착 · 미확인 중 하나를 태깅한다. 판정 축은 BMC pci_info 의 iOnBoard, 추가 장착의 보드 표기는 strSlotDesignation 이다.
  2. lspci 슬롯과 BMC 항목은 버스 + 장치 번호로 잇는다. 같은 버스 · 장치의 다중 기능(듀얼 포트 NIC 의 .0 · .1)은 같은 태그를 받는다.
  3. 조회는 진단 완주 뒤 비동기로 한다. 사용자 요청 스레드도, 설정 · 굽기 워커도 태깅을 기다리지 않는다.
  4. 미준비 증상(오류 · 빈 목록)은 5 회 · 30 초 간격으로 재시도한다. 인증 실패는 즉시 중단한다.
  5. 끝내 못 받으면 "미확인" 으로 두고 프로비저닝을 막지 않는다 — 상태 · 원장에 실패를 남기지 않는다.
  6. 스펙 그룹 키에서 온보드 항목을 뺀다. 뺀 뒤 비면 "추가 장착 없음" 을 뜻하는 값으로 둔다.
  7. 서버 상세 화면 PCIe 표에 "장착" 열을 더하고, 태깅이 끝나면 새로고침 없이 갱신되게 한다.
비 목표 :
  • hdd_info · cpu_info · dimm_info 는 쓰지 않는다 — 디스크는 RAID 인벤토리와 lsblk 가 담당한다.
  • BMC 미준비 조건 자체를 해소하지 않는다(콜드 부팅 유도 등).
  • 그룹 재편성을 자동 실행하지 않는다 — 키가 바뀌면 다음 편성 때 반영된다.
🎬 미리보기 — 매칭 · 재시도 라이브 데모

왼쪽은 진단이 이미 적재한 lspci 항목, 오른쪽은 BMC pci_info 응답이다. 오른쪽 항목을 빼고 넣거나 응답 조건(빈 목록 · 인증 실패)을 켠 뒤 [조회 시도] 를 누르면, 시도 횟수가 올라가며 왼쪽 배지와 판정 캡션이 바뀐다. 판정 JS 는 §4 의 PcieSlotTagger.tag 진리표와 재시도 규칙을 그대로 재현한다.

주의

  • 과도기 그룹 분화 — 태깅 전 서버(UNKNOWN)는 종전대로 온보드가 키에 남아, 같은 하드웨어라도 태깅된 서버와 다른 그룹에 갈 수 있다. 다음 PXE 재진단 때 해소된다(재진단마다 이벤트가 다시 나므로 태깅도 갱신된다).
  • DDL 0 · env 0 — 두 필드는 기존 JSON 컬럼 안에 들어간다. 스키마 변경도 새 환경변수도 없다.
  • slotDesignation 은 보드 인쇄 표기를 그대로 담는 표시 전용 값이라 이번에는 String 이다(D-3). 판정에 쓰이지 않는 표시 전용 값이라 VO 로 올리지 않는다(세션 결정 · CP1) — 판정에 쓰이게 되는 시점에 승격한다.
