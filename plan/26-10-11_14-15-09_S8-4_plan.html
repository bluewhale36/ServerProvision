화면 탭을 고르고 Search 를 눌러 창을 연다. 창 안 값은 [검색] 을 눌러야 결과에 반영되고, 닫으면 버려진다. 모의 데이터를 실제로 걸러 결과 건수 · 토큰 · URL 을 계산한다. 시나리오 버튼은 클릭 지점을 주황 테두리로 짚으며 재생하고, 끝난 뒤 이어서 직접 조작할 수 있다.

§4. 도메인 모델 (SSOT)
엔티티 · VO · enum · 서비스 · 컨트롤러 변경 없음. 이 슬라이스의 SSOT 는 서버 코드가 아니라 줄 마크업이다. Primitive Obsession 점검 대상인 새 도메인 값이 없다.

줄 마크업 — 창 모양 · 토큰 문구 · "조건 걸림" 판정의 단일 출처

form#listQuery.n-filter-bar[data-list-query] ├── div.n-filter-search │ ├── input[data-list-search] 검색칸 (Enter = 제출) │ ├── button[type=button][popovertarget] 'Search' │ └── 적용 조건 토큰 자리 JS 가 줄에서 생성 ├── div.n-filter-panel[popover=auto] 창 │ ├── div.n-filter-row[data-filter-row] │ │ ├── span.n-filter-row-label 줄 라벨 = 토큰 라벨 │ │ └── div.n-filter-row-field 칩 · 체크박스 · 셀렉트 · 날짜 │ ├── … 줄 반복 │ └── 하단 [검색] · [닫기] └── 띠에 남는 것 정렬 · 보기 · 결과 N건 · 초기화

결정 보충

  • D1 — 띠 위 즉시 제출 규칙(S8-1)은 띠에 남는 정렬 · 보기에만 유지한다.
  • D2 — 바깥 클릭 · Esc 닫힘, 닫힐 때 버튼으로 포커스 복귀, aria-expanded 를 브라우저가 제공한다. 최상위 레이어라 Miller 의 overflow 잘림 · z-index 다툼이 없다. 위험: 창 안 날짜 · 셀렉트의 네이티브 선택기가 바깥 클릭으로 오인되는지 — CP5 확인 항목(B3). 문제 시 popover="manual" + 바깥 클릭 처리 소량으로 전환한다.
  • D3 — 미지원 브라우저는 @supports 분기로 화면 위쪽 가운데 고정(깨지지 않음). 근거: DESIGN.md 원칙 7 이 Chrome 기준(:has 사용 선례). 좁은 화면(≤ 640px)은 좌우 여백 16px 꽉 찬 폭.
  • D5 — 조건이 창 속에 숨으면 목록이 왜 좁아졌는지 화면에서 사라진다(예외 = UI 1차 안내 원칙의 조회판). 토큰은 JS 가 줄 마크업에서 생성한다(서버 코드 0).
  • D7 — [검색] = action.search, [닫기] = action.close(문구 규약 5: 파괴적 액션 없는 조회 패널 = 닫기).
  • D8 — 화면은 줄 묶음만 마크업 조각 인자(Thymeleaf fragment expression)로 넘긴다. resource-filter :: bar 는 이 조각에 자원 줄 3 을 넘기는 얇은 조각으로 바뀐다.
  • D9 — 띠 제출 경로는 검색칸 Enter 하나(placeholder 와 합치). 문구 'Search' 는 사용자 지시 영문 — 키 common.list.search-open. 창 하단은 한국어 '검색'(ecount 의 Search(F3) / 검색(F8) 대응).
  • D10 — 창 안이면 값만 바꾸고 제출하지 않는다(① change 즉시 제출 · ⑦ 날짜 즉시 제출 · ③ "전체" 칩의 제출에서 제외). 새 동작: ⑩ 창 열림 시 첫 컨트롤 포커스 / 닫힘(적용 없이) 시 되돌림 ⑪ 토큰 생성 · × 처리. 날짜 거꾸로 막기(syncRange)는 창 안에서도 그대로.
  • D11 — 슬라이스는 "CP5 가 한 이야기인가" 로 나눈다. 창 이전의 검증은 "같은 조회가 창을 통해 된다", 1 년 기본은 "기본값이 URL · 초기화 · isFiltered 와 공존한다", 선택기는 "자기 조회 화면이 있는 대상을 고른다" 로 이야기가 셋이다.
