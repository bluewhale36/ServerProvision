§2. 요구사항 + 비목표
  1. 정의서가 RHEL 이면 OS_INSTALLING 에서 kickstart 설치를 시작한다. Windows 동작은 바뀌지 않는다.
  2. 계열 판정은 OS 설치 phase 안에서 다형으로 한다. dispatcher 와 registry 는 계열을 모른다.
  3. 설치 트리를 확보한 경우에만 서빙한다.
    • 확보하는 중이면 대기 iPXE 를 낸다.
    • 확보에 실패하면 OS 설치 단계를 실패로 닫는다(b-1 D-10).
  4. 트리 .treeinfo 의 주 버전과 정의서 RhelRelease 가 다르면 실패로 닫는다(b-2 개정 5).
  5. kickstart · 트리는 토큰 경로로만 서빙한다.
    • 토큰은 메모리에만 두고, 완료 · 실패 · 시한 · 운영자 실패 때 회수한다.
    • kickstart 는 원장이 RUNNING 일 때만 낸다.
  6. 원장 행은 계열마다 origin 을 갖고, 모든 조회와 스위퍼는 자기 origin 행만 집는다.
  7. 실행 준비도가 RHEL 막힘 사유를 화면과 게스트 콘솔에 낸다. 사유는 b-3 Blocked · 트리 사전 점검 · 디스크다.
  8. 대상 디스크는 OS 영역 RAID 볼륨의 WWN 으로 정한다(b-6 을 합친다, Q2).
비 목표(어디로) :
  • 첫 부팅 완료 보고 · %post 유닛 · 대상 서버 echo · 성공 때 트리 release → b-5.
    • 그 전까지 RHEL 설치는 성공해도 시한 스위퍼가 실패로 닫는다. 이것은 잔존 비대칭이다.
  • Ubuntu 설치 → E4-1-b 밖.
  • 부트 순서 조작 → HF24 원칙상 하지 않는다.
  • F-1(Rocky 9 --allow-ssh) → 실설치 뒤 결정한다.
