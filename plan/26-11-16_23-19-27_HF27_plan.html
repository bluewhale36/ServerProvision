§1. 배경

버그 수정 plan 형식이라 표준 11 섹션과 인터랙티브 데모를 두지 않는다. 배경, 실측, 결정, 테스트 · CP5, 범위 밖, Critical Files 순으로 적는다.

드라이버 · 유틸리티를 '기존 디렉토리 등록'으로 등록하다가 중복 확인 창이 열렸을 때 [취소]를 누르면, 운영자가 지정한 기존 폴더가 통째로 삭제된다. BIOS · BMC 처럼 기존 폴더는 보존한다.

1-1. 출처

  • docs 스트림(DOC-7 사용자 매뉴얼)이 자원 관리 묶음을 코드와 대조하다 찾아 넘긴 3차 결함 C-16(데이터 손실 위험).
  • 매뉴얼에는 "이 경우 [취소]를 누르지 말 것" 경고로 들어가 있다.

1-2. 사용자 결정 (2026-11-16)

우선순위 제안 순서(HF26 → C-16 → B-1 · B-2 → C-15 · C-1 → 나머지)대로 진행한다.

§2. 실측

2-1. 두 등록 경로의 취소 처리

단계업로드 등록 (addSubprogram)기존 디렉토리 등록 (registerExisting)
대상 폴더업로드 압축을 푼 임시 트리운영자가 지정한 기존 폴더
내용 해시가 휴지통 · Deprecated 자원과 같을 때issueHashNudge → 중복 확인 창같음
창의 [취소]SubprogramNudgeService.cancel → SubprogramRegistrationService.purgeNudgeTempTree(payload.tempFilePath()) → 폴더 삭제같은 호출 · 운영자 폴더 삭제
  • payload 에 업로드 임시물인지 기존 폴더인지 구분하는 값이 없다.

2-2. BIOS · BMC 선례

  • BIOS · BMC 는 R12-1(BIOS) · R12-2(BMC) 에서 고쳐져 있다.
  • issueHashNudge 가 payload attributes 에 "claimExisting" 을 기록하고, cleanupNudgeCancelled(payload) 가 그 값이 true 면 지우지 않는다(BiosRegistrationService · BmcRegistrationService).
  • 같은 문자열 키 해석이 두 곳에 복제돼 있다.
§3. 결정 (채택 · 비채택 · 탈락 사유)
ID결정채택비채택탈락 사유
D-1구분 방법 BIOS · BMC 와 같은 claimExisting 플래그를 payload attributes 에 기록(업로드 false · 기존 디렉토리 true), 취소 처리는 SubprogramRegistrationService.cleanupNudgeCancelled(payload) 가 플래그를 보고 보존 · 삭제 기존 디렉토리 등록에서는 중복 확인 창을 띄우지 않기 창의 [그래도 등록] · [기존 영구 삭제 후 등록] 은 기존 디렉토리에도 의미가 있다(같은 내용의 휴지통 · Deprecated 자원과 어떻게 할지 고르는 것)
D-2플래그 해석의 단일화 ContentNudgePayload 에 키 상수와 판정 메서드(claimsExistingTree())를 두고 BIOS · BMC · 드라이버가 모두 쓴다 드라이버에 BIOS 코드를 한 벌 더 복사 같은 문자열 키 해석이 세 벌이 된다(중복 금지 원칙). 키 철자 하나가 틀리면 조용히 운영자 폴더를 지우는 종류의 결함이라 한 곳이어야 한다
D-3[그래도 등록] · [기존 영구 삭제 후 등록] 바꾸지 않는다. 기존 디렉토리 등록에서 이 두 선택은 운영자 폴더를 그 자리에서 자원으로 등록한다(영구 삭제 대상은 충돌한 다른 자원) — —
