§1. 현재 상태 (진단) — 마커 한 장이 거짓 해결됨 을 만든다

결함의 신원

MK4-2 진입 중 M 스트림이 샌드박스에서 실증한 결함이다. PathReconciliationService 의 삭제 자원 판정은 두 블록으로 되어 있다. 앞 블록은 디스크의 활성 트리를 순회하며 마커를 읽고, 뒤 블록은 소프트 삭제 자원을 전수 대조해 정상 보관 · 복귀 · 이탈 · 소실 · 유령을 판정한다. 문제는 두 블록이 하나의 억제 집합으로 연결된 방식이다.

  1. 앞 블록이 삭제 자원의 마커를 만나면 classifyEscape 를 호출하기 전에 그 자원의 키를 escapeReported 에 무조건 등록한다. 본체가 실제로 그 자리에 있는지 확인하지 않는다.
  2. 뒤 블록은 escapeReported 에 등록된 키를 통째로 건너뛴다. 그 자원에 대한 정상 · 복귀 · 소실 · 유령 판정 자체가 실행되지 않는다.
  3. classifyEscape 는 "원위치 + 본체 있음" 만 복귀로 판정하고 나머지 전부를 catch-all 로 SOFTDEL_ESCAPE_TO_OTHER(삭제 자원 위치 이탈)로 만든다. 본체가 없어도 그렇다.
  4. MK4-1 의 지속 모델에서 문제 신원은 (자원 종류 · 자원 번호 · 드리프트 종류) 3축이다. 그래서 억제된 원 판정(TRASH_LOST · GHOST_DB_ROW · SOFTDEL_ESCAPE_TO_ORIGINAL)은 이번 회차에 "관측되지 않음" 이 되어 SCAN_UNOBSERVED(점검에서 사라짐 — 자동 해소)로 닫힌다.
아무것도 변하지 않았는데 처리 이력에 해결됨 이 기록된다. 마커 한 장의 유무로 두 이름이 번갈아 열리고 닫히며 그때마다 해결 기록이 쌓인다. 복구 불능인 휴지통 소실이 이력에 해결됨 으로 적힌다.

409 영구 불능의 내용

첫 줄에서 해결(회수)을 실행하면 다음이 돌아온다 — "휴지통에 이미 이 자원의 사본이 남아 있어 회수를 진행할 수 없습니다. 휴지통의 기존 사본을 확인해 정리한 뒤 다시 점검하세요." 그런데 그 "기존 사본" 은 정상 보관된 자원 본체다. 안내대로 하면 자원을 잃고, 안 하면 경고가 영영 닫히지 않는다. 실제로 남은 일은 잘못 놓인 마커 한 장을 지우는 것뿐이다.

억제 자체는 무근거하지 않다 — 문제는 억제의 조건이다

본체가 정말 탈출했다면 빈 휴지통은 그 탈출로 설명되므로 TRASH_LOST 를 이중 보고하지 않는 것이 옳다. 즉 억제라는 장치가 틀린 것이 아니라, 억제를 본체 확인 없이 발동시키는 조건이 틀렸다. 올바른 원칙은 같은 파일에 이미 두 번 구현되어 있다.

  • PATH_DRIFT 판정(4b)은 마커를 발견한 뒤 본체를 별도로 확인해, 본체가 없으면 MISSING 으로 떨어뜨린다(주석 B-1).
  • TRASH_MARKER_STALE 은 "독립 신호 — 다른 판정과 무관하게 동시 보고 가능" 으로 선언되어, 마커 이상을 자원 상태 판정과 분리한다.

이 슬라이스는 새 원칙을 발명하는 것이 아니라, 이미 두 곳에서 지켜지는 원칙을 삭제 자원 판정에도 적용해 전수로 확정하는 일이다.

§2. 요구사항 (확정) + 비목표

목표

  1. 판정 진리표 기반 제어 흐름 재설계 — 자원 상태 축과 마커 신호 축을 독립 평가한 뒤 합성한다. 거짓 해결됨 이 소멸하고, 정상 보관 자원의 409 영구 불능이 해소된다.
  2. 미아 마커 종류 신설 — 본체 없이 발견된 삭제 자원 마커를 자원 상태 판정과 분리해 병행 보고한다.
  3. 승계 기록 계층 — 한 문제가 다른 종류로 재분류될 때 계보 링크 컬럼과 감지를 두어, 처리 이력이 "재분류로 이어짐" 을 사실대로 말하게 한다.
비 목표 (전부 토론에서 확정) :
  • 휴지통 수색 커버리지 — MK4-2 로.
  • 승계 계보의 화면 표시 — MK4-4 로. 본 슬라이스는 저장과 감지까지만 한다.
  • firstHit 다중 사본 순서 의존 — 이번에는 기록만 남긴다(HF4-5 가 의도적으로 scope 밖에 둔 영역).
  • 활성 자원의 마커 단독 사본(matchedMarkers 스킵으로 생기는 침묵 칸) — 진리표에 빈 칸으로 기록한 뒤 후속에서 판단한다.
  • staging · inotify 도입, DriftKind 전면 재설계 — 하지 않는다.

§3. 판정 · 기록 데이터 흐름 (엔드포인트 표면 변경 0)

제어 흐름 교체 (BEFORE / AFTER)

BEFORE — 두 블록 + 무조건 억제

[블록 1] 활성 트리 마커 순회
  if (마커 소유 자원이 soft-delete) {
      escapeReported.add(key);      // 본체 확인 없이 무조건
      report(classifyEscape(...));  // 나머지 전부 catch-all 이탈
  }

[블록 2] 삭제 자원 전수 대조
  for (자원 : softDeleted) {
      if (escapeReported.contains(key)) continue;  // 통째로 건너뜀
      ... 정상 / 복귀 / 소실 / 유령 판정
  }

[종결] closeUnobserved()
  관측되지 않은 문제 → SCAN_UNOBSERVED
  억제된 원 판정이 여기서 거짓 해결됨이 된다

AFTER — 두 축 독립 평가 + 합성

[축 1] 자원 상태 = classifyResourceState(
          휴지통 기록, 휴지통 실물, 원위치 본체)   // A ~ F

[축 2] 마커 신호 = classifyMarkerSignal(
          발견 위치, 그 위치 본체)                 // ⓜ0 ~ ⓜ3

[합성] verdicts = compose(자원 상태, 마커 신호)
  규칙 1 : 본체 없는 마커는 상태 판정을 건드리지 않고 병행
  규칙 2 : 본체 동반 발견은 "부재" 판정만 대체
  규칙 3 : 원위치 마커는 복귀 판정의 증거로 합류

[종결] closeUnobserved()
  같은 회차 승계 감지 → SUPERSEDED + predecessor 기록
  아니면 SCAN_UNOBSERVED (기존 동작 유지)

escapeReported 는 폐기하지 않는다. 규칙 2 가 지정한 대체 칸(상태 F · B 에서 본체가 타위치에서 발견된 경우)으로 한정해 남긴다. 억제 장치는 그 칸에서만 정당하다.

합성 규칙 3 개 (전 칸이 여기서 도출된다)

규칙 1

본체 없는 마커(ⓜ3)는 자원 상태 판정을 절대 건드리지 않는다. 자원 상태 판정을 그대로 내고, SOFTDEL_MARKER_STRAY(미아 마커, 신설)를 병행 보고한다.

규칙 2

본체 동반 발견(ⓜ2)은 자원 상태의 "부재" 를 설명할 때만 그 판정을 대체한다. 상태 F(소실)와 B(유령)는 본체가 어디에도 없다는 판정인데 타위치에서 본체가 발견됐으므로 이탈 SOFTDEL_ESCAPE_TO_OTHER 가 대체한다 — escapeReported 억제가 정당한 유일한 이탈 칸이다. 상태 A · C · D · E 는 본체 부재 판정이 아니므로 대체하지 않고 이탈을 병행 보고한다(복귀와 사본이 동시에 실재하는 사실 그대로).

규칙 3

원위치 마커(ⓜ1)는 복귀 판정(A · E)에 증거로 합류할 뿐 새 판정을 만들지 않는다. 원위치 본체가 없으면 ⓜ3 으로 귀결된다(미아 마커).

결정 1 — 판정 제어 흐름

ⓐ 진리표 합성

채택. 자원 상태 축과 마커 신호 축을 독립 평가한 뒤 (상태, 신호) → 판정 목록 함수로 합성한다. 전수 확정이 가능하고, 테스트가 칸과 1:1 이며, 빈 칸이 눈에 보인다.

ⓑ 현행 순차 분기 패치

탈락. 결함 칸에만 조건을 추가하는 방식. 이번 사고의 형태가 바로 case 별 때우기의 누적이므로, 다음 빈 칸을 또 못 본다.

ⓒ score 기반

기본 설계 비채택(토론의 사용자 착안). score 는 증거가 흐릿할 때 "가장 그럴듯한 하나" 를 고르는 도구다. 이 도메인의 판정 입력은 전부 관측 가능한 이진 사실이라 흐릿함이 없고, 겹침의 1차 해소책은 병행 보고와 축 추가다. 또 "왜 이 판정인가" 에 "점수가 높았다" 로만 답해 신뢰 기준 ⓑ(사실과 다른 줄이 없는 감사 기록)와 충돌하며, 보정할 실사용 데이터도 없다. 진리표 확정 후에도 해소 불가능한 확률적 모호가 실재하면 재검토(D11).

④invariant 위반 칸의 보수 판정이 소음을 만든다로그 경고로 관측한 뒤, 실재하면 별도 종류 신설을 검토한다
