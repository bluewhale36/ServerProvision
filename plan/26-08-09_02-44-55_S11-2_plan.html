남은 문제 — 정당한 재분류의 계보 단절

한 자원에 생긴 하나의 사건이 점검 회차 사이에 다른 종류의 문제로 모습을 바꾸는 일이 있다. 운영자가 사라진 본체를 원위치에 되돌리면, 다음 점검에서 소실 문제는 더 이상 관측되지 않고 복귀 문제가 새로 열린다. 두 기록 모두 그 자체로는 사실이지만, 시스템에는 둘이 같은 사건의 앞뒤라는 표시가 없다.

실증 사례 — S11-1 CP5 의 A5 : 자원 7 의 미아 마커 문제가 SCAN_UNOBSERVED(점검에서 사라짐 — 자동 해소)로 닫히고, 같은 회차에 복귀 문제가 새로 열렸다. 화면상 두 줄은 서로 무관한 사건으로 보이며, 후임 문제의 관측 횟수와 최초 발견 시각이 1 로 리셋된다. 운영자가 "이 문제가 언제부터 있었나" 를 물으면 답이 4일 전이 아니라 오늘이 된다.

왜 이렇게 되는가 — 문제 신원이 3축이기 때문

MK4-1 이 정한 문제 신원은 (자원 종류 · 자원 번호 · 드리프트 종류) 3축이다. 종류가 신원의 일부라서, 종류가 바뀌면 시스템의 눈에는 같은 문제의 변화가 아니라 별개 문제의 닫힘 + 별개 문제의 열림으로 보인다. 신원 정의를 2축으로 낮추면 서로 다른 문제가 한 줄에 뭉개지므로, 신원은 그대로 두고 줄과 줄 사이를 잇는 링크를 따로 두는 것이 이 슬라이스의 방향이다.

왜 지금 S11 안에서 하는가 : 승계 기록은 계보 링크 컬럼이라는 스키마 변경을 동반한다. 스키마를 건드리는 일은 판정 정합 캠페인(S11)이 열려 있는 동안 한 번에 처리하고, 화면 표시는 사용성 캠페인(MK4-4)으로 넘기는 것이 S11 토론 D8 의 확정 사항이다.
§2. 요구사항 (확정) + 비목표
  1. 계보 링크를 저장한다. drift 테이블에 predecessor_drift_id(BIGINT NULL) 컬럼과 자기 참조 외래키를 두고, 후임 행이 전임 행을 가리킨다(링크 방향 후임 → 전임 — S11 우산 plan §8 확정).
  2. 재분류를 자동 감지한다. 점검 회차에서 관측되지 않아 닫히는 문제 d 에 대해, 같은 회차 관측 목록에서 같은 자원 신원 그리고 다른 드리프트 종류 그리고 이번 회차에 새로 열린 문제 n 을 찾는다.
  3. 찾으면 두 가지를 함께 기록한다. ① n 의 계보 링크에 d 를 기록한다(비어 있을 때만) ② d 를 SCAN_UNOBSERVED 가 아니라 SUPERSEDED 로 닫는다.
  4. 계보 링크는 최초 1회만 할당된다. 이미 값이 있으면 덮어쓰지 않는다 — 이력은 사후에 바뀌지 않아야 한다는 불변 원칙.
  5. 처리 이력의 문구가 사실과 일치해야 한다. 재분류로 이어진 문제에 "점검에서 사라짐 — 자동 해소" 라고 적히지 않게 한다(S11 토론의 신뢰 기준 ⓑ).
  6. 화면은 바꾸지 않는다. 실측 정정(CP5) — 닫힘 액션(resolvedBy)과 그 라벨은 현재 어떤 화면 · 응답에도 노출되지 않는다(해결 주체의 표시 자체가 MK4-4 소관). 따라서 액션 추가는 화면에 아무 변화도 만들지 않으며, 라벨 문구의 계약은 단위 테스트(U8)로 고정한다.
비 목표 :
  • 계보의 화면 표시(전임 · 후임을 잇는 타임라인, "이 문제는 4일 전 소실에서 이어졌습니다" 안내) — MK4-4 로 넘긴다. 본 슬라이스가 남기는 것은 데이터뿐이다.
  • 과거 파동의 소급 복원 — 반영 시점 이후의 점검 회차부터 계보가 쌓인다. S11-1 이 관측한 1회성 재분류를 포함해 그 이전 기록은 손대지 않는다(사후 조작 금지).
  • 다대다 계보(전임 여러 개를 한 후임에 매다는 중간 테이블) — 실사용 관찰 전의 조기 일반화. D-2 참조.
  • 드리프트 종류 자체의 신설 · 개명 — 종류 목록은 현행 그대로다. 이번에 늘어나는 것은 처리 액션 한 종류뿐이다.

도메인 메서드 — 최초 1회 고정

// Drift : 계보 링크는 한 번 정해지면 바뀌지 않는다 (이력 불변)
public void linkPredecessor(Drift predecessor) {
    if (this.predecessor != null) return;   // 이미 있으면 불변 — 덮어쓰지 않는다
    this.predecessor = predecessor;
}

재할당을 예외로 거절하지 않고 조용히 무시하는 이유는, 이 경로가 사용자 액션이 아니라 점검 루프 내부라서다. 같은 회차에 후보가 여러 번 평가되더라도 첫 결정이 유지되면 충분하고, 여기서 예외를 던지면 점검 전체가 한 자원 때문에 중단된다. 예외는 진짜 비정상에만 쓴다는 원칙의 적용이다.

열린 문제 ──점검에서 미관측 + 후임 있음──▶ 닫힘 (SUPERSEDED) ← 후임이 predecessor 로 이 행을 가리킴 열린 문제 ──점검에서 미관측 + 후임 없음──▶ 닫힘 (SCAN_UNOBSERVED) ← 종전 동작 그대로

스키마 변경이 필요 없는 부분

처리 액션은 문자열로 저장되고 컬럼이 VARCHAR(32) 이므로, 10 자인 SUPERSEDED 를 넣는 데 DDL 이 필요 없다. 이번 DDL 은 계보 링크 컬럼 한 건뿐이다.

§8. 부산물 / 주의 / 결정 사항

경계 결정 — 채택안과 탈락 사유

D-1 후임 다수

상황 — 같은 자원에 신규 종류가 2 개 이상 열림.

  • 채택 : 신규 전부가 같은 전임을 가리킨다(fan-out). 링크 컬럼이 후임 쪽에 있어 별도 구조 없이 자연히 지원된다.
  • 탈락 : 하나만 골라 링크 — 택일 근거가 없고 나머지 후임의 계보가 사라져 정보 손실이다.

D-2 전임 후보 다수

상황 — 같은 자원의 열린 문제 여러 개가 같은 회차에 닫히고 신규 1 개가 열림.

  • 채택 : 후임의 전임은 1 개. lastObservedAt 이 가장 최신인 전임을 고른다 — 닫힘 처리 순서에 의존하지 않는 결정성을 얻는다. 나머지는 종전대로 SCAN_UNOBSERVED.
  • 탈락 : 다대다 중간 테이블 — 실사용 관찰 전의 조기 일반화다("갈라지는 시점에 분리" 원칙). 필요성이 실증되면 MK4-4 시점에 재평가한다.

D-3 전임의 닫힘 액션

상황 — 승계로 닫히는 전임을 무엇으로 기록할 것인가.

  • 채택 : SUPERSEDED 신설. 처리 이력은 사실과 다른 줄을 담지 않아야 한다는 S11 토론의 신뢰 기준 ⓑ 를 따른다.
  • 탈락 : SCAN_UNOBSERVED 를 유지한 채 링크만 기록 — "점검에서 사라짐 — 자동 해소" 라는 문구가 재분류라는 사실을 가린다. 데이터는 맞는데 화면이 거짓말하는 상태가 된다.

Open Questions (CP1 결정 요청)

#질문권고
Q1 D-2 의 동률 처리 — 점검 회차 의미상, 같은 회차에 함께 닫히는 전임들은 직전 회차에 함께 관측되었을 가능성이 높아 lastObservedAt 이 같아지는 경우가 흔하다. 이때 무엇으로 하나를 고를 것인가. 확정(2026-08-09 CP1 승인) — 2 차 정렬키로 drift 식별자 오름차순(= 먼저 열린 전임). 근거는 ① 같은 회차라면 "먼저 시작된 사건" 이 계보의 뿌리에 가깝고 ② 식별자는 재실행해도 변하지 않아 결정성이 보장되기 때문이다. 검토된 대안(해결 인과 기반 배정)은 병행 드리프트 해결의 순서 의존성(공유 자원 row · 실물 매개, 선행 해결이 후행 해결을 409 로 만듦)과 전임 풀 구조(APPLY 로 닫힌 문제는 풀에 없음) 때문에 비채택 — 그 순서 의존성 자체는 R 전수 감사 입력으로 등재했다.

기확정 사항 — 재론하지 않고 참조만

  • 저장형(도출형 · note 문자열 대신 컬럼) — S11 우산 plan §8.
  • 링크 방향은 후임 → 전임 — 같은 곳. fan-out 을 구조 변경 없이 담을 수 있는 것이 이 방향의 이득이다(D-1 과 맞물린다).
  • 기록과 표시의 분리 — S11 토론 라운드 3 · D8.
  • 후임의 관측 횟수 · 최초 발견 시각은 물려받지 않는다 — S11 토론 라운드 3 에서 확정("연속은 별도 컬럼 없이 링크 사슬을 따라가며 계산 — 데이터 이관 불요"). 그 값들은 "이 종류의 문제가 언제부터 관측되었나" 라는 사실이라 덮어쓰면 다른 거짓이 되고, 사용자가 원하는 "이 사건이 언제 시작되었나" 는 계보를 거슬러 올라가 표시 계층(MK4-4)에서 합산한다.

위험 — 적대적 자기 비판

  1. 외래키 RESTRICT 의 대가 : 앞으로 drift 행을 하드 삭제하는 경로(보존 기간 정리 등)가 생기면 제약 위반으로 실패한다. 이것은 결함이 아니라 의도된 시끄러움이다 — 계보가 조용히 끊기는 것보다 낫다. 삭제 정책이 실제로 필요해지는 시점에 CASCADE · SET NULL · 소프트 정리 중 무엇을 쓸지 다시 결정한다.
  2. 같은 회차 다중 재분류의 순서 의존 : D-2 의 lastObservedAt 규칙으로 선해소했다. 남은 동률 문제는 Q1 로 올렸다 — 이 부분을 승인 없이 임의 구현하지 않는다.
  3. 소급 없음 : 계보는 반영 이후의 점검부터 쌓인다. S11-1 이 관측한 1 회성 재분류를 포함한 과거 파동은 링크가 비어 있다. MK4-4 의 화면은 링크가 없는 것이 정상인 행을 자연스럽게 다뤄야 한다.
  4. 감지 조건이 너무 넓지 않은가 : 같은 자원에 무관한 두 문제가 우연히 같은 회차에 하나는 닫히고 하나는 열리면 잘못된 계보가 그어질 수 있다. 다만 그 경우에도 같은 자원이라는 사실은 참이고, 링크는 표시 계층에서 참고 정보로 쓰일 뿐 어떤 자동 조치도 유발하지 않는다. 조건을 더 좁히는 것(예: 종류 쌍 화이트리스트)은 오탐보다 미탐이 더 나쁜 이 맥락에서 이르다고 판단했다 — MK4-4 에서 실사용 관찰 후 재평가한다.
