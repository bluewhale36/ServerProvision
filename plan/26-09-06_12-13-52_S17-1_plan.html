§0. 승격 동기 — 실험 시트를 원본 소스로

디자인 실험(방향안 C)은 34 화면 전수에서 성립해 디자인으로 검증됐다(근거 sbx-design/UX-sweep.md · 스크린샷 64). 이제 실험을 원본 소스로 승격한다 — 실험 시트 experiment-c.css(533줄)를 걷어내고, 그 결정을 원본 style.css 본문과 layout.html 마크업으로 옮긴다.

왜 실험 시트 그대로는 안 되는가

experiment-c.css 는 페이지 CSS 12벌 뒤에 실려 명시도로 이기는 오버레이다 — :root 접두 128 규칙 · !important 5 · build-app-css.sh 생성물(손수정 금지). 이 구조 자체가 부채다.

  1. :root 접두는 "페이지 CSS 를 이기려고" 붙인 것이라 정본에서는 불필요하고 오히려 명시도를 왜곡한다.
  2. 생성물이라 사람이 못 고친다.
  3. 실험이 명시도로 덮어 가린 탓에 규칙 충돌(결함)이 드러나지 않았다.

승격은 :root 접두를 떼고 style.css 본문과 정면으로 정합을 맞추는 것이다. 그 과정에서 가려져 있던 결함 6이 표면화한다 — 이 슬라이스가 그 여섯을 함께 정정한다.

핵심 원칙 (불가침) — 화면 특수 규칙은 전역 시트가 아니라 해당 템플릿의 국소 클래스로 내린다. 결함 6 가운데 넷이 "한 화면 규칙이 전역 시트로 새어 나가 다른 화면을 오염" 시킨 것이다. 승격의 방향은 전역을 국소로다.
이 슬라이스가 하는 일 다섯 — ① 슬레이트 팔레트 · 토큰을 style.css :root 로 흡수 ② 격자선 표 · 반지름 2값 · 그림자 0 을 각 섹션 본문으로 흡수(접두 제거) ③ 사이드바를 .n-shell 한 겹으로 ④ 결함 6 정정 ⑤ 앱 최초 @media(1024) 도입. 더해 .n-btn-outline 를 정식 정의하고 DESIGN.md 를 같은 PR 에서 개정한다.
§1. 현재 상태 (진단)

1-1. 오버레이 구조 — 무엇이 지금 렌더를 이기는가

실화면은 지금 페이지 CSS 12벌 + 실험 시트 1벌이 순서대로 실려, 뒤에 실린 experiment-c.css 가 명시도(그리고 필요하면 !important)로 앞을 덮는 구조다. 방향안 C 의 모든 결정 — 슬레이트 팔레트 · 격자선 표 · 반지름 2값 · 그림자 0 · 사이드바 배치 — 이 그 한 벌 안에 있고, 규칙마다 :root 접두가 붙어 명시도를 인위로 올려 두었다.

1-2. 승격 브랜치에는 실험 시트가 없다

experiment-c.css 와 그것을 거는 layout.html 의 <link> 는 실험(refine)에만 있고 승격 브랜치 refactor/S17-1 에는 없다(origin/dev 973a015 기준). 승격은 깨끗한 dev 위에서 실험 시트의 결정을 옮겨 적는 일이지, 실험 파일을 병합하는 일이 아니다. 따라서 결과물에 오버레이 · 접두 · 생성물이 남지 않는다.

1-3. 실험이 가려 온 결함 6

오버레이가 명시도로 이겨 온 탓에, 아래 여섯은 실험 화면에서 "정상으로 보였"거나 실험 시트가 애초에 안 덮어 방치돼 있었다. 접두를 떼고 본문과 정합하는 순간 표면화하므로 승격과 함께 정정한다(상세 · 처방은 §4 D2).

§2. scope (확정) · 비목표

배포창 9/15~30 전 목표다. 순수 CSS · 템플릿 리팩터이며 도메인 · 엔티티 · URL 은 건드리지 않는다.

  1. 슬레이트 팔레트 · 토큰을 style.css :root 로 흡수(경고색 재정의 포함).
  2. 격자선 표 · 반지름 4px / 6px 2값 · 그림자 none 을 각 섹션 본문으로 흡수(:root 접두 제거).

  4. 결함 6 정정(§4 D2).
  5. 1024 반응형(결정 ③) — 앱 최초 @media 도입(현행 ≤900px 만). Miller · 서버 목록 · /system/asset 탭 스트립.
  6. .n-btn-outline(bare) 정식 정의 + 마커 회수(실험 시트 주석 제거).
  7. DESIGN.md 전면 개정 — S17-1 CP4 산출물에 포함(코드 + 문서 한 PR · 드리프트 방지 — 앵커 지침).

§3. 이식 지도 · 데이터 흐름 (URL 변경 0)

새 URL 도 없고 데이터 흐름도 바뀌지 않는다. 이 슬라이스가 옮기는 것은 CSS 규칙과 마크업 래퍼이며, 컨트롤러 · 서비스 · 응답은 그대로다. 그래서 §3 은 요청 흐름 대신 이식 지도 — 실험 시트의 어느 규칙이 style.css 의 어느 섹션으로 가는지 — 를 담는다.

§4. 설계 결정 D1~D4 (SSOT) — 엔티티 · DDL · URL 변경 0

새 엔티티도 새 값 객체도 없다. 결정 넷은 전부 CSS 규칙과 템플릿 래퍼에 관한 것이다 — 사이드바를 어떻게 감쌀지(D1) · 결함 6 을 어떤 처방으로 정정할지(D2) · 1024 반응형을 어떤 거동으로 켤지(D3) · .n-btn-outline 를 어떻게 정식화할지(D4).

D1 — 사이드바 = .n-shell 한 겹 (결정 ① 확정)

채택은 layout.html 의 <body> 직속을 <div class="n-shell"><nav>…</nav><div class="n-shell-main">…본문…</div></div> 로 감싸는 것이다. nav 와 본문이 flex 형제가 되어, 모달 오버레이(position:fixed)가 뷰포트 전체를 덮으므로 보정이 필요 없다.

안요지결과
.n-shell 래퍼nav · 본문을 flex 형제로채택 모달 fixed 가 전체를 덮어 보정 불요 · 사용자 선택
body padding 228px실험 방식 — 마크업 0탈락 .cm-overlay / .gem-overlay 에 margin-left:-228px 보정이 영구히 필요 · 정본에 군더더기
미해결 — CP2 실측 항목 : .n-shell 래퍼를 어디에 두는가는 현행 layout.html 구조에 달렸다. 공용 레이아웃 fragment 가 있으면 거기에, 없어 페이지마다 <body> 안에 navbar fragment + 본문을 직접 넣는 구조라면 대안 — 래퍼 대신 body { display:flex } 로 body 자체를 shell 로 삼는다. plan 에서 확정하지 않고 CP2 에서 구조를 실측해 정한다(§8 Open Question OQ-1).

④의 .n-badge-off 신설이 배지 클래스를 하나 늘리지만, "비활성" 과 "정의서 지정(정보)" 이 같은 클래스를 공유하던 것이 더 큰 문제였다. 순증 1 클래스로 뜻 충돌을 해소한다(적대적 비판 §8 참고). ⑤는 이 슬라이스에서 판 · 격자 · 탭스트립만 걸고, asset.css / diagnostic-asset.css 어휘 흡수는 S17-3 으로 넘긴다 — churn 이 S17-3 과 겹치지 않게 경계를 여기서 못박는다.

D3 — 1024 반응형 (앱 최초 @media) : 브레이크포인트 · 사이드바 · Miller

현행 앱에는 @media 가 ≤900px 밖에 없다. 방향안 C 의 지원 하한을 1024 로 잡았으므로 그 지점에서 반응형을 켠다. 세 축을 각각 대안 비교로 결정한다.

§7. 예외 계층 — 신규 0

신규 예외 클래스가 없으므로 .claude/domain-conventions/new-exception.md 의 관문은 열지 않는다. 이 슬라이스는 CSS 규칙과 마크업 래퍼만 바꾸며, 예외를 만들지도 삼키지도 않는다.

  • CSS · 템플릿 — 색 토큰 · 격자 · 반지름 · 사이드바 · @media · 배지 클래스는 서버 판단이 개입하는 자리가 아니다. 던지는 예외가 없다.
  • 거절 경로 — 400 · 404 · 409 · 500 의 매핑은 기존 advice 그대로다. 폼 · 상태 변경 경로의 예외 흐름은 손대지 않으며, 그 회귀 없음을 §6 이 가드한다.
예외 계층이 그대로라는 사실은 이 리팩터가 표현(presentation)만 손댄다는 것을 뒤에서 확인해 준다. 도메인 판정이 바뀌었다면 여기에 무언가 적혔어야 한다.
