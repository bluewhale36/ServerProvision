§1. 현재 상태 (진단)

실기 3호(2026-09-08)에서 정상 종료(Redfish GracefulShutdown)를 세 번 발행했다. BMC 는 세 번 모두 Task 를 만들었고(state=null) 화면은 200 을 받았지만, 호스트는 꺼지지 않았다. 결국 매번 [강제 끄기] 로 끝냈고 그날 종료 7 건이 전부 강제였다.

시각대상결과
18:06웨이브Task 생성 · 호스트 무반응 → 강제 끄기
18:08사이버 성우동일
18:46일산 상2동일

원인 둘

  1. 호스트에 받는 쪽이 없다. 정상 종료는 BMC 가 ACPI 전원 버튼을 누르는 것이라 호스트 OS 가 그 이벤트를 받아 스스로 꺼야 한다. 진단 리눅스(Alpine)에는 acpid 가 없었다 — apkovl/etc/apk/world 에도, 런레벨에도 부재.
  2. 화면이 결과를 모른다. server-power.js 는 E1.5 의 결정 D4(화면 경로는 폴링하지 않는다)에 따라 발행 결과만 표기하고 [상태 조회] 로 잇게 돼 있다. 운영자는 "전달됐지만 무시된 것" 과 "곧 꺼질 것" 을 구분할 수 없었다.
F-10 — 발행은 성공(200)인데 결과는 실패다. 응답 코드가 조작의 성패를 말해 주지 않는 상황이라 운영자는 매번 60초쯤 지켜보다 포기하고 강제로 껐다.

진입 전제 — E1.5(Redfish 전원 제어 · PowerControlResult · RedfishResetType)와 E1-1(진단 자산 조립 build-assets.sh)이 완료돼 있다. 서버의 발행 경로는 그대로 두고 화면과 진단 이미지만 손댄다.

§2. 요구사항 (확정) + 비목표
  1. 정상 종료를 발행하면 화면이 스스로 결과를 확인한다 — GET …/power 를 5초 간격으로 최대 60초.
  2. 시한 안에 Off 를 보면 "정상 종료가 완료됐습니다 (PowerState Off 확인)." 로 확정하고 감시를 멈춘다.
  3. 시한을 넘기면 무응답임을 문장으로 알리고 — 전원 버튼을 처리하는 OS 가 없는 상태(진단 리눅스 · 설치 화면 · UEFI 셸)일 수 있다고 짚고 — [강제 끄기] 를 n-btn-outline-danger → n-btn-danger 로 강조한다(기존 클래스 재사용 · 신규 CSS 0).
  4. 발행 자체가 실패하면(kind=FAILED) 감시를 시작하지 않는다.
  5. 다른 전원 명령을 누르거나 정상 종료를 다시 누르면 진행 중이던 감시를 멈추고 강조를 되돌린다.
  6. 진단 리눅스는 전원 버튼에 응답한다 — acpid 를 world 에 넣고 button/power → poweroff 핸들러를 가방에 동봉해 기본 런레벨에 올린다.
비 목표 :
  • 서버가 폴링해 결과를 확정하는 것 — E1.5 D4 를 유지한다(화면 경로에 60초 블로킹 금지).
  • 시한이 지났을 때 자동으로 강제 끄기로 넘어가는 것 — 파괴적 조작은 운영자 확인(confirm 모달)을 거친다.
  • Windows 설치 화면 · UEFI 셸이 전원 버튼에 응답하게 만드는 것 — 우리가 못 고친다. 안내로 덮는다.
  • 감시 간격 · 시한(5초 · 60초)의 설정화 — 상수로 고정하고 실기 관측 뒤 재검토(§8 Q3).

§4. 도메인 모델 (SSOT)

설계 대안 비교

안요지판정
A 서버 폴링Graceful 발행 뒤 서버가 60초 PowerState 를 확인하고 FAILED 로 확정탈락 — 결과는 정확하지만 E1.5 D4 가 금지한 60초 블로킹을 화면 경로에 얹는다
B 화면 감시서버는 단발 유지 · JS 가 5초 × 60초 지켜보고 Off 면 확정, 아니면 안내채택
C 이미지 수정진단 리눅스에 acpid 를 넣어 실제로 응답하게단독으로는 탈락 — Windows 설치 화면 · UEFI 셸은 여전히 무응답이라 안내가 필요하다
채택 = B + C — 안내(B)로 모든 상태를 덮고, 우리가 고칠 수 있는 상태(C)는 실제로 고친다. 둘은 겹치지 않는다: B 가 없으면 Windows 에서 여전히 깜깜하고, C 가 없으면 진단 리눅스는 영원히 안내만 받는다.

계약 ② ACPI 이벤트 (진단 이미지)

etc/acpi/events/power   event=button/power.*  →  action=/etc/acpi/handler.sh %e
etc/acpi/handler.sh     case button/power) logger -t provision-acpi … ; /sbin/poweroff

핸들러는 전원 버튼만 처리하고 나머지 이벤트는 무시한다. logger -t provision-acpi 로 실기에서 호출 여부를 직접 확인할 수 있다.

Primitive Obsession — 신규 엔티티 필드 · Value Object · Enum 이 0 이다. 재사용하는 도메인 타입은 RedfishResetType.GRACEFUL_SHUTDOWN 과 PowerControlResult(kind · powerState · message) 이며, 감시 간격 · 시한은 화면 스크립트 상수라 타입화 대상이 아니다.

주의
