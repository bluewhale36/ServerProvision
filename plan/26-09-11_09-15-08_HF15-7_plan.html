§1. 현재 상태 (실기 4호 실측)

결함 ① — 되읽기 오류 한 번이 축을 통째로 실패시킨다

실기 4호(2026-09-10 10:37 · 10:38) 사이버 웨이브에서 BeginBmcSettingStep 이 COLD_REDUNDANT 항목을 쓴 뒤 되읽기 GET /api/cold_redundant-status 를 호출했고, BMC 가 {"error":"Error in Getting Cold Redundant Status","code":1334} 를 돌려줬다. 현재 BmcSettingItem.apply 는 DATA_REJECTED 와 PROTOCOL 을 항목 REJECTED 로 바꾸고, 단계는 REJECTED 를 WRITE_REJECTED 로 읽어 축을 실패시킨다.

같은 요청이 10:46 세 번째 시도에서 통과했다 — 값이 거절된 것이 아니라 읽기가 일시적으로 실패한 것이었다. 그런데도 축이 닫혀 사용자가 [재시도] 를 2 회 눌러야 했다.

결함 ② — 전원 제어 섹션이 새로고침 전까지 "BMC 미검출" 로 남는다

#powerControlSection 은 페이지 로드 시 bmcDetected 로 버튼과 "BMC 미검출" 문구를 서버가 렌더한다. 상세 페이지는 SSE(server-stream.js)가 신호를 받으면 [data-live] 영역만 다시 받아 교체하는데, 이 섹션에는 data-live 가 없다. 그래서 진단이 BMC 를 찾아도 화면은 그대로다(실기 4호 사용자 지적).

server-power.js 는 DOMContentLoaded 에 섹션 안 버튼으로 리스너를 직접 붙이고, 정상 종료 감시(watchGen · 타이머)는 클로저 상태다. 즉 영역을 교체하면 리스너가 사라진다 — 속성 하나만 붙이는 것으로는 끝나지 않는다.

§2. 요구사항 (확정) + 비목표
  1. 되읽기 오류는 축을 실패시키지 않는다. 항목 결과를 TRANSIENT 로 두고 행을 RUNNING 으로 유지해 다음 워커 주기에 다시 시도한다.
  2. 3 회까지만 기다린다. 3 회째에는 그 항목만 SKIPPED:되읽기 오류 3회 — <detail> 로 남기고 다음 항목으로 계속한다. 종결 요약에 "COLD_REDUNDANT 건너뜀(…)" 이 실린다.
  3. 쓰기 단계의 값 거절은 종전대로 즉시 실패. 쓰기 DATA_REJECTED(예: 1010 Invalid Data)는 REJECTED → WRITE_REJECTED.
  4. 전원 제어 섹션은 새로고침 없이 갱신된다. #powerControlSection 에 data-live="power" 를 붙이고, server-power.js 를 문서 위임으로 바꿔 교체 후에도 버튼이 동작한다.
비 목표 :
  • 쓰기 단계의 DATA_REJECTED 는 관용하지 않는다 — 값 거절은 정의서 · 자원 문제이지 일시 오류가 아니다.
  • 전원 상태 자체를 SSE 로 밀어 주지 않는다(E1.5 D4 단발 조회 유지). 갱신되는 것은 "BMC 검출 여부에 따른 섹션 렌더" 뿐이다.
🎬 미리보기 — 워커 주기 시뮬레이터

4 항목을 순서대로 처리하는 워커 주기를 재현합니다. COLD_REDUNDANT 의 쓰기 · 되읽기 결과를 고른 뒤 [워커 주기 실행] 을 누르면 원장 meta(items · retries)와 행 상태가 바뀝니다. 판정 JS 는 §4 의 D-1 · D-2 와 같은 규칙입니다(드리프트 0). 판정 규칙 축을 "대조 — 옛 동작" 으로 두면 실기 4호의 실패가 그대로 재현됩니다.

§8. 예상 부산물 / 주의 / 결정
  • 재개 멱등 전제 — 다음 주기는 기존 재개 규약대로 항목을 처음부터 다시 쓴다. 즉 재시도는 "되읽기만" 이 아니라 "쓰기 + 되읽기" 를 되풀이한다.
  • 시한과의 관계(D-3) — 재시도가 축 시한 안에서 돌기 때문에, 시한이 먼저 끝나면 종전 경로로 닫힌다. 시한 판정 로직은 이번에 손대지 않는다.
  • 클로저 감시 상태 — 위임 전환 후에도 watchGen · 타이머는 남는다. 영역 교체 중 감시가 돌고 있으면 다음 틱이 문구를 복원하는지 CP5 C1 에서 확인한다.
  • DDL 0 · env 0 — 원장 meta 는 기존 저장 구조를 쓰므로 스키마 · 환경변수 변경이 없다.
