목표 공급 SPI 가 나르는 값

WindowsInstallationResolutionProviderImpl 이 활성 할당 스냅샷의 WindowsInstallationRequest(imageName · Administrator 비밀번호 · 상위 osMetadataId)에서 WindowsInstallTarget(imageName, password) 를 만든다. OS 이름 · 버전은 아직 나르지 않는다 — 선별이 서려면 이 값이 먼저 필요하다.

WindowsInstallTemplates 의 autounattend 는 specialize 패스에서 ComputerName · TimeZone 만 다루고, oobeSystem 의 FirstLogonCommands 가 표식 파일과 spv-report.ps1 -BaseUrl -Token 을 실행한다. 토큰은 완료 보고 때 회수된다(메모리 레지스트리).

선행 R15-1 이 놓고 간 것 (CP6 완료 · 미커밋)

  • Subprogram.osName(nullable OSName) — null 이면 OS 무관
  • SubprogramVariant — osVersion nullable(전 버전 와일드카드) · entrypointRelativePath · arguments · rebootRequired · sortOrder · versionKey()(trim + 소문자) · entrypointKind()
  • 실 DB — MS04-CE0 = ASPEED(변형 2025 msi) · Chipset · QAT(변형 없음) / MS74-HB0 = Chipset(변형 없음). 전부 WINDOWS_SERVER
  • 게스트 보드는 진단이 적재한 GuestServerDetail.boardModel, 정의서 OS 는 OSMetadata(osName, osVersion)
핵심 결손 — 선언은 끝났는데 소비처가 없다.
  • 변형(MSI · EXE)은 R15-1 이 적을 수만 있게 했고 실행하는 쪽이 없다. SetupComplete 은 INF 밖을 모른다.
  • $OEM$ 은 보드 · OS 를 보지 않고 전부 싣는다 — MS74 전용 드라이버가 MS04 게스트에도 실린다.
  • INF 가 없는(MSI 전용) 패키지는 아예 실리지 않아 $OEM$ 에 존재조차 하지 않는다(INF_MISSING 제외).
§2. 요구사항 (확정) + 비목표
  1. 서버가 고른다 — Windows 설치 서빙 시점에 게스트의 보드 모델과 정의서의 대상 OS(OSMetadata 의 osName · osVersion)로 설치할 드라이버 항목을 서버가 판정한다. 게스트는 판단하지 않고 목록만 따른다(R15 토론 Q4 = (c)).
  2. 변형이 있는 패키지는 버전 일치 변형 하나, 없으면 전 버전 변형 하나. 둘 다 없으면 그 패키지는 설치하지 않는다.
  3. 변형이 없는 패키지는 종전대로 트리 전체 INF(TREE) — 현행 동작을 보존한다.
  4. 게스트별 번들 파일 spv-drivers.lst 로 목록을 내주고, SetupComplete.cmd 가 그 목록만 진입점 확장자별(INF pnputil · MSI msiexec · EXE 직접)로 실행한다.
  5. 목록이 없으면 막지 않는다 — 토큰 소멸 · 네트워크 문제로 목록을 못 받으면 SetupComplete 이 현행(전체 INF)으로 내려간다. 설치 자체는 진행된다.
  6. $OEM$ 은 전체를 싣는다 — 게스트별로 가르지 않되, 대상에 변형만 있는(INF 없는) 패키지를 더한다. 선별은 서빙 시점의 목록이 한다.
  7. 선택 · 제외 사유가 남는다 — 원장 openServed meta 와 게스트 상세 Windows 카드에. 제외는 사유와 함께 보인다.
  8. 실행 결과가 돌아온다 — 첫 로그온 보고가 행마다의 exit code 를 실어 오고, 상세 카드가 "설치 실행 N · 실패 M" 으로 보인다.
  9. 준비도는 막지 않는다 — 드라이버가 0 개로 판정돼도 설치는 진행하고 안내만 한다.

§4. 도메인 모델 (SSOT)

대상 OS 의 전달 (D-1)

record WindowsInstallTarget(WindowsImageName imageName, String administratorPassword,
                            String unsupportedFamily, OsTarget osTarget)

record OsTarget(OSName osName, String osVersion)     // 메타 부재 · 삭제면 target.osTarget == null

WindowsInstallationResolutionProviderImpl 이 스냅샷의 osMetadataId 로 OSMetadataRepository 를 조회해 채운다. 메타가 없거나 삭제됐으면 null 이고, 그때 변형 매칭은 전 버전 변형만 본다.

선택 진리표 — WindowsDriverSelection (신규 · 의존 0 정적)

Selection select(Long boardId, OsTarget osTarget, List<Subprogram> candidates, WindowsOemManifest manifest)

record Entry(Long id, String name, String folder, Mode mode,
             String entrypoint, String arguments, boolean rebootRequired)   // entrypoint 는 Windows 경로(\)
record Skipped(Long id, String name, String reason)
String toListText(Selection selection)                                      // mode|folder|entrypoint|arguments|reboot

폴더명은 조립기와 같은 folderOf(Subprogram)(<id>_<슬러그>)를 쓴다 — 지금 WindowsOemPayloadAssembler 안에 두 번 쓰인 s.getId() + "_" + slug(s.getName()) 를 메서드 하나로 뽑아 선택기와 공유한다(SSOT). UTILITY 는 대상 밖이다.

§8. 설계 결정 (D-1 ~ D-9) / 부산물 / 주의
#채택비채택 + 탈락 사유
D-1대상 OS 의 전달 — WindowsInstallTarget 에 OsTarget(OSName, String osVersion) 을 더하고, 제공자 구현이 osMetadataId 로 OSMetadataRepository 를 조회해 채운다. 메타 부재 · 삭제면 null이미지 이름("Windows Server 2025 SERVERSTANDARD")에서 연도를 파싱 — 이름 규칙에 기대는 추정이고, 정의서가 이미 OS 메타를 가리키고 있다
D-2선택 규칙 — 의존 0 정적 진리표 WindowsDriverSelection.select(...). 후보 = 활성 · 미삭제 DRIVER 중 (보드 = 게스트 보드 또는 공용) AND (osName = 대상 OS 또는 null). 변형 없음 → TREE, 변형 있음 → 정확 일치 → 전 버전 → 제외. 비 ASCII 진입점은 제외실행기 안에서 즉석 필터 — 진리표를 테스트로 고정할 수 없고 카드 미리보기와 서빙이 어긋난다
D-3게스트 전달 — 번들 파일 spv-drivers.lst + autounattend specialize 의 RunSynchronousCommand(curl.exe 로 C:\SPV\ 에 내려받기). 못 받으면 legacy 로 내려간다(a) 게스트별 $OEM$ — R15 토론에서 탈락. (b) autounattend 에 echo 로 목록을 박아 넣기 — 네트워크 무의존이지만 cmd 이스케이프(공백 · 특수문자)와 XML 길이에 취약
D-4SetupComplete 개정 — 목록이 있으면 for /f delims=| 로 행마다 확장자별 실행 · 행마다 [SPV-INSTALL] folder|mode|exit=<code> 로그 · reboot=1 이 있으면 끝에 재부팅 1 회. 없으면 종전 루프게스트가 보드 · OS 를 읽어 스스로 고르기(R15 Q4 (b)) — 판단이 두 곳으로 갈라져 서버 화면과 실제 설치가 어긋난다
D-5실행 결과 보고 — spv-report.ps1 이 [SPV-INSTALL] 줄을 파싱해 installs:[{folder, mode, exitCode}](최대 50)를 완료 보고에 더한다. 요청 필드는 선택(하위 호환)driversAdded 만으로 갈음 — INF 등록 수는 MSI · EXE 의 성패를 말하지 못한다(그래서 driversAdded 는 종전 그대로 두고 축을 하나 더한다)
D-6원장 · 화면 — openServed meta 에 drivers · driversSkipped. 상세 카드는 서빙 전 준비도 미리보기("드라이버 N(변형 M · 트리 K) · 제외 J"), 서빙 뒤 원장 meta. 제외는 접이식 표. 준비도는 막지 않는다드라이버 0 을 BLOCKED 로 — 드라이버 없이도 설치는 성립하므로 막을 근거가 없다(안내로 충분)
D-7$OEM$ 후보 확대 — 대상 = 활성 DRIVER 중 (변형 1 개 이상) OR (트리에 INF). 매니페스트 Entry 에 variants(개수)를 더해 STALE 판정이 변형 변경도 잡는다INF 기준 유지 — MSI 전용 패키지(ASPEED 를 MSI 만 선언한 경우)가 $OEM$ 에 실리지 않아 목록이 가리키는 폴더가 게스트에 없게 된다
D-8하네스 — windows-install-cycle.sh 의 serve 모드가 spv-drivers.lst 도 GET 해 출력하고, complete 모드가 INSTALLS_JSON 환경변수로 installs 를 보낸다수동 curl — CP5 마다 손으로 조립하면 재현이 남지 않는다
D-9실행은 실기 — 렌더된 스크립트의 문법 · 분기는 스냅샷 테스트로 잠그고, 실제 실행(msiexec · 재부팅)은 HF15 CP7 일괄 실기(다음 회차)에서 ASPEED 의 MSI 실행과 재부팅을 본다샌드박스에서의 실행 확인 — SetupComplete · msiexec · shutdown 은 리눅스 샌드박스에서 돌릴 수 없다

Open Questions (CP1 결정 확정 · 2026-09-13)

#질문plan 의 잠정 처리
Q1조립 반영 확인(매니페스트에 폴더 존재)이 변형이 있는 패키지에도 걸리는가 — 브리프 D-2 는 TREE 문장에만 붙여 썼는데 프리셋 ③(ASPEED, 변형 보유)은 걸리는 것을 전제한다결정(CP1) — 전 패키지 공통. 목록이 가리키는 폴더가 게스트 $OEM$ 에 없으면 어느 mode 든 실패하므로 변형 보유 패키지도 매니페스트에 있어야 한다
Q2원장 driversSkipped 에 후보 밖(다른 보드 · 다른 OS)까지 담는가, 아니면 후보 안의 제외(버전 없음 · 비 ASCII · 조립 미반영)만 담는가결정(CP1) — 원장 driversSkipped 는 후보 안의 제외(해당 버전 변형 없음 · 조립 미반영 · 비 ASCII 경로)만 담는다. 다른 보드 · 다른 OS 는 후보가 아니라 기록하지 않는다(카드에도 안 보임)
Q3목록 행의 정렬 순서 — 자원 id 순인가, 이름 순인가, 다른 기준인가 (SubprogramVariant.sortOrder 는 한 패키지 안 변형의 순서라 행 순서를 정하지 않는다)결정(CP1) — 자원 이름 오름차순 · 같으면 id 오름차순(결정적 · 설치 순서 의미 없음). 목록 파일 · 원장 meta · 카드가 같은 순서
Q4mode 의 표현 — InstallEntrypointKind 에 TREE 를 더하는가, 선택 전용 enum 을 따로 두는가결정(CP1) — 선택 전용 enum WindowsDriverSelection.Mode(TREE · INF · MSI · EXE). InstallEntrypointKind 는 진입점 파일의 종류라 TREE(패키지 모드)를 넣지 않는다
Q5대상 OS 가 미상(null) 일 때 후보의 osName 필터를 통과시키는가결정(CP1) — 대상 OS 미상이면 Windows 계열(OSFamily.WINDOWS_BASED · WINDOWS · WINDOWS_SERVER)과 OS 무관(null) 패키지를 통과시키고 변형은 전 버전 변형만 고른다(대상이 Windows 설치인 것은 요청 타입이 보증한다)

잔존 · 위험 (브리프 §7)

  • 토큰 레지스트리가 메모리다 — 설치 도중 앱이 재시작되면 목록 GET 이 404 가 되어 legacy 전체 INF 로 내려간다(설치는 되지만 MSI 는 실행되지 않는다). 원장 · 카드에 "목록 미수신" 이 남지 않으며, 첫 로그온 보고의 installs 가 legacy 표식 1 행으로 알려 준다.
  • curl.exe 가 없는 옛 이미지(2016 이전)는 목록 없이 legacy 다. specialize 패스에서의 네트워크 가용은 실기에서 확인한다(DHCP 는 보통 그 전에 올라온다).
  • 재부팅 요구 변형이 있으면 SetupComplete 끝에 재부팅이 1 회 일어나 완료 보고가 그만큼 늦어진다(시한 60 분 안).

부산물 / 미루는 것

  • 공통화 — folderOf(Subprogram) 추출(현재 WindowsOemPayloadAssembler 안 두 곳). 선택기와 조립기가 같은 폴더명을 내야 하므로 이번에 뽑는다.
  • 미루는 리팩터 — OS 버전 문자열의 Value Object 승격(지금은 versionKeyOf 정규화 하나로 SSOT 유지).
  • DDL 0 · env 0 — 스키마와 환경변수 변경이 없다. R15-1 의 subprogram_variant DDL 은 그 슬라이스 소관이다.
  • CLAUDE.md 수정 없음 — 규약 변경 사항이 없다.
