§1. 현재 상태 (진단)

S8-4 로 게스트 서버 목록의 조건은 Search 버튼이 여는 조회 조건 창(popover="auto") 안에 줄로 선다. 그중 '보드' 줄은 제조사별 optgroup 셀렉트 하나라 한 개만 고를 수 있고, 목록이 길어지면 스크롤로 찾아야 한다.

§2. 요구사항 (확정) + 비목표

요구

  1. 조건 창의 '보드' 줄 = 검색 아이콘 + 입력칸 + 고른 값 칩들 + 전부 해제 ×
  2. 아이콘 클릭 → 검색 팝업(빈 검색). 입력칸에 글자 + Enter → 그 글자로 걸러진 팝업. 일치 1 건이면 팝업 없이 바로 칩 추가
  3. 팝업 = 제목 바 · 자체 검색칸(입력 후 [Enter]) · Search · '사용 중단 포함' 토글 · 표(체크 열 · 이름 · 보조 열) · 하단 [적용] · [닫기]
  4. 이름 클릭 = 하나 바로 추가 · 팝업 닫힘. 체크 여러 개 + [적용] = 한꺼번에 추가. 고른 값은 기존 칩에 누적
  5. 칩 ⊖ = 하나 해제 · 줄 오른쪽 × = 전부 해제
  6. Esc = 검색 팝업만 닫힘 (조회 조건 창은 남음 · 포커스는 줄 입력칸으로)
  7. 같은 선택기로 '소속 그룹' 줄을 화면에 되살린다 (무소속 포함)
  8. 고른 값도 S8-4 규칙을 따른다 — 창 안에서 바꾼 것은 [검색] 으로 적용 · 적용 없이 닫으면 버림 · 걸린 값은 띠 토큰

🎬 미리보기 — 라이브 UX 데모

모의 게스트 서버 목록이다. Search 로 조회 조건 창을 열고, 보드 · 소속 그룹 줄의 🔍 또는 입력칸 Enter 로 검색 팝업을 띄운다. 팝업은 조건 창 위에 겹쳐 뜨고, 닫혀도 조건 창은 남는다. 칩 추가 · 해제는 창 안 변경이라 [검색] 전까지 결과 · 토큰 · URL 이 바뀌지 않는다. 모의 데이터(보드 12 · 그룹 8 + 무소속 · 서버 20)를 실제로 걸러 계산한다. 시나리오 버튼은 클릭 지점을 주황 테두리로 짚으며 재생하고, 끝난 뒤 이어서 직접 조작할 수 있다.

결정 보충

  • D1 — 부모 popover 의 DOM 안에서 열린 auto popover 는 브라우저가 "자식" 으로 쌓는다. 그래서 자식이 열려도 부모(조건 창)가 닫히지 않고, Esc · 바깥 클릭이 자식만 닫는다 — ecount ⑩ 동작이 표준으로 나온다. 위험: 중첩 판정은 "자식의 DOM 조상 또는 여는 버튼이 부모 안" 이어야 성립한다 — CP5 확인 항목(A1 · B1).
  • D2 — 정의서 선택 모달(U3-5-b)과 같은 결이다. 선택지가 늘어도 페이지가 무거워지지 않고, 1 건 판정을 서버 검색과 같은 규칙으로 낸다. 대안은 엔드포인트가 0 이라 가장 단순하고 보드 · 그룹이 수십 개 규모면 충분하다는 장점이 있다.
  • D3 — S8-2 의 단계 · 상태 칩과 같은 규칙이다(보드 A 또는 B · 보드 × 그룹 × 다른 조건).
  • D5 — S8-2 원칙(고르면 늘 빈 결과가 되는 선택지를 두지 않는다)을 유지한다. '사용 중단 포함' 토글은 사용 중단 보드 모델을 숨김 / 표시한다.
  • D6 — 중복 추가를 막고, 해제는 줄의 칩에서 한다.
  • D7 — 되돌리기 = 줄 칩 영역의 처음 마크업을 보관했다가 복원. 검색 팝업이 닫히는 것은 조건 창 변경을 버리지 않는다(팝업만 닫힘).
  • D8 — fragments/ui/lookup-field :: field(name, label, lookupUrl, selected) (줄 = 돋보기 · 입력칸 · 칩 · ×) + fragments/ui/lookup-panel (팝업 껍데기) + static/global/list-lookup.js.
  • D9 — ecount ③ 동작. 0 건에 팝업을 여는 이유는 입력이 잘못됐는지 보이게 하기 위해서다.
