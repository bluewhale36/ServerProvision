간소 트랙 — 사용자 지시에 따라 산출물을 압축한 핫픽스 plan 이다. 명세의 골격 · 디자인 객체 · 섹션 ID 체계는 유지하고, 이 슬라이스에 해당하지 않는 절은 "해당 없음 + 사유" 한 줄로 닫는다.
§1. 현재 상태 (진단) — hover 가 disabled 를 이긴다

S11-1 의 CP5 샌드박스 검증 중 발견했다(스크린샷 C2b). src/main/resources/static/global/style.css 에서 비활성 버튼을 중립 회색으로 정규화하는 .n-btn:disabled 규칙(211행 부근)과 flavor 별 :hover 규칙(296행~)이 명시도가 동률(0,2,0)이다. CSS 는 명시도가 같으면 나중에 선언된 규칙이 이기므로, 뒤에 있는 hover 가 disabled 정규화를 덮는다.

증상 — 비활성 버튼에 마우스를 올리면 활성 색으로 복귀한다. 사용자에게는 누를 수 있는 버튼처럼 보인다. 실제로는 눌리지 않으므로, 화면이 "막혀 있음" 을 알려주려던 시각 신호가 마우스를 올리는 순간 사라지는 셈이다.

왜 이것이 원칙 문제인가 — CLAUDE.md 의 불가침 원칙 "UX 모순은 UI 1차 차단" 은 막힐 행동을 disabled + tooltip 으로 먼저 알리는 것을 전제한다. 이 결함은 그 차단을 없애지는 않지만 차단의 시각 신호를 약화시켜, 원칙이 의도한 안내 효과를 깎는다.
대상현재 상태
flavor hover 규칙 (296행~)가드 없음 — 비활성 버튼에도 hover 색이 적용된다
danger 계열 (376행):hover:not(:disabled) 가드 보유 — 이 슬라이스가 일반화할 선례
링크형 a.n-btn.n-btn-disabled같은 동률 구조라 동일 결함. provisioning 템플릿 2곳에서 실사용 중
레거시 .btn-*템플릿 사용 0건 — 이번에 건드리지 않는다

성격 — 특정 화면의 버그가 아니라 버튼을 쓰는 모든 화면에 걸친 횡단 결함이며, 순수 CSS 문제다. Java 코드 · Thymeleaf 템플릿 · 데이터와 무관하다.

BEFORE — 동률 + 후순위

/* 211행 부근 */
.n-btn:disabled { background:#eee; color:#999; }   /* (0,2,0) */

/* 296행~ */
.n-btn-primary:hover { background:var(--blue); }   /* (0,2,0) — 뒤에 있어 이긴다 */

AFTER — 가드로 대상에서 제외

/* 211행 부근 — 위치 · 명시도 그대로 */
.n-btn:disabled { background:#eee; color:#999; }

/* 296행~ */
.n-btn-primary:hover:not(:disabled):not(.n-btn-disabled) { background:var(--blue); }
§2. 요구사항 (확정) + 비목표
  1. flavor hover 선택자 11 개(primary · secondary · ghost · info · warning · success · outline-success · outline-danger · outline-info · outline-warning + danger 보강)에 :not(:disabled):not(.n-btn-disabled) 가드를 붙인다.
  2. 버튼 요소(:disabled)와 링크형(.n-btn-disabled)을 같은 가드 한 쌍으로 함께 막는다.
  3. 비활성 규칙 주석에 재발 방지 문구를 병기한다 — "새 flavor 의 hover 규칙에 반드시 같은 가드".
  4. 정상 hover 는 그대로 살아 있어야 한다(활성 버튼의 hover 색 변화는 무해).
비 목표 :
  • 레거시 .btn-* 계열 — 템플릿 사용 0건이라 불변.
  • 색 팔레트 · 버튼 디자인 변경 — 하지 않는다. 이번 변경은 적용 대상 축소뿐이다.
  • 비활성 규칙의 위치 이동 · 명시도 인위 상승 — §8 에서 탈락시킨 접근이다.
  • Java · Thymeleaf · 데이터 변경 0.
🎬 미리보기 — 종전 CSS vs 수정 CSS 를 나란히

두 패널의 버튼은 같은 마크업이고 적용된 hover 규칙만 다르다. 왼쪽은 가드 없는 현행, 오른쪽은 가드를 붙인 수정안이다. 버튼에 마우스를 올려보면 차이가 바로 드러난다 — 왼쪽은 비활성인데도 파란색으로 복귀하고, 오른쪽은 회색을 유지한다.

마우스가 없는 환경을 위해 hover 시뮬 토글을 뒀다. 켜면 두 패널의 승자 선언을 JS 가 계산해 그대로 적용하고, 아래 캡션에 어느 규칙이 이겼는지 출력한다.

§8. 대안 비교 · 재발 방지

ⓐ hover 선택자에 가드

채택. flavor hover 11 개에 :not(:disabled):not(.n-btn-disabled) 를 붙인다. 이미 danger 계열이 쓰고 있는 선례의 일반화라 새 관례를 만들지 않고, 변경이 선택자 줄에 국소적이며, 무엇을 의도했는지가 선택자 자체로 읽힌다.

ⓑ 위치 이동 · 명시도 상승

탈락. disabled 규칙을 파일 후미로 옮기거나 명시도를 인위로 올리는 방식. 파일 구조 churn 이 생기고, 새 flavor 의 hover 규칙이 추가되면 다시 진다 — 원인을 고치지 않고 순서에 기대는 해법이다.

ⓒ !important

탈락. 즉효이지만 유지보수 관례를 위반하고, 한 번 쓰면 이후 예외가 누적되는 시작점이 된다.

재발 방지 — 비활성 규칙 주석에 "새 flavor 의 hover 규칙에 반드시 같은 가드" 를 병기한다. 규칙을 추가하는 사람이 원인 지점에서 바로 읽게 두는 것이 목적이다.
