§1. 범위 — 무엇을 만들었나

S19-1 이 세운 게스트 체인은 토큰이 생긴 뒤의 요청만 인증했다. 토큰이 생기기 전의 첫 접촉 — 등록과 토큰 발급을 하는 /boot 와 부팅 자산 /assets/** — 은 열려 있었다. S19-2 는 그 구간에 PXE 부팅 계정의 Basic credential을 요구하고, 게스트 채널 전체에 프로비저닝 LAN 출발지 제한을 건다. credential 은 URL 로 배포되며 진단 이미지는 바꾸지 않는다.

① 첫 접촉의 credential

  • /boot · /assets/** 는 Basic credential(PXE 부팅 계정 pxe.boot.username · pxe.boot.secret)이 있어야 한다
  • 인증 결과는 권한 MachineAuthority.PXE_BOOT("ROLE_PXE_BOOT") 하나
  • 자산을 서빙하는 인스턴스는 secret 없이 기동하지 않는다(fail-fast)

② 출발지 대역 제한

  • pxe.guest.allowed-cidrs 의 CIDR 에 맞는 출발지만 — 게스트 채널 전체
  • 인가 = 대역 ∧ 역할. 대역 밖은 credential 이 맞아도 403
  • 비면 제한 없음 + 기동 WARN. nginx 뒤에서는 X-Forwarded-For 를 출발지로(루프백 프록시만 신뢰)

③ credential 이 든 URL 의 조립

  • PxeBootUrls 가 base-url 에 userinfo 를 넣어 재진입 URL 과 자산 URL 을 만든다
  • 체인로드 스크립트의 커널 · initrd · modloop · apkovl · apk 저장소 · 재진입 chain 여섯 곳이 그 URL 을 쓴다
  • provision_base 만 credential 없이 — 에이전트는 토큰으로 인증한다

변경 전후 — 게스트가 받는 스크립트

BEFORE — 첫 접촉이 열려 있고 URL 에 credential 이 없다

# 인가
/boot · /assets/**  →  permitAll

# 체인로드 스크립트(진단)
kernel http://host:port/api/pxe/v1/assets/vmlinuz-lts …
      modloop=http://host:port/api/pxe/v1/assets/modloop-lts …
      provision_base=http://host:port
chain /api/pxe/v1/boot?systemUUID=…      # 상대 경로

AFTER — Basic credential ∧ 대역, URL 에 credential 이 실린다

# 인가
/boot · /assets/**  →  allOf(ProvisioningLanPolicy, hasAuthority(ROLE_PXE_BOOT))

# 체인로드 스크립트(진단)
kernel http://pxe:***@host:port/api/pxe/v1/assets/vmlinuz-lts …
      modloop=http://pxe:***@host:port/api/pxe/v1/assets/modloop-lts …
      provision_base=http://host:port    # credential 없음(토큰이 credential)
chain http://pxe:***@host:port/api/pxe/v1/boot?systemUUID=…   # 절대 credential URL
예외 하나와 범위 밖 :
  • /api/pxe/v1/assets/agent.sh 는 credential 없이 열되 대역 제한만 건다. 진단 리눅스의 firstboot 가 credential 없는 provision_base 로 이 파일을 받기 때문이다(CP5 F-1). 저장소의 공개 스크립트라 secret 이 없고, 토큰 없이는 아무것도 못 한다. firstboot 가 토큰을 보내도록 이미지를 고치면 이 예외를 닫는다.
  • tftp 의 boot.ipxe 는 앱이 만들지 않는 인프라 파일이다 — chain URL 에 credential 을 넣는 것은 런북(배포)과 랩 스크립트(치환)의 몫이다.
§2. 구조 — 필터 · 부품 · 타입

2-1. 게스트 체인 안에서 요청이 지나는 필터

게스트 체인(@Order(1) · /api/pxe/v1/**)은 이제 인증 필터 둘을 가진다. Spring Security 의 httpBasic 이 꽂는 BasicAuthenticationFilter 가 첫 접촉의 Basic credential 을 세우고, S19-1 의 AuthenticationFilter 가 게스트 토큰을 세운다. 둘은 이 체인 전용 ProviderManager 하나를 공유하며, 인가 필터는 대역과 역할을 함께 본다.

필터credentialprovider세우는 권한실패하면
BasicAuthenticationFilter(httpBasic)Authorization: Basic 헤더PxeBootAuthenticationProviderROLE_PXE_BOOTPxeBootEntryPoint — 401 text + WWW-Authenticate
AuthenticationFilter(S19-1)X-Guest-Token 헤더 · 경로 서빙 토큰GuestTokenAuthenticationProviderROLE_GUESTGuestAuthenticationEntryPoint — 401 JSON
AuthorizationFilter—ProvisioningLanPolicy ∧ AuthorityAuthorizationManager—대역 밖 403 PXE_LAN_FORBIDDEN · 권한 부족 403 GUEST_FORBIDDEN · 익명 401(경로별 entry point)

2-2. 부품 배치 — 트리

텍스트 트리의 순서와 들여쓰기 그대로다. 상자 하나가 부품 하나(이름 · 맡는 일), 테두리 영역이 필터와 ProviderManager 의 경계다. S19-1 의 토큰 부품은 접어 두었고 S19-2 가 더한 것을 편다.

2-3. 값이 어떤 타입을 거치는가 — credential 사슬과 URL 사슬

윗줄은 게스트가 낸 credential 이 권한이 되기까지, 아랫줄은 설정값이 게스트에게 줄 URL 이 되기까지다. 두 사슬은 같은 secret(PxeBootProperties.secret)을 다른 방향으로 쓴다 — 하나는 대조, 하나는 배포.

§3. 데이터 흐름 — 요청 한 건

실선은 호출과 넘기는 값, 점선은 반환과 돌려주는 값, 고리 화살표는 그 주체 안의 처리다. 번호는 시간 순. secret 은 *** 로 적는다.

3-1. 정상 — iPXE 의 첫 접촉: /boot 가 credential 이 든 체인로드 스크립트를 준다

3-2. 정상 — 자산 수신과 에이전트 기동: credential URL · credential 없는 agent.sh · 토큰

3-1 의 스크립트를 받은 뒤 게스트 안의 주체가 바뀐다. iPXE 가 커널 · initramfs 를, Alpine initramfs 가 modloop · apkovl · apk 저장소를, firstboot 가 agent.sh 를, agent.sh 가 에이전트 채널을 부른다 — credential 은 셋이 다르다.

iPXE 와 busybox wget 은 credential 을 먼저 보내지 않는다. 자산마다 401 챌린지 → credential 붙여 재요청 → 200 쌍이 앱 로그에 찍힌다. 로그의 401 을 전부 거절로 읽으면 안 된다. 또 "입고 검수 대기" 의 30초 폴링은 진단 리눅스 안의 /agent/checkin(토큰)이고, iPXE 의 /boot 재진입 루프는 재부팅 뒤에만 돈다 — 두 루프가 같은 30초라 로그에서 구분해 읽는다.

§4. 클래스별 책임 — 맡는 것 · 맡지 않는 것

4-1. 설정과 URL

클래스변경맡는 것맡지 않는 것
PxeBootProperties신규PXE 부팅 계정 값 하나(pxe.boot.username 기본 pxe · pxe.boot.secret). 생성자에서 검증 — unreserved 문자(A-Za-z0-9._~-)만, pxe.assets.root 가 있으면 secret 필수(fail-fast). userinfo()(user:secret) · configured(). toString 은 secret 을 가린다대조(provider) · URL 조립
PxeBootUrls신규게스트에게 줄 절대 URL 의 유일한 조립처 — pxe.server.base-url 에 userinfo 를 넣는다(java.net.URI 로 재조립). reentry(query)(base-url 없으면 종전 상대 경로) · assetsBase() · provisionBase()(credential 없음)스크립트 본문 · credential 검증
MachineAuthority수정PXE_BOOT("ROLE_PXE_BOOT") — 기계 principal 권한 어휘에 첫 접촉 계정을 더한다사람 계정 권한(Role)

4-2. 인증

클래스변경맡는 것맡지 않는 것
PxeBootAuthenticationProvider신규UsernamePasswordAuthenticationToken 만 지원. 사용자명 일치 ∧ MessageDigest.isEqual(상수 시간) secret 일치 → 인증된 토큰(권한 ROLE_PXE_BOOT · credentials 는 비운다). 미설정 인스턴스는 무조건 거절. 빈이 아니다응답 작성 · 대역 판정
GuestSecurityConfig수정공유 ProviderManager(토큰 provider + PXE provider)를 http.authenticationManager 로 · httpBasic(entry point = PxeBootEntryPoint) · 인가 규칙 lanAnd(PXE_BOOT | GUEST) · lanOnly()(agent.sh) · 경로별 entry point(DelegatingAuthenticationEntryPoint.builder())웹 체인
BasicAuthenticationFilter프레임워크httpBasic 이 꽂는다. Authorization: Basic 이 있을 때만 디코드해 관리자에 넘기고, 실패는 자기 entry point 로 401—

4-3. 인가와 거절

클래스변경맡는 것맡지 않는 것

/api/pxe/v1/windows/{UUID}/… · /firmware/{UUID}/…경로 서빙 토큰(S19-1)대역 ∧ ROLE_GUEST헤더는 읽지 않는다

거절 응답 네 가지

  • 401 text — 첫 접촉에 credential 이 없거나 틀리다. text/plain;charset=UTF-8 한 줄 + WWW-Authenticate: Basic realm="provision-pxe". iPXE 콘솔에는 "Permission denied" 가 남는다.
  • 401 JSON GUEST_UNAUTHENTICATED — 에이전트 · 서빙 경로에 토큰이 없거나 틀리다(S19-1). WWW-Authenticate 없음.
  • 403 JSON PXE_LAN_FORBIDDEN — credential 은 세워졌으나 출발지가 대역 밖. 익명이 대역 밖이면 이것이 아니라 401 이다.
  • 403 JSON GUEST_FORBIDDEN — 세워진 권한이 경로가 요구하는 것과 다르다(Basic 으로 에이전트 채널 등).

설정과 배포

  • 환경변수 둘 — PXE_BOOT_SECRET(영문 · 숫자 · . _ ~ - 만 · 자산 인스턴스는 필수) · PXE_GUEST_ALLOWED_CIDRS(쉼표 구분 · 비면 제한 없음 + WARN). 사용자명은 PXE_BOOT_USERNAME(기본 pxe).
  • tftp boot.ipxe 의 chain URL 에 pxe:<secret>@. nginx 설정은 무변경 — SERVER_FORWARD_HEADERS_STRATEGY=native 일 때 앱이 X-Forwarded-For 를 출발지로 쓰되 같은 호스트의 프록시만 신뢰한다.
  • DDL 0 · 진단 이미지 무변경 · 하네스 · 랩은 PXE_BOOT_AUTH=pxe:<secret> 없이는 스스로 멈춘다.

secret 이 보이는 곳과 보이지 않는 곳

  • 보인다 — tftp 파일 · iPXE 콘솔의 URL · 게스트의 /proc/cmdline · /boot 응답 본문. 프로비저닝 LAN 안에서 PXE 부팅하는 기계는 어차피 받는 값이고, 그 경계는 카탈로그 보드 검사와 운영자의 개시 승인이 맡는다.
  • 보이지 않는다 — 앱의 요청 로그. 브라우저 · iPXE · wget · apk 는 userinfo 를 URL 에 싣지 않고 Authorization 헤더로 보내므로 RequestCorrelationFilter 가 남기는 method · path · query 에 secret 이 오지 않는다.
