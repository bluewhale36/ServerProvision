§1. 범위 — 무엇을 만들었나

종전 PXE 네트워크 구성 화면은 ISC dhcpd 조각(/etc/dhcp/serverprovision-pxe.conf)을 렌더해 include 로 잇고 dhcpd -t 로 검사한 뒤 재기동했다. 낼 수 있는 응답이 자체 DHCP 한 모드뿐이라, 자체 DHCP 를 둘 수 없고 사내 DHCP 도 고칠 수 없는 사내망에서는 쓸 수 없었다. R16 은 데몬을 dnsmasq 로 바꾸고, 한 화면 · 한 행에서 자체 DHCP(AUTHORITATIVE)와 proxyDHCP(PROXY) 두 모드를 낸다.

proxyDHCP 는 PXE 규격이 정한 응답 형태다 — IP 는 남이 주고 부팅 위치만 우리가 답한다. 게스트 ROM 은 사내 DHCP 에서 주소를 받고, 부트 서버 질의는 우리 dnsmasq 에 따로 던진다. 화면의 모드 라디오가 주소 배정 필드 묶음을 통째로 켜고 끄며, 그 판정(DhcpMode.requiresAddressing())을 Validator 와 엔티티 invariant 가 같이 본다.

① 두 모드를 한 화면에서

  • DhcpMode 상수 둘이 모드별 필수 필드와 조각의 모드별 줄을 함께 든다 — DnsmasqConfigRenderer 에는 모드 분기가 없다
  • 화면은 <fieldset disabled> 로 주소 배정 묶음을 막고 안내를 낸다(UI 1차 차단)
  • 서버는 PROXY 로 온 주소 배정 값을 검증하지 않고 버린다 — 사내 DHCP 의 몫이다

② 적용 파이프라인

  • 렌더 → temp → 원자 교체 → dnsmasq --test 게이트 → 재기동 → active 검증
  • 어긋나면 이전 조각(없으면 유효한 빈 조각)으로 되돌린다
  • 프로세스 락 안에서 조각 상태와 DB 기록이 함께 갱신된다

③ 관측과 배선

  • 임대 파일 파서 교체 · 조각 드리프트 · 서비스 상태 · 자산 대시보드 chip
  • DDL R16 · 런북 docs/pxe-dnsmasq-setup.md · env PXE_DNSMASQ_FRAGMENT_PATH
  • sudoers 한 줄과 방화벽 4011/udp — proxy 질의가 닿는 포트다

변경 전후 — 데몬과 그 배선

BEFORE — ISC dhcpd · 자체 DHCP 한 모드

데몬         dhcpd (ISC)
조각         /etc/dhcp/serverprovision-pxe.conf
             (메인 conf 에서 include 로 잇는다)
문법 게이트   dhcpd -t -cf <conf>
재기동        sudo systemctl restart dhcpd
모드          자체 DHCP 하나 — 주소 배정과 부팅 응답이 한 덩어리
사내망        쓸 수 없다(자체 DHCP 금지 · 사내 DHCP 수정 불가)

AFTER — dnsmasq · 두 모드

데몬         dnsmasq
조각         /etc/dnsmasq.d/serverprovision-pxe.conf
             (conf-dir drop-in · include 불요)
문법 게이트   dnsmasq --test -C /etc/dnsmasq.conf   (비특권)
재기동        sudo systemctl restart dnsmasq
모드          AUTHORITATIVE · PROXY — 한 화면 · 한 행
사내망        proxyDHCP 로 답한다(IP 는 사내 DHCP · 부팅 위치만 우리가)
바꾸지 않은 것 : PXE 부팅 진입점 /api/pxe/v1/boot · 자산 서빙 · S19-2 의 credential 과 LAN 제한 · tftp 의 ipxe.efi · boot.ipxe(앱이 만들지 않는 런북 관리 파일). R16 은 게스트가 우리 서버를 찾아오는 구간만 바꾼다 — 찾아온 뒤의 인증 · 등록 · 실행은 종전 그대로다.
§2. 구조 — 부품 · 타입 · 패키지

2-1. 부품 배치 — 저장 한 번이 지나는 길과, 화면이 읽어 오는 길

왼쪽 위가 적용 경로다. 화면이 낸 값이 검증 · 변환을 거쳐 DhcpConfigApplyService 에 닿고, 거기서부터는 조각을 만들고 바꾸고 검사하고 재기동하는 다섯 부품이 순서대로 일한다. 그 귀결 하나(ApplyOutcome)가 DB 기록과 HTTP 응답 둘로 갈라진다. 아래쪽은 관측 경로로, 적용과 겹치는 부품(SystemServiceInspector)을 공유하되 상태를 바꾸지 않는다.

2-3. 값이 어떤 타입을 거치는가

윗줄은 화면이 낸 문자열이 검증된 desired 가 되기까지, 가운뎃줄은 그 desired 가 dnsmasq 가 읽는 파일이 되기까지, 아랫줄은 저장된 행이 다시 화면으로 돌아오기까지다. 문자열이 Value Object 로 좁혀지는 지점이 한 곳(PxeNetworkConfigMapper)이고, 그 앞에서 PxeNetworkConfigValidator 가 같은 Value Object 생성자를 미리 시도해 실패를 필드 오류로 옮긴다.

2-4. 조각 — 두 모드의 실제 텍스트

렌더러는 순수 함수이고 같은 입력이면 항상 바이트 단위로 같은 조각을 낸다. 머리말과 공통 다섯 줄은 렌더러가 고정하고, 갈리는 세 구간(주소 배정 · ROM 응답 · iPXE 응답)은 DhcpMode 상수가 든다.

AUTHORITATIVE — 자체 DHCP

# Managed by ServerProvision. Do not edit by hand.
port=0
bind-interfaces
listen-address=192.168.1.15
log-dhcp
dhcp-authoritative
dhcp-range=192.168.1.100,192.168.1.200,255.255.255.0,600s
dhcp-option=option:router,192.168.1.1
dhcp-option=option:dns-server,8.8.8.8
dhcp-match=set:efi,option:client-arch,7
dhcp-match=set:efi,option:client-arch,9
dhcp-userclass=set:ipxe,iPXE
tag-if=set:rom,tag:efi,tag:!ipxe
dhcp-boot=tag:rom,ipxe.efi,,192.168.1.15
dhcp-boot=tag:ipxe,boot.ipxe,,192.168.1.15

PROXY — proxyDHCP

# Managed by ServerProvision. Do not edit by hand.
port=0
bind-interfaces
listen-address=10.1.1.10
log-dhcp
dhcp-no-override
dhcp-range=10.1.1.0,proxy,255.255.255.0
dhcp-match=set:efi,option:client-arch,7
dhcp-match=set:efi,option:client-arch,9
dhcp-userclass=set:ipxe,iPXE
tag-if=set:rom,tag:efi,tag:!ipxe
pxe-prompt="ServerProvision",0
pxe-service=tag:rom,BC_EFI,"ServerProvision PXE",ipxe.efi,10.1.1.10
pxe-service=tag:rom,x86-64_EFI,"ServerProvision PXE",ipxe.efi,10.1.1.10
pxe-service=tag:ipxe,BC_EFI,"ServerProvision iPXE",boot.ipxe,10.1.1.10
pxe-service=tag:ipxe,x86-64_EFI,"ServerProvision iPXE",boot.ipxe,10.1.1.10
줄뜻
port=0dnsmasq 의 DNS 를 끈다 — 우리는 DHCP 만 쓴다(조각에 있어도 전역에 적용된다)
bind-interfaces · listen-address부트 서버 주소가 붙은 NIC 에만 응답한다. 다중 NIC 장비에서 엉뚱한 대역에 답하지 않게 한다
dhcp-match · client-arch 7 · 9UEFI 클라이언트에 efi 태그를 붙인다
dhcp-userclass · tag-ifuser-class iPXE 로 ROM 과 iPXE 를 갈라 각자 다른 파일을 준다 — 같은 파일을 주면 무한 체인이 된다
dhcp-boot vs pxe-service자체 DHCP 는 option 67(filename)로 답하고, proxy 모드의 dnsmasq 는 dhcp-boot 를 무시하므로 두 단 모두 pxe-service 로 답한다
CSA 이름표가 RFC 4578 과 반대다 — dnsmasq 2.85 에서 x86-64_EFI 가 client-arch 7, BC_EFI 가 9 다. 실 AMI UEFI ROM 은 7 을 보내므로 같은 파일을 두 이름으로 선언해 어느 해석이든 맞게 했다. 아키텍처당 서비스가 하나뿐이면 dnsmasq 가 메뉴를 띄우지 않고 곧장 siaddr · file 로 답한다.
§3. 데이터 흐름 — 적용 한 건 · 첫 접촉 한 건

실선은 호출과 넘기는 값, 점선은 반환과 돌려주는 값, 고리 화살표는 그 주체 안의 처리다. 번호는 시간 순.

3-1. 정상 — [저장 및 적용] 한 번이 조각을 바꾸고 dnsmasq 를 재기동한다

기록(persister)이 적용 안에서 불린다. DhcpConfigApplyService 가 프로세스 락을 쥔 채 파이프라인을 돌리고 그 락 안에서 콜백으로 저장까지 커밋하므로, 조각의 실제 상태와 DB 의 applied_result 가 한 임계 구간에서 함께 움직인다. 실패를 HTTP 로 승격하는 throwIfNotApplied 는 락 · 트랜잭션 밖에서 컨트롤러가 부른다 — 안에서 던지면 실패 기록 자체가 롤백돼 사라진다.

3-2. 거절 · 복원 — 어디서 갈라지고 무엇으로 끝나는가

네 귀결 중 APPLIED 가 아닌 셋은 저장은 남기고 끝난다. 그래서 폼에 다시 들어가면 마지막 적용 배지(복원됨(재기동 실패) 등)와 드리프트 경고 — "저장된 구성이 현재 서빙 중인 dnsmasq 조각과 다릅니다 … 다시 저장하면 재적용을 시도합니다" — 가 뜨고, 입력값은 그대로 프리필된다. 사용자는 값을 고쳐 다시 제출하는 것으로 재적용을 시도한다.

3-3. 게스트 첫 접촉 — proxyDHCP 에서 우리 서버를 어떻게 찾아오는가

사내망(proxyDHCP)에서는 주소를 주는 쪽과 부팅 위치를 답하는 쪽이 다르다. 게스트 ROM 이 한 번의 브로드캐스트로 두 답을 받고, 부트 서버 질의는 포트 4011 로 우리에게 따로 온다. 자체 DHCP 모드에서는 ②와 ④가 없고 dnsmasq 가 IP 와 부팅 파일명을 한 번에 준다.

방화벽 두 자리 — dhcp 서비스(67 · 68)만 열면 ⑤가 닿지 않는다. proxyDHCP 의 부트 서버 질의는 4011/udp 로 오므로 이 포트를 함께 열어야 한다. tftp 는 별도 소켓(tftp.socket)이고, ⑨부터는 S19-2 의 Basic credential 과 LAN 제한이 그대로 적용된다.

3-4. 관측 — 화면이 읽어 오는 것

임대 목록(/system/pxe-infra)은 DhcpLeaseReader 가 임대 파일을 읽어 DnsmasqLeaseParser 에 넘긴 결과다. 한 줄이 한 임대이고 <만료 epoch> <MAC> <IP> <hostname> <client-id> 형식이며, 만료 0 은 무만료다. DHCPv6 duid 줄과 손상된 줄은 그 줄만 버린다 — 어떤 입력에도 예외를 던지지 않는다. 활성 여부는 파일이 적어 주는 것이 아니라 만료 시각과 관측 시각의 비교로 판정한다(dnsmasq 가 만료된 줄을 다음 갱신까지 남기기 때문이다). 저장된 구성이 PROXY 면 임대가 존재할 수 없으므로 표 대신 안내를 낸다.

자산 대시보드의 "PXE 인프라 (dnsmasq)" 영역은 슬롯 하나(조각 파일의 존재 · 크기 · 수정 시각 · 전체 구성 문법 판정)와 헤더 chip(서비스 상태 · 모드 · 활성 임대)으로 이뤄진다. 임대 chip 은 자체 DHCP 모드에서만 낸다. 조각 경로가 설정되지 않은 환경에서는 PxeInfraProperties 빈이 통째로 없고, 영역은 명령을 한 번도 spawn 하지 않은 채 "서빙 비활성" 으로 조회된다.

§4. 클래스별 책임 — 맡는 것 · 맡지 않는 것

4-1. 모드와 렌더

모드가 늘어도 분기가 늘지 않게, 갈리는 것을 전부 enum 상수 안으로 넣었다. 렌더러에는 모드 분기가 없고 상수의 메서드를 순서대로 부를 뿐이다.

클래스변경맡는 것맡지 않는 것
DhcpMode신규모드 두 값과 그 표기. requiresAddressing() 이 필수 필드 판정의 SSOT. 조각의 모드별 세 구간(appendAddressing · appendRomBoot · appendIpxeBoot)을 상수가 직접 든다화면 라벨 이상의 UI · 명령 실행 · 파일 IO

4-2. 적용

적용 경로는 예외로 끊지 않고 값(ApplyOutcome)으로 귀결한다. 예외로 바꾸는 일은 상수가 알고(ApplyResult), 부르는 자리는 컨트롤러 한 곳이다.

4-3. 화면과 검증

모드가 필수 필드를 정한다는 사실은 세 곳이 알아야 하는데, 그 판정은 하나다. 화면은 <fieldset disabled> 로 막고(브라우저가 전송에서 제외한다), Validator 는 그 모드에서만 필수를 요구하며, 엔티티는 비정상 경로를 대비한 안전망으로만 던진다.

§5. 계약 — 조각 · 상태 · 예외 · 명령 · 배선

조각

  • 경로 /etc/dnsmasq.d/serverprovision-pxe.conf — Rocky 의 dnsmasq 기본 conf-dir 라 include 를 잇지 않는다.
  • 머리말 # Managed by ServerProvision. Do not edit by hand. 는 가변값 없는 고정 문자열이다.
  • 빈 조각 = 머리말 + # (구성 없음 — 유효한 빈 조각). 복원 경로를 하나로 두기 위해 파일을 지우지 않는다.

배선

  • env — PXE_DNSMASQ_FRAGMENT_PATH(있어야 영역이 활성) · PXE_DNSMASQ_CONF_PATH(기본 /etc/dnsmasq.conf) · PXE_DNSMASQ_LEASES_PATH(기본 /var/lib/dnsmasq/dnsmasq.leases).
  • 파일 권한 — /etc/dnsmasq.d 를 provisioning 그룹 쓰기(2775)로, systemd 드롭인에 ReadWritePaths=/etc/dnsmasq.d.
  • 방화벽 — dhcp 서비스(67 · 68) + 4011/udp. tftp 는 별도 소켓. 종전 dhcpd 는 disable 해 포트 67 을 양보한다.
  • 게스트 채널 대역 PXE_GUEST_ALLOWED_CIDRS 는 env 로 남긴다 — 화면의 서브넷과 별개 값이다(S19-2 의 보안 경계를 화면 입력에 묶지 않는다).
