§1. 완료 요약 — 무엇을 했나

파일 봉인(해시 마커)으로 판정할 수 없는 이질 영역인 dhcpd(DHCP 서버)를, 선행 슬라이스 a 가 만든 통합 시스템 자산 대시보드의 세 번째 영역으로 붙였다. b 는 오직 관측(읽기 전용)이며 신규 예외 0 · DB·엔티티·스키마 무변경이다. dhcpd 의 건강은 해시 드리프트가 아니라 세 개의 독립축으로 판정된다.

  1. 조각 파일 존재 + 구성 문법 — managed.conf 가 있는가 + dhcpd -t 가 통과하는가
  2. systemd 서비스 라이브니스 — systemctl is-active dhcpd 가 active 인가
  3. 임대 현황 — dhcpd.leases 의 활성 임대 건수

a 가 열어 둔 확장점(SystemAssetArea, 도메인이 구현해 끼우는 Service Provider Interface)이 이 이질 판정을 집계 코드에 영역별 분기를 만들지 않고 흡수할 수 있는지가 확장점 계약의 스트레스 테스트였다. 대시보드 집계 서비스는 영역 종류를 묻지 않고 area.context() 를 균일하게 map 할 뿐이다 — 이질 판정이 집계 분기 없이 합류했고, 계약은 통과했다.

완료 상태 — 커밋 d3c4f32 로 CP4(Step 8~9)까지 완료. ./gradlew test BUILD SUCCESSFUL, 1463 tests · 0 failures · 0 errors · 6 skipped(baseline), 신규 pxeinfra 29 테스트, 진단 무결성 회귀망 무변경 green. CP5(샌드박스 하네스 E2E)는 선행 E1-I-2 와 합동 종합 검증으로 유보한다(§11).

§4. 실현된 판정 모델 (SSOT)

도메인 의미값을 전부 Value Object / Enum 으로 타입화했다(Primitive Obsession 금지). 원시 String mac / int exitCode 를 SPI·대시보드로 전파하지 않는다 — 종료양태·서비스 상태·임대 binding 은 각각 enum, IP·MAC 은 기존 VO 로 잠갔다.

① 조각 슬롯 판정 — ConfigFileCondition (implements AssetCondition)

NOT_CONFIGURED ──▶ ABSENT ──▶ SYNTAX_ERROR ──▶ UNKNOWN ──▶ SYNTAX_OK (서빙 비활성) (조각 없음) (구성 문법 오류) (문법 미검사) (구성 유효 · 유일한 healthy)
static ConfigFileCondition of(boolean fragmentPresent, CommandResult syntaxCheck) {
    if (!fragmentPresent) return ABSENT;
    return switch (syntaxCheck.outcome()) {
        case NOT_FOUND, TIMED_OUT -> UNKNOWN;                       // 종료양태 우선
        case COMPLETED -> syntaxCheck.exitedZero() ? SYNTAX_OK : SYNTAX_ERROR;
    };
}
// healthy() == (this == SYNTAX_OK)  → okCount 는 SYNTAX_OK 슬롯만 셈
중요 시맨틱 : dhcpd -t 는 조각이 아니라 dhcpd.conf 전체를 검사한다 — 조각과 무관한 기존 오류도 조각 슬롯을 문법 오류로 만든다. 그래서 라벨을 "조각 문법"이 아니라 "구성 문법 오류"(전체 구성)로 확정했다.

② 서비스 상태 — ServiceState (plain enum, AssetCondition 미구현)

enum ServiceState { ACTIVE, INACTIVE, FAILED, UNKNOWN;
    static ServiceState from(CommandResult r) {            // 종료양태 우선, COMPLETED 에서만 stdout 파싱
        return switch (r.outcome()) {
            case NOT_FOUND, TIMED_OUT -> UNKNOWN;
            case COMPLETED -> switch (r.stdout().strip()) {
                case "active" -> ACTIVE; case "inactive" -> INACTIVE;
                case "failed" -> FAILED; default -> UNKNOWN; };
        };
    }
    ObservationSeverity severity() { ... }  // ACTIVE→OK · INACTIVE→WARN · FAILED→CRITICAL · UNKNOWN→INFO
}

ServiceState 는 슬롯이 아니라 헤더 관측이라 AssetCondition(healthy() = okCount 집계용)을 구현하지 않는다(Interface Segregation Principle — 관측은 healthy 불요). 배지 어휘는 ObservationSeverity 가 단독 소유하고, severity() 는 ACTIVE→OK · INACTIVE→WARN · FAILED→CRITICAL · UNKNOWN→INFO 로 구현했다(failed 가 inactive 보다 위중).

파서는 lease <ip> { … } 블록 단위 try/catch 로 VO invariant throw·손상 블록·미지 binding·빈 파일을 전부 흡수한다(절대 throw 0). IpAddressVO(IPv4 전용)·MacAddressVO 는 재사용, LeaseBindingState·LeaseSnapshot 은 신규 VO 로 타입화(원시 String/int 전파 0). 파일 부재는 DhcpLeaseReader(Files.readString 실패 → 빈 snapshot)가 흡수한다.

잠정 (Rocky 9 실측 전) : 파서 타입·사다리·구조(ISC binding state/hardware ethernet/starts/ends)는 dhcpd 버전 무관하게 안정적이라 확정했다. 손으로 쓴 픽스처는 실 ISC 문법으로 작성한 "잠정" 상태이며, 실 서버 캡처로의 교체는 합동 CP5 전에 한다(§11·Q2). 파서 구조·타입·사다리는 실측과 무관하게 확정이다.

⑤ 특권 명령 경계 — 포트 + enum + 경화된 CommandResult

interface SystemCommandRunner { CommandResult run(AllowedCommand cmd, List<String> callerArgs); }
enum CommandOutcome { COMPLETED, TIMED_OUT, NOT_FOUND }   // 3-상태 종료양태를 상호배타 타입화
record CommandResult(CommandOutcome outcome, int exitCode, String stdout, String stderr) {
    boolean exitedZero() { return outcome == COMPLETED && exitCode == 0; }   // exitCode 는 COMPLETED 에서만 의미
}
enum AllowedCommand {                                     // 지금은 2상수 (restart/restorecon 은 c 착수 시 추가)
    DHCPD_SYNTAX_CHECK("/usr/sbin/dhcpd", ...),  DHCPD_SERVICE_STATUS("/usr/bin/systemctl", ...);
    List<String> assembleArgv(List<String> callerArgs);  Duration timeout();  String sudoersLine();
}
enum ArgShape { NONE, ONE_PATH }                          // 경로 루트 위반만 invariant if-throw

원안(int exit + boolean timedOut)의 두 결함 — ① 명령 부재를 표현할 필드가 없어 종료코드 매직 상수로 오분류, ② timedOut=true 이면서 exit=0 같은 무효 조합 표현 가능(Primitive Obsession) — 을 CommandOutcome enum 하나로 경화했다. exitCode 는 exitedZero()(COMPLETED 에서만)를 강제 경유해 raw exit 가 SPI·대시보드로 유출되지 않는다. 운영 빈 ProcessSystemCommandRunner 는 IsoPreparationService 의 waitFor()-후-read() 데드락을 답습하지 않도록 stdout/stderr 전용 배수(drain) 스레드로 구현했고, 타임아웃 초과 시 destroyForcibly() + CommandResult.timedOut()(예외 아님).

⑥ 영역 확장점 — DhcpdAssetArea implements SystemAssetArea

areaKey()      -> SystemAssetAreaKey.DHCPD
availability() -> PxeInfraProperties 빈 존재 ? CONFIGURED : NOT_CONFIGURED  (@ConditionalOnProperty + ObjectProvider)
inspect(slot)  -> 미구성이면 ConfigFileCondition.NOT_CONFIGURED,  else ConfigFileCondition.of(present, dhcpd -t)
supportsSeal() -> false   // 명시 override (기본 default=true → 안 하면 기본 seal() 의 409 안전망에 걸림)
context()      -> CONFIGURED ? [ {서비스 상태 chip}, {"활성 임대","N건",INFO} ] : List.of()   // 미구성 게이팅

조각 문법 검사·서비스 상태·임대 읽기는 각각 얇은 어댑터(DhcpdConfigInspector / SystemServiceInspector / DhcpLeaseReader)로 분리했다. DhcpLeaseReader 는 대시보드 영역과 임대 목록 컨트롤러가 공용(중복 회수)하며, 미구성·파일 부재·IO 실패를 빈 snapshot 으로 흡수한다.
