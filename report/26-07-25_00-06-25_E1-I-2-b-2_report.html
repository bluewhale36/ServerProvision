§1. 슬라이스 개요 — 무엇을 닫았나

진단 리눅스 자산은 조회(E1-I-1) → 단일 파일 교체(E1-I-2-a) → 범용 버전 저장소(E1-I-2-b-1) 세 슬라이스로 쌓여 왔다. 이번 b-2 는 저장소가 갖고 있으나 화면에 노출되지 않던 능력을 대시보드에 붙여 묶음을 닫는 마지막 슬라이스다. 운영자는 이제 각 슬롯의 과거 버전을 보고, 특정 버전으로 되돌리고, 보존 개수를 조정할 수 있다.

선행 슬라이스b-2 가 소비한 것
E1-I-1 현황·무결성 대시보드슬롯 6종 조회 화면에 버전 이력과 롤백 버튼을 얹는다. loadDashboard() 는 entity-free 그대로 두고 컨트롤러가 이력을 합성
E1-I-2-a 단일 파일 교체업로드 교체의 원자적 스왑·재봉인 로직을 활성화 코어로 흡수해 롤백과 공유
E1-I-2-b-1 범용 버전 저장소list / openVersion / prune 를 화면·활성화 배선으로 연결. 저장소는 도메인 무관이라 코드 변경 없이 재사용
결과 — b-1 이 완성한 저장소의 list/openVersion/prune 가 이제 화면과 활성화 흐름으로 연결됐다. "되돌린 버전을 실제로 활성화(스왑·재봉인)하는 배선"이 없어 비어 있던 자리를 활성화 코어 통합으로 채웠고, 교체와 롤백이 한 코어를 공유한다. 신규 예외는 0 이고, 재사용 예외들이 롤백 경로에서 처음 트리거되는 시나리오까지 통합 테스트로 덮었다.
§2. 요구사항 결과 + 비목표

CP1 plan 이 확정한 요구사항 일곱 항목의 구현 결과다.

요구사항결과구현 요지
슬롯별 버전 목록완료교체 대상 4슬롯(VMLINUZ·INITRAMFS·MODLOOP·AGENT) 각 행에 <details> 로 버전 이력을 접어 표시. 비대상 2슬롯(APKOVL·REPO)은 "빌드 스크립트로 교체" 안내만
버전 행 표시완료아카이브 시각, 크기, 짧은 SHA(앞 12자), 되돌리기 버튼. 최신 순(OrderByIdDesc)
롤백 = 승격(제거)완료현재 활성본을 archive → 고른 버전 활성화 → 그 버전을 이력에서 제거. "이력 = 현재 아닌 되돌릴 수 있는 버전" 불변 유지
롤백 = 교체와 동일 활성화 코어완료원자적 스왑 + 재봉인을 private activate(slot, root, InputStream) 하나로 통일. 소스만 업로드 스트림 ↔ 버전 파일 스트림
보존 개수 설정 화면완료대시보드 상단 인라인 폼(POST /settings, PRG). 단일행 엔티티가 실효값 소스, prune 이 여기서 읽음
서빙 비활성 UI 1차 차단완료서빙 꺼짐 시 교체·롤백 폼을 렌더하지 않음. 서버 requireServingRoot()(409)가 direct POST 안전망
파괴적 확인 없음완료롤백은 현재 활성본을 archive 하므로 가역. native confirm() 대신 버튼 title 경고
비 목표(다음 단계로 미룸) :
  • dhcpd.conf·tftp 등 PXE 인프라 자산 롤백 → E1-I-3. 저장소는 이미 도메인 무관이라 재사용하고, 활성화 코어의 공유는 E1-I-3 이후 리팩토링에서.
  • 시간 기반 TTL 정리 — 이번은 개수 기반 FIFO 만. 시간 만료 정리는 도입하지 않았다.
  • 활성화 로직의 SPI 일반화 — 이번 활성화 코어는 진단 자산 특화. SPI 추출은 dhcpd/tftp 구현자가 실재하는 E1-I-3 이 끝난 뒤 단계 신설 없는 리팩토링(R* 계열)으로(§10 잔존).
  • 게스트 실시간 반영 — 롤백은 자산 파일만 되돌린다. 부팅 중 게스트로의 반영은 다음 부팅 사이클에서.

§4. 설계 결정 (채택 · 비채택 · 탈락 사유)

CP1 plan 에서 확정하고 이번 슬라이스가 구현한 결정 일곱 건이다. 각 결정의 채택안과 탈락 대안을 함께 남긴다.

D1 · 활성화 단일 서비스 통합 (replace · rollback · private activate)
채택 하나의 DiagnosticAssetActivationService 가 replace(slot, MultipartFile)(트리거=업로드) · rollback(slot, Long versionId)(트리거=저장본) · private activate(slot, root, InputStream)(공용 코어)를 모두 보유한다. 기존 DiagnosticAssetReplaceService 는 이 서비스로 흡수·삭제됐고, 교체 스왑 로직이 activate 로 이동했다.
탈락 ⓐ 롤백이 스왑 로직을 복붙 — 중복 금지(불가침) 위반.
탈락 ⓑ replace 와 활성화를 두 서비스로 분리 — "왜 롤백은 activation 인데 replace 는 아닌가"라는 임의적 경계가 생기고, 둘 다 "슬롯에 새 버전을 활성화"하는 트리거(소스만 다름)라는 본질이 흐려진다.

D2 · 롤백 시맨틱 = 선택 버전 승격(제거)
채택 3A openVersion(X) → activate(X 바이트) → remove(key, X). 현재 활성본을 archive 하고 X 를 활성화한 뒤 X 를 이력에서 뺀다. 롤백을 반복하면 직전 활성본이 이력에 들어오고 방금 되살린 버전은 빠져 핑퐁이 정합.
탈락 3B X 를 남기고 순수 교체로 취급 — 현재 바이트와 동일한 이력 항목이 목록에 중복 노출되고 다음 교체가 그것을 또 복제해 누적. 명확한 사용성이라는 프로젝트 핵심 동기에 반한다.

순서 안전성 확인 — activate 가 소스를 temp 로 먼저 실체화하므로, 이어지는 archive → prune 이 하필 롤백 소스(같은 계열의 오래된 버전 파일)를 지우더라도 temp 에 바이트가 이미 있어 안전하다. remove 는 멱등이라 prune 이 먼저 지웠으면 no-op. 이 안전성은 단위 테스트 rollback_restoresVersion 이 실증한다.

D3 · 버전 목록 노출 = 컨트롤러 합성
채택 loadDashboard()(무결성, entity-free)는 그대로 두고, 별도 DiagnosticAssetVersionService.listReplaceableVersions() 가 Map<슬롯 name, List<AssetVersionView>> 를 만들어 컨트롤러가 둘을 합성한다. 뷰는 교체 셀에 <details> 로 목록을 접어 표시. 활성 파일을 재해시하지 않고 asset_version 행만 읽어 208MB 급 자산에도 저렴하다.
탈락 ⓐ loadDashboard 에 이력 결합 — E1-I-1 이 의도적으로 세운 entity-free 대시보드 원칙을 깬다.
탈락 ⓑ 별도 /versions 페이지 / XHR 프래그먼트 — 문맥이 갈리고 SSR 우선 원칙에 반한다.

D4 · 보존 개수 설정 = 경량 DB 백업 인라인 폼
채택 4D 단일행 AssetHistorySettings(retentionCount) — TrashSettings 의 singleton + 시드 + 캐시 패턴을 필드 하나로 축소 미러. @PostConstruct 가 count()==0 이면 property 기본값으로 시드하고, update 시 volatile 캐시를 갱신한다. AssetHistoryProperties.retention-count 는 시드 기본값 출처로만 남고, prune 이 읽는 실효값은 이 설정 서비스로 교체됐다. 화면은 대시보드 상단 인라인 폼(PRG).
대안 4C trash/settings 전체 미러(별도 페이지 = 파일 8~10개) — 단일 필드에 과중.
대안 4B property 유지·화면 없음 — 승인 scope 가 '보존 개수 설정 화면'을 명시하므로 미충족.

D5 · 스왑 소스 추상화
채택 activate(slot, root, InputStream source) 하나로 업로드 교체(file.getInputStream())와 롤백(Files.newInputStream(openVersion(X)))을 통일. 원자적 스왑·재봉인·fail-closed 규율이 두 경로에 한 번만 존재한다.

D6 · 예외 · UI 1차 차단
채택 신규 예외 0(재사용). 서빙 비활성 시 뷰가 교체·롤백 폼 자체를 렌더하지 않고, requireServingRoot 서버 가드(409)가 direct POST 안전망. 롤백은 현재 활성본을 archive 하므로 가역이라 native confirm() 대신 버튼 title 경고.

D7 · remove(key, versionId) 추가
채택 AssetHistoryService 에 멱등 remove 를 추가(없거나 그 키 소속이 아니면 no-op, 이력 파일 + 행 삭제). 롤백 승격에서 되살린 버전을 이력에서 뺀다.

§5. 레이어별 구현 (도메인 모델 SSOT)

Controller — DiagnosticAssetController 수정

롤백·설정 두 엔드포인트를 추가하고, GET 이 버전 목록과 보존값을 함께 담도록 populateDashboard() 로 모델 조립을 공통화했다. 설정 폼이 유효 검증에 실패하면 같은 대시보드 뷰를 재렌더하고 BindingResult 필드 에러를 노출한다. 슬롯 경로변수는 parseSlot 이 enum 으로 해석하며 없는 이름은 404(forging 차단).

Service (트랜잭션 경계 · 핵심 로직)

DiagnosticAssetActivationService 신규

교체·롤백·private activate. archive 실패나 스왑 IO 실패 시 temp 를 정리하고 활성 파일을 건드리지 않는 fail-closed. DiagnosticAssetReplaceService 흡수.

DiagnosticAssetVersionService 신규

읽기 전용. 교체 가능한 슬롯만 list 로 조회해 AssetVersionView 로 미리 계산. 활성 파일 재해시 없음.

AssetHistorySettingsService 신규

singleton 시드/정리 + 캐시. getRetentionCount() 가 prune 실효값, update() 가 캐시 갱신. @Transactional 은 seed·update 에.

AssetHistoryService 수정

remove(key, versionId) 멱등 추가(D7). prune 의 retention 실효값 소스를 property 에서 설정 서비스로 교체(D4).
