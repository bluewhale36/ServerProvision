§1. 진입 전 상태 (진단)

E1-I-3-a 진입 시점에 진단 리눅스 부팅 자산은 조회·무결성 판정(E1-I-1)과 단일 파일 교체·버전 이력·롤백(E1-I-2)까지 갖춰져 운영자가 쓸 수 있었다. 다만 그 화면 전체가 진단 자산 한 종류에만 묶여 있었다 — 현황 대시보드도, 운영 설정도, 전역 무결성 봉인도 모두 /system/diagnostic-asset 아래에 있었고, 자산 종류가 하나 더 생기면 화면을 통째로 다시 만들어야 하는 구조였다.

영역진입 전결손
진단 리눅스 자산조회·무결성·교체·이력·롤백 완비화면이 진단 전용 URL 에 격리
TFTP 부팅 자산(ipxe.efi)파일은 배포되나 운영 화면 없음존재·무결성을 볼 수 있는 대시보드가 없음
집계단일 종류의 6슬롯만여러 자산 종류를 한눈에 볼 통합 뷰 부재
판정 로직DiagnosticAssetIntegrityService 안에 private 으로 묶임다른 종류가 재사용할 수 없는 형태
잠복 결함(진단 중 발견) — 직전 슬라이스 E1-I-2-b(f0ac2f8)가 로컬 스키마 생성을 위해 JPA ddl-auto 를 update 로 바꾼 뒤 validate 로 되돌리지 못한 leftover 가 남아 있었다. 바로 위 주석과 직전 안정화 커밋(2b7f397)에 모순되며, update 는 부팅마다 엔티티에 맞춰 스키마를 리뷰 없이 변형해 엔티티↔스키마 fail-fast 검증을 잃는다. 본 슬라이스 적대적 리뷰에서 잡아 별도 커밋으로 정정했다(§5).
§2. 무엇을 만들었나 (확정) + 비목표

격리돼 있던 진단 리눅스 자산 화면을, 여러 자산 종류를 한 대시보드로 집계하는 통합 화면 /system/asset 으로 승격했다. 그 밑에 자산 종류 하나가 자기 슬롯·판정·봉인을 스스로 제공하는 확장점 SystemAssetArea(Service Provider Interface — 도메인이 구현해 끼우는 확장점)를 열고, 진단 리눅스와 TFTP 두 영역을 그 위에 올렸다.

  1. 통합 대시보드 GET /system/asset — 등록된 모든 자산 영역의 슬롯 현황을 영역별 표 + 전 영역 합계(정상 N / 전체 N)로 집계.
  2. 확장점 SystemAssetArea — 대시보드 서비스는 List<SystemAssetArea> 를 주입받아 라우팅만 하고, 영역이 늘어도 집계·컨트롤러에 조건분기(if/switch)를 늘리지 않는다.
  3. 다형 판정 AssetCondition — 대시보드 집계·배지·쓰기 차단이 슬롯 판정 하나를 단일 진실 출처(SSOT)로 공유. 진단 영역이 쓰는 SealedFileCondition 은 기존 문자열을 byte 동일 승계.
  4. 판정 엔진 SealedFileInspector 추출 — 프로브·검증·봉인 실 로직을 진단·TFTP 두 영역이 공유.
  5. 두 영역 등록 — DiagnosticSystemAssetArea(6슬롯) + TftpAssetArea(ipxe.efi). 봉인 대칭성은 확장점 default 로 다형화.
  6. 운영 설정·전역 봉인·재검증을 통합 화면으로 승격. 자산 하나의 교체·롤백·이력은 진단 상세 URL 에 잔존, 구 대시보드 URL 은 302 이전.
비 목표 (이번 슬라이스 밖 — 어디로 가는지 명시):
  • dhcpd 설정 조각 쓰기(수정·반영) — E1-I-3-c 소관. 3-a 는 읽기·집계·봉인만.
  • dhcpd 등 관측 영역의 실제 등록 — 후속 E1-I-3-b(관측, 완료). 3-a 는 봉인 미지원 경로를 확장점 default 로 열어만 둔다.
  • 진단 자산 활성화 골격의 확장점 추출·어댑터 병합 — 단계 없는 리팩토링(R*)으로 이연.
  • 브라우저/샌드박스 E2E — CP5 는 E1-I-2 와 합동 종합 검증으로 유보(§11).

§4. 설계 실현 (SPI 다형 집계)

① SPI 다영역 집계 — 라우팅만, 분기 없음

SystemAssetDashboardService 는 스프링이 발견한 List<SystemAssetArea> 전량을 주입받아 EnumMap<SystemAssetAreaKey, SystemAssetArea> 로 라우팅 맵을 세운다. 집계(loadOverview)는 이 맵을 순회하며 각 영역의 슬롯을 inspect 할 뿐이라, 영역이 늘어도 이 서비스와 컨트롤러의 코드가 자라지 않는다(조건분기 legacy 확장 금지 — 다형성으로 흡수). 같은 라우팅 키를 두 구현이 주장하면 URL 이 어느 영역으로 갈지 모호해지므로 기동 시 즉시 실패(fail-fast)한다.

② 다형 판정 AssetCondition — 세 소비처가 한 근거를 공유

슬롯 하나의 무결성·현황 판정을 label()·badgeClass()·healthy() 세 메서드로 표현한다. 대시보드 집계(healthy 슬롯 카운트)·배지 렌더링·쓰기 차단이 모두 이 하나를 공유해 문자열을 세 곳에 복붙하지 않는다. 영역마다 판정 축이 다르므로(진단 = 파일 봉인 사다리, 관측 = 서비스 상태) 영역별로 서로 다른 enum 이 이 인터페이스를 구현하고, 대시보드는 구체 enum 을 모른 채 세 메서드만 소비한다.

회귀망 무변경(byte 동일 승계) — 진단 영역이 쓰는 SealedFileCondition(enum)의 label()·badgeClass() 는 기존 IntegrityStatus.getDisplayMessage() 와 IntegrityStatusView.badgeClass() 가 내던 문자열과 정확히 동일하다. 그 결과 E1-I-1/2 의 진단 무결성 테스트 단언을 한 줄도 고치지 않고 green 을 유지했다(값을 바꾸려면 두 원본과 이 enum 을 함께 옮겨야 한다는 불가침 주석을 명시).

판정 사다리 (부재 → 미봉인 → 서명무효 → 변조 → 원본)

MISSING(자산 없음) ─┐ MARKER_MISSING(마커 파일 없음) ─┼─▶ 신뢰 불가(healthy=false) SIGNATURE_INVALID(서명 무효) ─┤ TAMPERED(변조 감지, 해시 불일치) ─┘ ORIGINAL(원본 유지) ───────────▶ 유일한 healthy=true (okCount 가산) NOT_CONFIGURED(서빙 비활성) ────▶ 자산 위치 미상 → 어댑터가 부재 판정으로 흡수

③ 판정 엔진 SealedFileInspector 추출

DiagnosticAssetIntegrityService 안에 private 으로 묶여 있던 프로브(존재·크기·수정시각·해시) + 검증(마커 검증 사다리) + 봉인 로직을 영역 무관 무상태 부품으로 추출했다. 레이아웃별 프로브 규칙도 이 부품이 SSOT 다 — 디렉토리(IN_TREE)는 번들 매니페스트 트리 해시, 단일 파일(SIDECAR)은 SHA-256 을 재계산 근거로 쓴다. 어댑터는 DiagnosticAssetIntegrityService 를 주입하지 않고 인스펙터를 직접 쓴다 — 서비스 주입은 이중 판정과 (서비스↔어댑터) 순환 위험을 만들기 때문이다.

④ 두 영역 등록 + 봉인 대칭성 다형화

DiagnosticSystemAssetArea

  • 진단 리눅스 6슬롯(커널·initramfs·modloop·apkovl·repo·agent)
  • 서빙 여부 = PxeAssetsProperties 가용성
  • 슬롯 교체 가능(replaceable) — 상세 화면 존치

TftpAssetArea

  • ipxe.efi 한 슬롯 — 읽기·봉인 전용(교체 폼 없음)
  • 서빙 여부 = TftpAssetsProperties 가용성
  • 같은 SealedFileInspector 위임(중복 회수)

봉인 대칭성은 supportsSeal()·seal() default 로 다형화했다. 봉인은 정적 파일의 해시를 기준선으로 기록하는 영역에만 의미가 있다 — 파일 봉인 영역은 supportsSeal()=true 로 실제 기록을 오버라이드하고, 봉인 개념이 없는 영역은 이를 false 로 두며 그 경우 default seal() 이 SystemAssetSealNotSupportedException(409)을 던진다(UI 1차 차단의 서버 안전망).

URL 이전 — 링크·즐겨찾기 보존

진단 상세(교체·롤백·이력)는 진단 고유 슬롯 네임스페이스 /system/diagnostic-asset/{slot} 에 그대로 남긴다(회귀 안전망 존치). 구 대시보드 URL /system/diagnostic-asset 는 /system/asset 로 302 리다이렉트해 즐겨찾기·기존 링크를 무해화했다.

§5. 적대적 검토 → 정비 (6건, 커밋 반영)

CP4 이후 적대적 코드 리뷰 6건을 실코드·git 이력으로 검증해 처리했다. 코드가 좋아 보인다고 넘기지 않고, 죽은 경로·거짓 계약·잠복 회귀를 실제로 트리거해 확인했다.

#구분발견 → 처리
1Critical ddl-auto 회귀 정정(별도 커밋 d403cf3) — E1-I-2-b 커밋이 안정화 커밋을 말없이 되돌려 update 로 둔 leftover 를 validate 로 복구. 신규 두 테이블의 수동 DDL 이 ddl/ 에 이미 존재함을 확인해 부팅 안전.
2死코드 死 집계 경로 통합 — 프로덕션 호출자 0 인 loadDashboard() + seal() 중복 루프 제거. 진단 6슬롯 오케스트레이션 커버리지를 프로덕션 경로 테스트 DiagnosticSystemAssetAreaTest(신설)로 이관 — 死경로로만 간접 검증되던 실경로를 직접 커버.
3死코드 미사용 SPI 메서드 제거 — findSlot·markerResourceType·historyCategory(호출자 0, 매직 문자열 중복). 소비처가 생기는 후속 슬라이스(b/c)에서 재도입한다.
4거짓 계약 TFTP 봉인 미지원 오기 정정 — ipxe.efi 는 정적 파일이라 봉인이 의미가 있는데 미지원으로 잘못 표기돼 있었다. 예외 javadoc·테스트를 정합화하고, 봉인 미지원 default 가 실제로 409 를 던지는지 SPI 단 trigger 테스트를 별도로 뒀다.
5고아 死링크·고아 정리 — 상세 화면의 死링크, 고아 템플릿 2종(구 진단 대시보드·설정), 고아 JS 삭제.
6커버리지 프로덕션 경로 직접 테스트 — 위 2·4 의 결과로 DiagnosticSystemAssetAreaTest·SystemAssetAreaDefaultsTest 등 프로덕션 어댑터·확장점 default 를 직접 검증하는 테스트를 추가.
발견 사항(기록) — 1번 ddl-auto leftover 는 직전 슬라이스에서 유입돼 잠복하던 것으로, 정상 흐름에서는 드러나지 않는다. 본 슬라이스에서 실코드·직전 안정화 커밋(2b7f397)과 대조해 발견·정정했다.
§6. Step 8 통합 테스트 시나리오

§9. Verification
"무변경"의 정직한 범위 — "집계 무분기·진단/TFTP production 무변경" 보증은 프로덕션 어댑터·진단 테스트에 한정이다. E1-I-2 단계에서 만든 테스트 DTO 생성처는 통합 응답 형태에 맞춰 가산 갱신됐다. "완전 무변경"이 아니라 "프로덕션 판정 경로·진단 회귀 단언 무변경"으로 읽어야 한다.
