§1. 범위 — 무엇을 만들었나

게스트 채널 /api/pxe/v1/** 을 웹 화면 체인에서 떼어 전용 SecurityFilterChain 으로 받고, 게스트가 제시하는 두 credential 을 Spring Security 의 인증으로 올렸다. 컨트롤러는 토큰 문자열이 아니라 체인이 세운 principal 을 받는다.

① 전용 체인

  • GuestSecurityConfig 가 @Order(1) 로 /api/pxe/v1/** 만 받는다
  • 세션 없음(STATELESS) · CSRF 없음 · 로그인 리다이렉트 없음
  • 거절은 전부 JSON(401 · 403)

② 두 credential → 한 principal

  • 헤더 X-Guest-Token(진단 에이전트 · Windows 완료 보고)
  • 경로 서빙 토큰 /windows/{token}/… · /firmware/{token}/…
  • 둘 다 GuestPrincipal(게스트 서버 id · systemUUID) + 권한 MachineAuthority.GUEST 로 끝난다

③ 컨트롤러 진입 방식

  • @CurrentGuest GuestPrincipal 인자 하나
  • 토큰 대조 코드는 컨트롤러 · 서비스에서 사라지고 필터의 provider 한 곳으로 모였다
  • GuestTokenAuthenticator 삭제 → GuestPrincipalLoader(principal → 엔티티)

변경 전후 — 컨트롤러 · 서비스가 받는 것

BEFORE — 토큰 문자열이 서비스까지 내려간다

// 컨트롤러
checkin(@RequestHeader("X-Guest-Token") String token)

// 서비스
GuestServer server = guestTokenAuthenticator
        .authenticate(token);   // findByGuestToken
                                // 없으면 404 NotFound
                                // 헤더 누락은 400

AFTER — 체인이 세운 principal 만 내려간다

// 컨트롤러
checkin(@CurrentGuest GuestPrincipal guest)

// 서비스
GuestServer server = guestPrincipalLoader
        .require(guest);        // findById + touchSeen
                                // 토큰 대조는 이미 끝났다
// 없거나 틀린 토큰은 여기 오기 전에 401 JSON
이 슬라이스 밖 : /api/pxe/v1/boot 와 부팅 자산 /api/pxe/v1/assets/** 는 토큰이 생기기 전의 첫 접촉이라 이 체인 안에서 permitAll 로 남긴다. 그 구간을 막는 것은 2단계(S19-2 · PXE 부팅 계정 + LAN 제한)의 몫이다.
§2. 구조 — 두 체인과 부품 배치

2-1. 요청이 어느 체인으로 가는가

Spring Security 는 SecurityFilterChain 빈을 @Order 순으로 훑어 매처에 처음 맞는 체인 하나에 요청을 넘긴다. 게스트 체인이 앞이라 /api/pxe/v1/** 은 웹 체인에 닿지 않는다.

순서체인매처세션credential거절
@Order(1)GuestSecurityConfig/api/pxe/v1/**없음 · 컨텍스트는 요청 속성헤더 토큰 · 경로 서빙 토큰401 · 403 JSON
@Order(2)SecurityConfig(S18)나머지 전부HTTP 세션formLogin · httpBasic로그인 302 · 401

2-2. 게스트 체인 안의 부품 배치

체인 하나가 필터 두 개로 일한다. AuthenticationFilter 가 credential 을 principal 로 바꾸고, AuthorizationFilter 가 경로별 권한을 본다. 그 뒤가 컨트롤러다. 각 필터에 꽂힌 부품은 이 슬라이스가 만든 클래스다.

2-3. 값이 어떤 타입을 거치는가

§3. 데이터 흐름 — 요청 한 건

주체 넷 — 게스트(에이전트 · iPXE) · 게스트 체인(Spring Security 필터) · 인증 부품(이 슬라이스가 만든 클래스) · 컨트롤러 · 서비스(execution 영역). 가로가 주체, 세로가 시간이다.

3-1. 정상 — 진단 에이전트가 헤더 토큰으로 체크인한다

3-2. 정상 — iPXE 가 경로 토큰으로 wimboot 를 받는다

레지스트리는 발급 시 guestByToken 역맵을 함께 채우고 회수 시 지운다. 그래서 회수된 토큰은 ③ 에서 풀리지 않아 401 로 끝난다.

3-3. 거절 — 세 갈래가 어디서 끝나는가

상황어디서 끝나는가응답
credential 이 없다(헤더도 경로 토큰도 없음)Converter 가 null → 필터 통과 → AuthorizationFilter 가 익명을 거절 → GuestAuthenticationEntryPoint.commence401 {"message":"게스트 인증이 필요합니다.","code":"GUEST_UNAUTHENTICATED"}

§4. 클래스별 책임 — 맡는 것 · 맡지 않는 것

4-1. 조립

클래스변경맡는 것맡지 않는 것
GuestSecurityConfig신규게스트 체인 조립 — 매처 · STATELESS · AuthenticationFilter(Converter + ProviderManager(Provider)) · 인가 규칙(/boot · /assets/** permitAll · 나머지 GUEST · ERROR/ASYNC permit) · entry point · AccessDeniedHandler. Provider 를 직접 new 한다웹 체인의 규칙
SecurityConfig(S18)수정웹 화면 체인(@Order(2))/api/pxe/v1/** — permitAll 줄을 뺐다. 게스트 체인이 앞에서 받으므로 이 체인에는 오지 않는다

4-2. credential · principal 값

클래스변경맡는 것맡지 않는 것
GuestCredential신규credential 의 종류를 닫힌 타입으로 표현(sealed) — HeaderToken(String) · ServingToken(UUID, kind)유효성 판단
GuestPrincipal신규인증 결과 값 객체 — 게스트 서버 id · systemUUID엔티티 접근
GuestAuthenticationToken신규Authentication 구현 — 전(credential) · 후(principal + MachineAuthority.GUEST) 두 상태를 정적 팩토리 unauthenticated · authenticated 로만 만든다—
MachineAuthority신규기계 principal 권한 문자열의 유일한 정의처 — GUEST("ROLE_GUEST")사람 계정 권한(Role — 가입 화면 · users_role · 포함 관계)

4-3. 인증 부품 (AuthenticationFilter 에 꽂히는 것)

클래스변경맡는 것맡지 않는 것
GuestCredentialConverter신규요청에서 credential 하나를 읽는 규칙 — 서빙 경로면 경로 토큰(헤더 무시), 아니면 헤더, 없으면 nullDB · 레지스트리 조회
GuestPrincipalResolver신규credential → principal. HeaderToken 은 guest_server.guest_token 대조, ServingToken 은 레지스트리 guestOf → findById. 읽기 전용 트랜잭션접촉 기록(touchSeen) · 예외 변환
GuestTokenAuthenticationProvider신규Spring Security 의 AuthenticationProvider 계약 — GuestAuthenticationToken 만 지원, Resolver 의 결과를 인증된 토큰으로, 없으면 BadCredentialsException. 빈이 아니다응답 작성

4-4. 거절 응답

클래스변경맡는 것맡지 않는 것
GuestAuthenticationEntryPoint신규401 JSON. AuthenticationEntryPoint(credential 없음)와 AuthenticationFailureHandler(credential 틀림)를 한 클래스가 겸해 두 경우의 응답이 같다403
GuestAccessDeniedHandler신규403 JSON401
GuestJsonResponses신규상태 · 메시지 · 코드로 ApiErrorResponse 를 JSON 으로 쓰는 한 함수(Jackson 3 ObjectMapper). 메시지 · 코드 상수의 정의처—

4-5. 컨트롤러 진입

클래스변경맡는 것맡지 않는 것
CurrentGuest · CurrentGuestArgumentResolver · GuestWebConfig신규컨트롤러 인자 @CurrentGuest GuestPrincipal 해석 — SecurityContextHolder 의 인증된 GuestAuthenticationToken 에서 principal 을 꺼낸다. 없으면 GuestUnauthenticatedException(401). GuestWebConfig 가 MVC 에 등록인증 자체
GuestUnauthenticatedException신규@ResponseStatus(UNAUTHORIZED). 체인 뒤에서는 일어나지 않고 슬라이스 테스트 · 배선 오류에서만 401—

4-6. execution 영역의 변화

클래스변경맡는 것맡지 않는 것
GuestPrincipalLoader신규principal → GuestServer 엔티티 + touchSeen(now). 호출자의 트랜잭션에 참여. principal 이 DB 에 없으면 데이터 손상으로 보고 IllegalStateException(500)토큰 대조(필터로 이동)
GuestTokenAuthenticator삭제—종전에 헤더 토큰을 findByGuestToken 으로 대조하고 없으면 404 를 내던 클래스. 그 일은 GuestPrincipalResolver + 필터가 맡는다
WindowsInstallTokenRegistry · FirmwareImageTokenRegistry수정기존 발급 · 해석 · 회수 + guestByToken 역맵 + guestOf(token) 역조회—
GuestAgentRestController · WindowsInstallReportRestController수정@RequestHeader 토큰 대신 @CurrentGuest GuestPrincipal 을 받아 서비스에 넘긴다토큰 검사
AgentReportService · WindowsInstallCompletionService수정시그니처 String presentedToken → GuestPrincipal guest. 첫 줄이 guestPrincipalLoader.require(guest)토큰 검사
§5. 계약 — 요청 · 응답 형태
경로credential인가비고
/api/pxe/v1/agent/**헤더 X-Guest-Token: <guest_server.guest_token · 32 hex>ROLE_GUEST진단 에이전트 체크인 · step 열기/닫기 · Windows 완료 보고

/api/pxe/v1/firmware/{UUID}/{file}경로 서빙 토큰 — 헤더는 읽지 않는다ROLE_GUEST펌웨어 이미지
/api/pxe/v1/boot · /api/pxe/v1/assets/**없음permitAll단, 틀린 credential 을 제시하면 401 — 필터의 failureHandler 가 먼저 끝낸다

거절 본문

  • 전부 ApiErrorResponse JSON(message · code) · Content-Type: application/json;charset=UTF-8 · Set-Cookie 없음.
  • 401 GUEST_UNAUTHENTICATED — credential 없음 · credential 틀림 둘 다. 403 GUEST_FORBIDDEN — 인증됐으나 권한 부족.
  • 종전의 위조 토큰 404 · 헤더 누락 400 계약은 401 로 바뀌었다(모의 게스트 하네스도 401 로 갱신).

두 체인 사이의 무관계

  • 웹 로그인 쿠키는 게스트 채널에서 아무 뜻이 없다 → 401.
  • 게스트 토큰 헤더는 웹 체인에서 아무 뜻이 없다 → 로그인 302.
  • 인증 관리자도 공유하지 않는다 — 게스트 provider 는 게스트 필터의 ProviderManager 안에만 있다.
