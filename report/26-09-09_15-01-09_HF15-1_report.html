§0. 한 줄 요약

실기 3호에서 다섯 대가 전부 거친 "프로비저닝 중 재부팅이 PXE 로 오지 않는다"(F-2 · F-2b)와 "재시작하기 전의 폴링을 복귀로 읽어 판독이 실패한다"(F-4), "재시도 뒤 네트워크 부팅을 손으로 건다"(O-10)를 정정했다. 방식은 무장 지점을 하나 더 늘리는 것이 아니다 — 원하는 무장 상태를 진행 상태의 함수 하나 (ProvisioningProgress.isPxeGuaranteeWindow())로 정하고, 게스트 상태가 바뀔 때마다 조정자 (BootOverrideReconciler)가 BMC 의 BootSourceOverride 를 그 값에 맞춘다. 복귀 증거는 컬럼을 나눠 (last_boot_at) /boot 도착만으로 판정한다.

CP5 결과 — 3 항목 중 P1 · P3 은 PASS, P2 는 결과 통지가 화면에 없어 부분 PASS 로 보고됐다(결함 F-1). 세션이 그 자리에서 고쳐 같은 샌드박스에서 재검증해 3 / 3 PASS 로 닫았다. 전체 테스트 3,120 green.

§2. 구현

무장을 부르는 방식이 바뀌었다

BEFORE — 사이트별 명시 호출

PowerOnStep      → arm(PXE_ONCE)
BeginSettingStep → arm(PXE_ONCE)
agent reboot     → 무장 없음   ← F-2b

경로를 아는 사람이 그 자리에 적어야 성립한다.

AFTER — 상태의 함수 하나

desired = isPxeGuaranteeWindow()
        ? PXE_CONTINUOUS : RELEASE
모든 변화 → 조정자가 그 값에 맞춘다

경로가 늘어도 무장 코드를 적을 자리가 없다.

창 밖 ──개시──▶ 창 안 (PXE_CONTINUOUS) ──서빙 · 실패 · 종단 · 회수──▶ 창 밖 (RELEASE) ▲ │ └────────────────── 재시도 ───────────────────────────┘

개시부터 OS 설치 착수(wimboot 서빙) 직전까지가 창 안이다. 실패는 창 밖이고 재시도가 창을 다시 연다. 설치한 OS 가 다시 PXE 로 돌아가면 안 되므로 서빙 시점에 창이 닫히고, 그래서 Windows 설치 중 재PXE 정책은 손대지 않았다.

§3. 강제 장치 (설계가 사고를 막는 방식)

고친 것은 네 건의 증상이지만, 같은 종류가 다시 나지 않게 하는 장치는 여섯 가지다.

장치무엇을 막는가
판정 SSOT 하나 — isPxeGuaranteeWindow() 무장을 부를 자리가 코드에 없으므로 새 경로에서 빠뜨릴 수가 없다. F-2b 는 빠뜨림 그 자체였다
Primitive Obsession 회피 — NextBoot enum 무장 의도를 boolean pxe 나 String "Continuous" 로 나르지 않는다. wire 값 · 판정 · 표기가 상수에 함께 붙어 로그와 화면 문구가 갈라지지 않는다
두 의미를 두 컬럼으로 — last_boot_at / last_seen_at F-4 는 "부팅" 과 "접촉" 을 한 값에 담아서 난 결함이다. 판독은 lastBootAt > rebootAt 만 본다
armed 캐시 — 뒤집힐 때만 BMC 호출 정상 진행에서 변화마다 BMC 를 두드리는 것. 세우기 실패는 기억하지 않아 재시도하고(보장 우선), 애초 상태를 모르는 게스트의 해제 실패는 한 번으로 접는다
예외를 삼키지도 전파하지도 않는다 워커에서 WARN 으로 남고 다음 변화에서 다시 조정된다. 요청 스레드가 BMC 를 기다리지 않으므로 화면이 멈추지 않는다
UI 1차 차단 — BMC 검출 서버에만 새 버튼 노출 BMC 없는 서버에서 누를 수 있는 버튼이 실패로 끝나는 것

레이어 경계도 유지했다 — 컨트롤러는 경로 변수만 받아 서비스를 호출하고, 조정자는 읽기 전용 TransactionTemplate 안에서 엔티티를 읽고 밖에서 BMC 를 부른다.

§6. 미수행 항목과 사유

계획한 세 항목은 모두 수행했다. 다만 계획이 덮지 못한 축이 하나 있어 여기 적는다 — 빠진 것을 감추지 않는 것이 이 절의 목적이다.

무장의 성공 경로(BMC 가 Boot{Continuous · Pxe · UEFI} PATCH 를 받아들여 다음 부팅이 실제로 PXE 로 오는 것)는 샌드박스에 도달 가능한 BMC 가 없어 확인하지 못했다. 실측한 것은 실패 경로뿐이다(연결 실패 → 다음 변화에서 재시도). 성공 경로는 BootOverrideReconcilerTest 의 여섯 칸으로 고정하고 실제 BMC 반영은 실기 4호로 넘긴다(§9).

설계상의 한계 — BMC 가 검출되지 않은 서버는 PXE 보장 대상이 아니다. 조정자가 부를 대상이 없으므로 그 환경에서는 F-2 · F-2b 가 여전히 재현될 수 있다. 결함이 아니라 이 정정의 경계다 — 게스트에 BMC 자격증명을 주는 대안은 plan 에서 탈락시켰다.
§7. 발견한 것과 정정

F-1 (CP5 발견) — 결과 flash 가 화면에 도달하지 않는다

증상: [재시도 후 네트워크 부팅] 을 누르면 되감기는 되지만 전원 제어 결과가 성공이든 실패든 화면에 전혀 표시되지 않는다. 도달 불가 BMC 에서는 6초 기다린 뒤 화면이 그대로 다시 그려지므로, 운영자는 네트워크 부팅이 걸렸는지를 알 수 없다.

원인: 컨트롤러는 addFlashAttribute("flashMessage", "재시도 접수 · " + power.message()) 로 flash 를 담는데, server-detail.html 에 그 값을 그리는 자리가 없었다. 저장소에서 렌더하던 템플릿은 그룹 상세와 시스템 화면들뿐이고 공용 레이아웃도 그리지 않는다. 같은 메서드의 Javadoc 은 "전원 결과는 flash 로 알린다(실패도 결과)" 라고 적혀 있어 의도와 구현이 어긋난 상태였다.

정정: 그룹 상세와 같은 조각을 server-detail.html 상단에 두어 flashMessage 를 n-alert n-alert-success 로 그리게 했다.

배포 전 필수 — 실 DB 에 ddl/HF15-1_guest_last_boot_at.sql 을 먼저 적용해야 한다. 애플리케이션이 ddl-auto=validate 로 뜨므로 컬럼이 없으면 기동 자체가 실패한다. 기존 행은 NULL 이고 다음 부팅에서 채워진다.

실기 4호 (CP7 · E 계열 일괄 승인에 합류)

회귀 위험

  • 무장이 Once 에서 Continuous 로 바뀌었다 — 종단에서 해제가 걸리지 않으면 서버가 계속 PXE 로 돈다. 위 해제 항목이 실기의 핵심 확인점이다. 해제가 끝내 실패해도 /boot 의 exit 폴스루로 로컬 부팅은 되어 서비스가 멈추지는 않는다.
  • 설정 판독 — 기존 행의 last_boot_at 이 NULL 이므로, DDL 적용 직후 진행 중이던 게스트가 설정 판독 단계에 있으면 다음 /boot 까지 대기한다(타임아웃 정책이 받는다).
